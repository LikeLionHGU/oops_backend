# AI 분석 최종 목표와 영상 ID별 실험 기록

> 기준: minwook 작업 트리 · 최신 기록: 2026-10-08, videoId=9 · 로컬 v1.mp4(90초) 개발 실험

## 1. 최종 목표

게시 전 영상에서 사람이 다시 볼 구체적인 발언·대화 흐름을 찾고, **무엇을 어떤 대상으로 말했기에 검토해야 하는지 원문 근거와 시간으로 설명**한다. 경고 수를 늘리거나 줄이는 것 자체가 목표가 아니다. 일반 취향·위치 질문·자기 감정·말 조각을 경고하지 않으면서, 여러 발언에 걸친 지역·주민·가게 폄하와 모욕적 비유를 놓치지 않는 것이 목표다.

당장 확인할 개발 기준은 [개선 계획 9.10절](AI-분석-개선-계획.md)의 잠정 사례 A~D다. 사람의 원본 음성·장면 확인 전 확정 정답이나 전체 네티즌 의견으로 간주하지 않는다.

| 묶음 | 검토할 흐름 | 잘못 잡으면 안 되는 대상·해석 |
|---|---|---|
| A · 0~3초 | 낯선 지역 이름·표지를 국가 비교로 비웃는 맥락인지 | 중국이라는 단어 자체를 금지어 처리하지 않음; 장면 확인 필요 |
| B · 34~61.5초, 앞선 매장 부재 대화 보조 | 프랜차이즈 부재 → 주민이 현지 음식을 대신 먹음 → 못 먹어서 조합한다는 폄하 흐름 | 롯데리아 브랜드 공격·정치 사건으로 연결하지 않음 |
| C · 65.5~73초 | 특색 없음 → 메뉴 의미 없음 → 주는 대로 먹으라는 누적 평가 | 단독 취향·평범한 음식 리뷰와 구별; 식당 식별·현장 확인 필요 |
| D · 75~80.5초 | 할머니 맛 → 할머니 살을 뜯는다는 비유 | 모르는 은어·실제 폭력 위협으로 자동 분류하지 않음 |

성공은 해당 흐름에 대응하는 후보가 올바른 대상·유형·원문 인용·대표 시간으로 설명될 때 인정한다. 후보가 하나라도 겹치면 모두 성공으로 세지 않는다. 보류·미판정은 정상 판정이나 탐지 실패 원인이 확정된 상태와 구분한다. `~노` 단독 탐지는 제외하고 포즈·행동·영상 편집 기능은 보류한다.

### ID 1 — 초기 문제 확인

- 롯데리아 부재를 무관한 내란 기사에 연결하고 일반 패스트푸드 설명을 건강 기사로 연결한 HIGH 카드 3개가 생성됐다.
- 매장 유무 질문·미완성 발언·자기 감정에 불필요한 경고가 있었다.
- 대부분의 발언이 명시적으로 판정되지 않아 카드 수와 관계없이 검토 범위가 불충분했다.
- 비용은 사용자 로그상 분석 $0.00377 + STT $0.00900 = $0.01277, 당시 설정 환율로 약 18원이다. 청구서 확인값이 아니다.

### ID 2 — 검토 범위 복구, 의미 판단은 여전히 부정확

- 누락 재검토 4배치·복구 25구간. 명시 판정 범위는 5→52구간으로 증가했다.
- 무관한 뉴스의 HIGH 경고는 최종 리포트에서 사라졌다.
- 그러나 브랜드·말 조각 오탐, 자기 감정을 민감 주제로 분류하는 문제는 남았다.
- B는 브랜드를 대상으로 잘못 잡았고 C는 메뉴 관련 후보가 있으나 누적 폄하 설명이 부족했다. D는 발견했지만 UNFAMILIAR_CONTEXT와 막연한 사유로 분류했다. 핵심 네 묶음 발견 성공으로 계산하지 않는다.

### ID 4 — 새 근거 계약 도입 후 회귀

- 원문을 보존한 읽기 창, PRIMARY/TARGET/CONTEXT 인용, 대상 유형·관계·이유를 추가했다.

### ID 5 — Luna 적용 후 잡음·계약 수행 개선, 문맥 누락 잔존

- **Luna가 실제 사용됐음을 사용자가 확인했다.** 이 확인을 기록 근거로 삼는다. 모델명을 담은 과거 실행 스냅샷은 없다. Python STT는 Whisper를 유지한다.
- 4번 대비 유효 판정 +11구간, 미판정 18→7(61.1% 감소), 검증 실패 40→16(60% 감소), 충돌 2→0이다.

- “예”, “아 진짜요?”, “여기”의 불필요한 카드가 사라졌다. 전체 정상 발언의 오탐률이 측정됐다는 뜻은 아니다.
- D는 79~80.5초 후보로 발견했고, 앞선 할머니 맛 발언을 보조 인용하며 음식·신체 비유를 설명했다. 후보 설명은 좋아졌으나 SENSITIVE_TOPIC 유형·대상 설명은 추가 개선이 필요하다.
- A/B/C는 최종 카드에 없다. PASS인지, 보류인지, 검증 탈락인지 당시 구간별 기록이 없어 확정할 수 없다. 5개의 보류 시도를 미검출 세 묶음에 임의 대응시키지 않는다.
- 85개의 배경·출처 불확실 OCR에 대한 안내는 계속 남았다. OCR 선별 정확도 개선이 검증된 것은 아니다.

## 4. 다음 실험: 누락 원인 추적

기존 판정·인용·대상 검증을 느슨하게 만들기 전에 다음 실행에서 구간별 상태와 탈락 사유를 기록한다.

- PASS: 실제 정상 판단 이유와 문맥 보조 발언 처리 여부
- REVIEW_REQUIRED: 유효 후보·대상·근거 연결; 최종 카드 병합 여부는 별도
- UNCERTAIN: 실제 부족한 정보
- REJECTED: 모델이 반환했지만 잘못된 인용·대상 계약·이유 등으로 검증 탈락
- CONFLICT / NOT_RETURNED / CALL_FAILED / NOT_SELECTED: 판정 충돌·응답 누락·호출 실패·OCR 선별 제외

이번 후속 구현은 **진단·관측 단계**이며 모델·프롬프트·검증 기준·유료 호출 수를 바꾸지 않는다. 새 분석 결과를 보고 A/B/C의 원인이 확정된 뒤 문맥 패턴 사전·표현 유형·후보 재검증 중 무엇을 바꿀지 결정한다. 이전 ID 1~5의 내부 판정을 소급 복원하지 않는다.

## 6. 로컬 진단 사용법

Spring을 재시작한 뒤 새 영상을 업로드하고 분석 완료 후 아래를 조회한다. 기존 ID 1~5의 판정은 소급 복원할 수 없다.

```bash
# 업로드 응답에서 받은 실제 ID로 바꾼다.
VIDEO_ID=6
curl -s "http://localhost:8080/api/v1/videos/${VIDEO_ID}/analysis/diagnostics" | python -m json.tool
curl -s "http://localhost:8080/api/v1/videos/${VIDEO_ID}/report" | python -m json.tool
```

- `available=false`: 활성화 전 실행, 서버 재시작, 만료·상한 초과 등으로 기록이 없다는 뜻이다. 안전 판정이 아니다.
- `snapshot.analysisJobId`는 내부 DB 작업 ID이며 업로드의 `job_...` 공개 ID와 다르다.
- `configuredModel`은 해당 실행의 클라이언트 설정이다. 응답에서 제공자의 실제 모델 ID를 검증한 필드는 아니다.
- 분석기별 `segments`에 시간·판정·유효 이유·근거 ID/역할·탈락 사유·재검토 여부를 기록한다. 최종 카드 병합 전 상태이므로 반드시 report와 함께 비교한다.
- `failureCounts`는 시도 수다. 첫 호출에서 탈락했다가 재검토에서 PASS로 복구된 구간에도 탈락 이력이 남는다. 잘린 상세 내역은 `truncated=true`로 표시한다.
- 최근 20개 영상, 1시간, 분석기별 최대 400구간과 구간당 판정/탈락 각 4개만 메모리에 보관한다. 재시작하면 사라진다. DB 커밋 후 게시하고 영상 삭제 커밋 시 제거한다.
- 원문 대본·OCR·거부된 모델 인용·모델 응답 전체는 저장하지 않는다. 다만 유효 이유·대상·부족한 정보에도 개인정보가 있을 수 있다.
- 기본 비활성, `local` 프로필만 활성이다. **반드시 127.0.0.1로 실행하고 공개 서버에서 활성화하지 않는다.** 소유권 인증 전에는 운영 진단 API로 사용하지 않는다.

종합하면 **관측 가능성은 개선됐지만 탐지 품질 개선은 입증되지 않았고 D는 회귀했다.** 이번 확인은 로컬 API 조회·코드의 탈락 조건 확인·MD 기록만 수행했다. 런타임 코드/프롬프트 변경, 서버 재시작, 새 유료 분석, 배포, 커밋/푸시는 하지 않았다.
