사용자 파일을 이번 작업에서 직접 삭제하지 않았다. 테스트는 메모리 DB와 별도 임시/테스트 저장소 또는 mock을 사용한다. 삭제 코드의 실행 시점만 개선했다. 삭제 후 파일 정리가 실패하면 로그를 남기지만 DB 행 복구/파일 복원/고아 파일 재정리까지 자동 제공하는 것은 아니다. 별도 후속 운영 과제다.

## 예약 원장

`tools/reservation_ledger.py`는 SQLite `BEGIN IMMEDIATE`로 여러 프로세스의 예약을 직렬화한다. 원장은 private `datasets/controversy/evaluation/reservations.sqlite3`에 600 권한으로 저장하며 Git에 넣지 않는다. 같은 artifact는 출력 폴더가 달라도 다시 소비할 수 없다. 모의 실행은 원장과 키를 사용하지 않는다.

`tools/seed_reservation_ledger.py`로 116/117/118/120의 고정된 frozen/원응답 보고서 hash와 승인/예약 연결을 확인해 기존 예약 4건을 가져왔다. **이번에 새 예산을 승인하거나 예약한 것이 아니다.** 같은 $1.00 승인에서 소비된 예약 $0.5824575·잔여 **$0.4175425**를 그대로 보존했다. 재초기화해도 같은 과거 항목을 확인할 뿐 새 잔액으로 덮어쓰지 않는다.

공유 실행기의 CLI는 원장 확인·예약 소비 뒤 키를 읽는다. 호출/키 로딩/파일 생성 이후 오류가 나거나 프로세스가 죽어도 예약은 남고 자동 반환되지 않는다. 실제 청구액을 보장하는 결제 차단이 아니라 **승인된 추정 예약의 중복·누적 초과를 막는 로컬 안전장치**다. 실제 provider 요청/원응답/모델·프롬프트·선택 근거는 변경하지 않는다.

아직 공통 원장은 `run_issue_scoped_comparison.py`를 사용하는 실행 경로에 연결한 상태다. 별도 transport를 직접 호출하는 과거 독립 실행기는 이 원장을 자동 사용하지 않는다. 해당 실행기를 다시 유료로 사용할 때는 먼저 동일 원장으로 이관해야 한다. 새 승인은 별도 승인 식별자/검증된 원장 초기화가 필요하며 모르는 승인이나 잔액은 실행을 차단한다.

과거 frozen의 ‘실행 가능’/잔여 값은 당시 계획으로 보존한다. **현재 실제 재실행 권한이나 최신 잔액으로 읽지 않는다.** 새 실제 실행은 원장의 판정을 통과해야 하며 `reservation.json`에 당시 원장 잔액을 함께 보관한다. 실제 120 artifact의 재소비 거절을 키/모델 호출 없이 확인했다.

## 영상 처리 변화와 제한

OCR은 타임라인 0초부터 간격별 첫 원본 프레임을 선택하고 실제 시간을 기록한다. 이전 `fps=1/4`는 예제에서 원본 1.96/5.96초 장면을 결과 0/4초로 바꿨다. 새 구현은 원본 프레임 자체와 시간을 함께 보존한다. 가변 프레임률에서 실제 4.12초라면 4초로 만들지 않는다. 시간 메타데이터를 확인할 수 없으면 실패로 남긴다.

이 변경은 **새 OCR 샘플과 시간 정보에 영향을 준다.** 기존 DB 리포트/대본/프레임은 덮어쓰지 않는다. 실제 영상의 OCR 커버리지·발언 연결 변화는 재시작 후 별도 검증해야 한다. 단위/합성 영상 테스트만으로 논란 탐지 성능이나 B 개선을 주장하지 않는다.

변환 제한은 명령별 타임아웃이다. STT/OCR 전체 요청의 합산 시간 제한, PaddleOCR 추론 시간 제한, 유튜브 다운로드 전체 제한을 모두 구현한 것은 아니다. `MEDIA_TIMEOUT_SEC`은 양수·최대 600초이며 기본 300초다. 오류로 끝난 임시 산출물은 기존 소유 폴더 정리 경로를 사용하고 원본/외부 저장 프레임을 임의 삭제하지 않는다.

## 반영 완료: 분석 트랜잭션 분리

실행 경로는 **짧은 영상 조회 → DB 연결 없는 STT/OCR·AI 계산 → 원문/결과/완료 상태의 원자적 저장**으로 바뀌었다. `runAsync`는 `NOT_SUPPORTED`로 외부 계산 중 트랜잭션을 열지 않는다. 조회 후 분리된 Video 엔티티의 기본 필드를 사용하며 STT가 확인한 제목/길이는 이 메모리 객체에만 반영한다. 완전 불변 DTO로 전환한 것은 아니다.

- `TranscriptService.extract`와 `ScreenTextService.extract`는 미저장 원문/프레임 참조를 반환한다. 구형 `extractAndSave`는 호출부·테스트와 함께 제거했다. 분석 도중 이전 DB 결과를 삭제하지 않는다.
- `AnalysisResultWriter.save`만 저장 트랜잭션을 연다. Video → 최신 Job 순으로 잠그고 작업 ID·PROCESSING을 확인한다. 취소/새 재시도로 대체된 결과는 삭제 작업 전 거절한다.
- 이전 검수 액션/참고/후보 → 표현/원문/화면 글자 → 프레임 순으로 FK 의존성을 정리한다. 새 원문·프레임·화면 글자·표현·커버리지·후보·리포트·메타데이터·COMPLETED를 함께 저장한다. 저장/flush/커밋 예외는 호출부로 전달되어 별도 짧은 실패 처리로 이어진다. 취소 상태는 실패로 덮어쓰지 않는다.
- 완료 알림과 진단은 커밋 후에만 발행한다. 취소도 Video → 최신 Job 잠금 순서를 쓰며 영상/작업 상태를 같은 트랜잭션으로 확정한다. 이전 `syncCancelledVideo` 커밋 후 중첩 트랜잭션은 제거했다.
- 새 OCR 파일은 `frames/<videoId>/jobs/<jobId>`로 격리한다. 실패/취소된 추출이 이전 결과의 이미지를 덮어쓰거나 삭제하지 않는다.

### 근거 ID 계약

미저장 입력에는 기존 `ReviewInput`의 `stt-index-N` / `ocr-index-N` 계약을 사용한다. 같은 미저장 객체를 판단·프레임 연결·최종 저장까지 유지하고, DB ID가 생긴 뒤 ReviewInput을 재구축하지 않는다. 선택 표현의 `segmentId`도 동일한 index ID로 저장한다. index는 해당 분석 입력에서만 유효하며 영상 간 전역 ID나 DB PK가 아니다. 검증된 근거의 원문·시간도 함께 보존한다. 과거 DB 기반 근거 ID와 리포트는 재작성하지 않는다.

### 검증과 남은 경계

메모리 DB·mock 외부 분석으로 다음을 검사했다: DB 연결 1개에서 두 분석의 외부 대기/상태 조회, 외부 추출 중 활성 트랜잭션·점유 연결 0, 저장 오류 후 FAILED와 이전 원문 보존, 실제 DB 길이 제약 실패 시 원문/리포트/완료/알림 롤백, 취소 뒤 새 작업 보존, 오래된 snapshot 거절, OCR 프레임 FK·검증 근거·표현 ID 저장. 기존 정리/재시도·삭제 회귀도 전체 테스트에 포함한다.

외부 호출을 강제 중단하는 취소는 아니다. 진행 중 호출은 돌아온 뒤 다음 경계에서 멈춘다. 저장 단계의 길이는 결과 크기·DB 부하에 따라 달라지며 일정 밀리초를 보장하지 않는다. `startAnalysis`의 worker health 확인 등 모든 API 외부 호출까지 DB 밖으로 이동한 것은 아니다. 운영 DB/부하 시험은 수행하지 않았다.

## 미참조 작업 프레임 수거기 — 기본 꺼짐

`oops.storage.orphan-frame-retention-hours: 0`으로 비활성화했다. 양수로 켜면 최소 24시간을 적용하며 매시 30분에 실행한다. 이번 작업에서 설정을 켜거나 실제 업로드 파일을 정리하지 않았다.

새 `frames/<videoId>/jobs/<jobId>` 폴더에서 다음 조건을 모두 확인해야 삭제한다.

- 정상 OCR 응답 뒤의 `.ocr-complete` 표시와 파이프라인 `finally` 뒤의 `.analysis-released` 표시가 있다. 해제 표시와 작업 종료 시간이 모두 보관 기간보다 오래됐다. 취소 상태만으로 파일 사용 종료를 가정하지 않는다.
- 해당 Job/Video가 DB에 있고 소유 관계가 일치하며 작업이 종료됐다. 영상 잠금 안에서 PENDING/PROCESSING 작업이 하나도 없는지 다시 확인한다. 정리 중 재시도·결과 저장은 같은 잠금을 기다린다.
- DB VideoFrame이 해당 작업 폴더를 참조하지 않는다. 실패/취소 후 이전 결과를 보존하는 경우에도 이미지 참조가 있으면 남긴다.
- 저장 루트·경로·하위 항목에 심볼릭 링크가 없고, 삭제 직전 해제 표시가 여전히 만료된 상태다.

원본 영상·현재 리포트 이미지·이전 평면 프레임 폴더는 대상이 아니다. 표시 없는 과거 폴더, 프로세스 강제 종료, OCR 타임아웃으로 worker 종료가 불확실한 폴더도 남긴다. 모든 고아 파일을 해결하는 기능은 아니다. 저장소는 신뢰할 수 있는 서버 프로세스만 수정하는 권한을 전제로 하며, 악의적인 로컬 프로세스의 동시 파일 교체를 차단하는 sandbox는 아니다.

회차당 최대 1,000개 만료 후보를 DB 검사하고, 보호된 폴더도 지나가도록 다음 페이지로 이동한다. 끝에서 처음으로 돌아오므로 삭제로 후보 위치가 바뀌면 다음 순환에서 다시 확인한다. 파일 트리 탐색 전체의 시간 상한은 별도로 두지 않았다. 일반 파일보다 표시를 나중에 정리하여 삭제 실패는 다음 회차에 재시도할 수 있다. 삭제된 파일은 DB 롤백으로 복원되지 않으며 백업 없이는 복구할 수 없다.

임시 폴더에서 만료/미만료/표시 없음/기존 파일 보존/링크/잘못된 ID를 검사했다. 메모리 DB에서 재시도 잠금 해제 후 새 PENDING을 확인하고 삭제하지 않는 경합을 검증했다. 완료·실패·취소의 미참조 조건, 현재 프레임 참조 보호, 기본 비활성화와 후보 페이지 순환도 테스트했다.

## 코드 정리에서 보존한 것

운영에서 쓰지 않는 OCR 구현은 정리했지만, 기존 발언 검토 fallback·실험별 frozen 재구성·과거 응답 계약은 일괄 삭제하지 않았다. 설정과 회귀 테스트에서 쓰는 코드를 데드코드로 오인하지 않는다. 구형 워터마크 회귀 코드는 테스트 폴더에 보관했고 삭제한 구형 parser는 Git 이력에서 복구할 수 있다. 사용자 데이터셋이나 원영상은 삭제하지 않았다.

실험 도구 전면 구조 개편은 미완료다. 공통 원장·보고서 집계/저장에 이어 과거 recipe 준비·검증을 `tools/issue_scoped_recipes.py`로 분리했다. stage 실행은 공유 실행기에 남겨 비용 예약/키 로딩/호출의 순서를 유지한다.

## 실험 보고서 책임 분리

`run_issue_scoped_comparison.execute`는 입력 검증·공통 원장 예약·키 로딩·요청·응답 계약 검사를 그대로 담당한다. 새 보고서 모듈의 `build_report`는 전달된 결과에서 비용/누락/상태와 실험별 보고 필드를 집계하고, `save_reports`는 원보고서와 별도 Java 감사 입력을 저장한다. 보고서 모듈 자체는 키·transport·예약 권한을 사용하지 않는다. 이 분리가 독립적인 유료 실행기를 새로 만든 것은 아니다.

- `fe2ace2`의 기존 보고서 집계 코드로 만든 합성 fixture의 SHA-256을 고정했다. 과거 일반 경로, bound live, 중단, mock, mock 중단, boundary 입력, context 재선택 7가지에서 새 함수의 논리 보고서 해시가 동일하다.
- 단일 JSON과 bundle의 원보고서·감사 입력이 같은 논리 값을 유지한다. 감사 변환 전 JSON 왕복으로 공유 객체 참조를 끊는 기존 동작을 보존하여 원보고서와 provider 원응답의 ID/문장이 바뀌지 않는다.
- mock은 API 호출/예약 소비/추정 청구 0, 가상 토큰 단가 값은 별도 필드다. 누락된 usage를 0원 확정으로 만들지 않고 unknownCostAttempts를 유지한다. 계약 통과는 의미 정확도 승인으로 승격하지 않는다.
- 기존 frozen 재구성·요청 hash·원장 중복 사용 차단·모의 stage/감사/예산 회귀 테스트도 전체 Python 검사에 포함했다. 모든 과거 private artifact를 전수 검증한 것은 아니며 실제 120 리포트나 frozen을 재작성하지 않았다.

실험별 registry 전환, 오래된 독립 실행기의 공통 원장 연결, 실행기 간 중복 요청 처리의 전면 통합은 후속이다. 판단 기준·모델·사전·운영 파이프라인은 바꾸지 않았다.

## 실험 준비·검증 책임 분리

`issue_scoped_recipes.py`는 기존 prepare/validate/catalog/bound/funding/target/full-boundary와 판단 요청 선택 함수를 소유한다. `experiment_costs.py`는 기존 byte 길이 + 2,000의 예약 휴리스틱과 Decimal 단가 계산을 그대로 옮겼다. 단가/토큰 계산법/승인 상수 값/프롬프트/요청 순서는 변경하지 않았다. recipe 모듈을 import하는 것만으로 실행기·transport가 있는 모듈·예약 원장을 로딩하지 않는 것도 독립 프로세스 테스트로 확인했다.

공유 실행기는 기존 prepare/validate 등의 이름을 호환 export로 제공한다. 준비/평가 도구는 새 recipe 모듈을 직접 참조하므로 실행기 의존을 줄였다. 시험용 예산 상수 patch 위치도 실제 소유 모듈로 바꿨다. 상수에 적힌 `userAuthorized`는 **과거 실험 재구성 자료**이지 새 유료 실행 승인으로 사용하지 않는다. 실제 실행은 기존 frozen 검증과 공통 원장 예약을 계속 통과해야 한다.
