# 행동·포즈 데이터셋과 긴 영상 적용 계획

> 기준 브랜치: `minwook` · 작성일: 2026-10-06 · 상태: 논문 검토 기반 설계, 데이터 수집·모델 실행 미실시

> 2026-10-08 상태 확인: 사용자 결정에 따라 **행동·포즈 개발은 보류**한다. 현재 구현은 STT/OCR 기반 텍스트 검토이며 이 문서의 시각 탐색·포즈 모델·데이터 수집은 실행하지 않았다. HyperFrames도 행동 분석 모델이 아니라 후속 합성/렌더 검토 도구이며 별도 도입하지 않았다. 현재 우선순위는 [향후 개발 계획](향후-개발-계획.md), 도구 연결 경계는 [비교·도구 검토](main-minwook-비교-및-도구-적용-검토.md)를 따른다. 아래 논문 설계안은 재개할 때의 참고 자료로 보존한다.

## 1. 참고 논문에서 가져올 것

사용자가 제시한 자료는 **SVHighlights: Towards Extremely Long Sport Video Highlight Detection**이다. alphaXiv 설명과 함께 논문 v2 원문 및 저자 저장소를 확인했다.

논문은 포즈 기반 논란 판별 연구가 아니라 긴 스포츠 영상의 하이라이트 탐지 연구다. 전체 영상과 공식 하이라이트를 정렬해 자료를 만들고, TF-SELECTOR는 샷과 음성 문맥으로 구간을 구성한 뒤 시각 설명·전사·음량으로 평가한다. 작업별 추가 학습이 없는 기준선이며, 실험은 A6000 GPU에서 수행됐다. [논문 원문](https://arxiv.org/html/2606.06926v2)

우리에게 적용할 가설은 의미가 이어지는 구간 구성, 짧은 클립을 원본 시점에 연결하는 자료 구축, 긴 영상 전체에서 후보를 찾아 검증하는 방식이다. 스포츠에서의 결과를 논란 탐지 성능으로 환산하지 않는다. 아래 행동 라벨·샘플링·검수 구조는 우리 서비스에 맞춘 제안이며 논문의 직접 구현이 아니다.

저자 코드에는 구간 분할·시각 설명·평가 구성이 공개돼 있다. 원본 경기 영상은 재배포하지 않고 요청 프레임은 연구 목적·재배포 제한을 둔다. 우리 자료 구축은 별도이며 해당 프레임을 상업 서비스 자료로 자동 편입하지 않는다. [저자 저장소](https://github.com/leedongkyu2019/SVHighlights)

## 2. 해결할 문제와 첫 행동 범위

목표는 긴 영상에서 짧게 나타나는 동작을 찾고, 같은 동작의 사용 맥락을 비교해 사람이 검토할 구간을 좁히는 것이다. 정지 포즈의 모양만으로 공격 의도나 화자의 소속을 추론하지 않는다.

첫 버전은 아래 세 행동군을 검토한다. 자료와 평가자 간 기준이 부족한 행동군은 보류할 수 있다.

| 행동군 | 관측 라벨의 예 | 문맥 검토 | 대조 자료 |
|---|---|---|---|
| 손가락 제스처 | 특정 손가락이 펴지고 다른 손가락이 접힌 상태, 예: `MIDDLE_FINGER_EXTENDED` | 누군가를 향한 사용인지, 설명·재현인지 | 제스처 설명, 우연한 손 움직임, 가림·저해상도 |
| 위협과 유사한 동작 | 손이 목 앞을 가로지르는 등 관측 가능한 궤적 | 발언·대상과 연결되는 위협인지, 연기·동작 설명인지 | 춤, 운동, 역할극, 일상 손 움직임 |
| 타인 동작의 재현 | 앞선 동작을 다시 수행하는 `MOVEMENT_REENACTMENT` | 특정인을 비웃는 맥락이 있는지 | 춤 따라 하기, 연기 연습, 설명·교육 |

관측 라벨은 임시 명칭이다. 인용·재현도 현재 조롱에 쓰일 수 있으므로 형식만으로 자동 통과시키지 않는다. 반대로 특정 손 모양이나 몸의 움직임만으로 차별·정치·커뮤니티 의미를 붙이지 않는다. 타인의 장애나 건강 상태를 동작에서 진단하지 않는다. 대상·상황이 확인되지 않으면 그 정보가 부족하다고 기록한다.

처음부터 모든 폭력·선정적 동작·표정·사회적 의미를 포괄하지 않는다. 초기 30개 파일럿에서 실제 구분 가능성과 자료 확보 난도를 확인해 우선 행동 2~3개를 확정한다.

## 3. 행동 라벨은 세 층으로 작성

| 층 | 기록하는 질문 | 예 |
|---|---|---|
| 관측 사실 | 누가 어느 구간에서 어떤 움직임을 보였는가? | 손가락 상태, 손의 이동, 방향, 반복, 접촉 여부 |
| 상황·관계 | 누구·무엇을 향했으며 어떤 발언·장면과 연결되는가? | 지칭 대상, 설명·재현, 역할극, 대상 불명 |
| 검수 결정 | 게시 전 사람이 다시 볼 구체적인 이유가 있는가? | `PASS`, `REVIEW_REQUIRED`, `UNCERTAIN`와 근거 |

포즈 검출 신뢰도는 관측 품질을 나타내며 검수 위험 확률이 아니다. 관측 사실이 확실해도 사용 의미가 불명확할 수 있고, 전체 영상에서 검수 이유가 명확해도 추출된 특징에는 필요한 정보가 없을 수 있다.

예를 들어 같은 손가락 상태를 설명하는 장면과 특정 출연자에게 사용하는 장면은 관측 라벨은 같고 검수 판단은 다를 수 있다. 자연 영상에서 그런 쌍을 확보하고 사람이 차이를 설명하도록 한다.

## 4. 포즈 좌표와 원본 영상을 함께 보관

몸의 관절 위치만으로 손가락 형태·물체·시선·대상을 모두 알 수 없다고 가정한다. 행동 라벨링에는 연속 RGB 프레임 또는 원본 짧은 영상, 필요한 손 영역, 시간별 몸·손 키포인트, 동시간대 STT/OCR를 연결한다.

MediaPipe Pose Landmarker는 몸의 33개 지점을, Hand Landmarker는 손의 21개 지점을 추정하는 구성으로 초기 특징 추출을 검토할 수 있다. 이 출력 자체가 우리 검수 유형의 분류기는 아니다. [몸 포즈 공식 문서](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker), [손 랜드마크 공식 문서](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker)

확장 실험에는 RGB·스켈레톤 행동 인식과 시간 구간 탐지를 지원하는 MMAction2를 검토한다. 기존 행동 클래스가 우리 동작을 이미 정확히 분류한다고 가정하지 않는다. 첫 자료 규모만으로 새 동작 모델의 일반화 성능을 주장하지 않는다. [공식 개요](https://mmaction2.readthedocs.io/en/latest/get_started/overview.html)

사람의 주석은 필요한 프레임의 관측·근거를 먼저 확정하고, 모든 프레임의 모든 관절을 손으로 수정하지 않는다. 자동 키포인트 오류는 검수 품질 기록에 남기고 모델 학습에 필요한 표본만 후속 교정한다.

## 5. 한 행동 사건의 필수 정보

| 정보 | 목적 |
|---|---|
| `event_id`, `case_id`, `source_id` | 구간·사례·원본 연결 |
| `action_start_ms`, `peak_ms`, `action_end_ms` | 준비·주요 동작·종료 위치, 핵심 동작 구간 별도 |
| `context_start_ms`, `context_end_ms` | 지칭 대상과 사용 목적을 확인하는 범위 |
| `actor_track_id`, 대상 참조(선택) | 영상 안에서 인물을 구분, 실제 신원 불필요 |
| `observed_action`, 반복·방향·접촉 | 물리적 동작의 관측 내용 |
| `frame_pts`, 인물/손 영역, 키포인트 참조 | 실제 원본 시간과 특징 연결 |
| `visibility`, 가림·크기·흐림·추적 단절 | 보이지 않음을 일반 행동으로 오해하지 않게 함 |
| 연결 STT/OCR·근거 사건 ID | 발언·화면·행동 관계 |
| 사용 맥락·결정·이유·불일치 | 사람이 검토한 해석과 한계 |
| `pair_id`, `leakage_group_id`, 원본/재현 구분 | 대조 실험과 평가 누출 방지 |

가변 프레임률 영상은 프레임 번호에 평균 FPS를 곱해 시간을 만들지 않고 실제 PTS와 원본 타임라인을 사용한다. 감속·속도 변경·자르기를 하면 원본 시간 매핑을 보존한다. 경계가 불명확하면 가능한 범위와 주석자 차이를 기록한다.

키포인트는 좌표계·인덱스·모델 버전·가시성·원본 시간과 함께 저장한다. 누락된 지점을 0 좌표로 정상 관측한 것처럼 다루지 않는다. 이미지 기준 좌표와 추정 3D 좌표를 혼용하지 않는다. 거울 영상·좌우 반전은 메타데이터로 기록한다.

여러 인물의 트랙은 샷 단위의 지역 ID부터 시작하며 컷 변경 때 추적을 재설정한다. 다른 컷의 사람을 자동으로 동일인이라고 확정하지 않는다. 다시 같은 인물인지 필요한 표본에만 수동 연결한다.

## 6. 원본과 문제로 제기된 짧은 클립의 정렬

짧은 클립을 원본에 연결하는 방식은 사건 자료 구축에 활용할 수 있다. 우리 클립은 크롭·자막 삽입·속도 변경·반복·부분 삭제가 있을 수 있어 자동 정렬 결과를 후보 위치로 취급한다.

1. 클립·원본 식별자, 편집 여부, 이용 범위를 기록한다.
2. 프레임 유사도나 이미지 특징으로 원본 후보 시점을 찾는다.
3. 여러 프레임의 시간 순서와 음성 단서를 함께 비교한다.
4. 편집 구간별 원본 시간 매핑을 저장하고 사람이 연속 장면을 확인한다.
5. 정렬 완료 뒤 앞뒤 문맥을 확장해 독립적인 검수 주석을 작성한다.

정렬 신뢰도와 검수 결정은 별도다. 클립에 들어간 구간을 자동 문제 라벨로 만들거나, 클립에 안 들어간 원본 구간을 일반 라벨로 만들지 않는다. 리플레이·동일 동작의 반복은 각각의 출현 시점을 보존하고 원본 사건과 재생 관계를 연결한다. 원본이 없으면 긴 영상 위치 평가에는 쓰지 않는다.

## 7. 긴 영상 처리 가설

전체 영상을 제한된 프레임 몇 장으로만 대표하지 않고, 아래 단계를 스트리밍 방식으로 처리하는 구조를 실험한다.

| 단계 | 처리 | 산출물 |
|---|---|---|
| 전체 탐색 | 샷 경계, 저비용 움직임·몸/손 관측, 시각 후보와 STT/OCR | 후보 범위와 실제 탐색 범위 |
| 문맥 구성 | 대화가 이어지는 샷 연결, 무음 동작 구간 보존 | 문맥 구간, 인접 구간 참조 |
| 상세 확인 | 후보 주변 연속 프레임·손 영역·키포인트·RGB 확인 | 행동 사건과 시점·관측 품질 |
| 검수 판단 | 실제 영상·발언·화면·대조 사례를 함께 확인 | 결정·근거·부족한 정보 |
| 위치·출처 정리 | 중복 사건 연결, 경계 보정, 원본 시간 변환 | 타임라인 후보와 분석 범위 |

발언이 없거나 민감 단어가 없더라도 시각 후보를 만들 수 있어야 한다. 움직임이 큰 장면만 고르면 정지한 손 제스처를 놓칠 수 있다. 사람·손 형태·연속 RGB 등 시각 단서를 함께 검토하고, 무음 영상에서도 독립 실행한다.

우리 설계에서는 문맥 구간과 행동 구간을 분리한다. 1분 문맥 안의 0.3초 행동을 전체 1분의 위험으로 표시하지 않고, 상세 확인 단계에서 실제 사건 경계를 반환한다. 단일 시각 설명만 저장하면 세부 손 모양이 사라지거나 설명이 틀릴 수 있어 원본 순서·영상 근거를 유지한다.

## 8. 샘플링과 놓침을 측정하는 방법

초기 비교값으로 전체 탐색 4~8fps, 후보 상세 확인 12~24fps를 검토한다. 이는 성능이 검증된 설정이 아니라 실험할 범위다. 원본 FPS보다 높은 관측 정보를 만들 수 없으며 복제 프레임을 추가 관측으로 세지 않는다.

현재 OCR 기본 간격 4초를 행동 탐색에 그대로 사용하면 그 사이에 끝나는 동작을 놓칠 수 있다. OCR과 행동의 추출 간격을 따로 설계한다. 손이 작거나 가려진 경우에는 높은 FPS만으로 해결되지 않으므로 크롭·해상도·가시성도 비교한다.

같은 짧은 정답 사건을 원본 프레임률과 서로 다른 샘플링 위상·FPS로 확인해 짧은 행동의 누락률을 측정한다. 상세 단계가 후보 구간에만 실행되면 전체 탐지율은 후보 단계의 재현율을 넘을 수 없으므로 후보 재현율을 먼저 평가한다.

1시간 영상을 4fps로 탐색하면 약 14,400개 프레임이 된다. 이 중 시간 기준 5%인 180초를 20fps로 상세 확인하면 약 3,600개 프레임을 추가 처리한다. 이는 처리량 계산 예시이며 속도·비용 절감의 실측값은 아니다. 디코딩·키포인트·RGB 모델 비용을 별도로 잰다.

후보가 아니었던 구간도 표본 감사하며, 평가 영상은 사람이 전체 확인해 실제 후보 누락을 센다. 가림·추적 실패·예산 상한으로 못 본 구간은 정상 판정으로 세지 않는다. 탐색 범위와 상세 판단 범위를 각각 기록한다.

## 9. 데이터 규모와 긴 영상 평가

공통 계획의 30개 파일럿에서 행동 10개·복합 10개부터 기준을 맞춘다. v0.1 200개 안의 행동 80개와 복합 40개를 시각 분석 자료로 사용한다. 별도 120개를 추가한다는 뜻은 아니다.

일반 행동 대조 자료에는 각도·거리·좌우 반전·동작 시작과 끝·가림·손에 물체가 있는 경우·여러 인물·설명/재현을 포함한다. 같은 영상의 비슷한 프레임 수백 개를 독립 사례 수로 홍보하지 않는다.

긴 영상 평가의 시작 구성은 서로 독립적인 영상 6개다. 예시 길이는 20·30·45·60·90·120분이며, 실제 확보 가능한 원본으로 조정한다. 이 구성의 원본 시청은 합계 365분이며 두 사람의 첫 시청만 약 12시간 10분이다. 주석·정지·재시청·조정 시간은 추가된다.

완결 영상에는 짧은 사건, 여러 곳에 분산된 사건, 무음 사건, 일반 행동, 여러 출연자, 행동이 컷 경계에 걸리는 장면을 포함한다. 평가용 원본과 같은 사건·대조쌍·연출 원본은 검색·학습·튜닝에 넣지 않는다.

자연 자료가 부족하면 팀 촬영으로 각도·속도·가림을 시험할 수 있다. 배우·장소·촬영 세션을 그룹으로 묶고, 이런 자료의 성능은 실제 콘텐츠 성능과 따로 보고한다.

## 10. 비교 구성과 평가 지표

| 비교 구성 | 확인할 질문 |
|---|---|
| 현재 STT/OCR 파이프라인 | 기존 서비스에서 어떤 시각 사건이 빠지는가? |
| 고정 간격 이미지·프레임 묶음 VLM | 일반적인 시각 검토만으로 얼마나 해결되는가? |
| 연속 RGB + 문맥, 포즈 없음 | 움직임·문맥이 주는 이득은 무엇인가? |
| 몸/손 특징 + 연속 RGB + 문맥 + 대조 사례 | 특징 추출·후보 선택·사례가 추가 비용을 정당화하는가? |

모델·자료·프레임/호출 예산 차이를 기록한다. 대조 사례 추가 전후와 문맥 추가 전후를 따로 비교한다. 텍스트 전용 모델 대비 개선만으로 시각 기술의 독창성을 주장하지 않는다.

- 후보 재현율: 사람이 정한 사건 중 상세 검토에 들어간 비율
- 사건 탐지 정밀도·재현율: 관측 행동과 검수 결정의 오류를 별도로 계산
- 시간 위치: 이벤트 구간의 temporal IoU, 경계 오차, 짧은 사건의 누락률
- 사용 부담: 영상 1시간당 불필요 알림, 사람이 검토할 시간, 같은 사건의 중복 알림
- 자원: 영상 1시간당 처리시간, 최대 메모리, 프레임·모델 호출 수, 저장량
- 한계 처리: 가림·추적 실패·문맥 부족·부분 분석의 기록 정확성

매칭은 같은 행동 유형·사건의 시간 겹침을 기준으로 일대일 처리하고, IoU 기준 등을 개발셋에서 정해 평가 전에 고정한다. 시간 겹침만으로 다른 사건을 정탐 처리하지 않는다. 가시성·동작 길이·영상 길이별 성능도 보고한다. 주석이 불확실한 사례를 일반 정답으로 밀어 넣지 않는다.

최상위 후보 하나만 맞는 지표로는 긴 영상의 다른 사건 누락을 설명할 수 없다. 후보 수/검수 시간 예산에 따른 사건 탐지율을 함께 보고, 전체 영상에서 누락까지 계산한다.

## 11. 서버 연결과 비용 제약

현재 백엔드의 `PoseAnalyzer`는 `supports()`가 항상 false인 미구현 상태다. 시각 coverage도 미제공으로 기록한다. 이 계획은 해당 기능을 켰다는 의미가 아니다.

후속 구현은 Python에 장면·프레임·몸/손 특징 추출을 추가하고, Spring은 요약된 행동 후보·근거·범위만 받아 기존 타임라인과 연결하는 방향이다. 모든 프레임·키포인트를 JPA 엔티티로 저장하지 않고 버전 있는 특징 파일과 구간 요약을 연결한다.

캐시 키에는 원본 해시, 추출 FPS·해상도, 샷/특징 모델 버전, 기준 버전을 포함한다. 샷별 작은 단위로 처리하고 인물 추적 상태를 리셋해 메모리를 제한한다. 긴 작업에는 단계별 결과 저장·재개·진행 조회가 필요하며, 현재 10분 HTTP timeout과 분석 전체 트랜잭션만으로 2시간 영상 처리가 보장되지 않는다.

먼저 오프라인 파일럿에서 추출 시간·메모리·누락을 측정한다. 현재 OCR 간격이나 활성 분석기를 바꾸지 않고, 무거운 공개 모델·스포츠 자료를 통째로 다운로드하거나 유료 GPU를 실행하지 않는다. 무료 모델에도 연산·저장 비용은 있으며, 기존 사용 가능한 장비와 배포 환경의 실측 뒤 모델을 선택한다.

## 12. 진행 순서와 통과 조건

| 순서 | 작업 | 통과 조건 |
|---|---|---|
| 1 | 행동 2~3개·주석 기준·파일럿 | 두 사람이 관측과 해석을 구분하고 이견을 기록할 수 있음 |
| 2 | 실제 대조 사례·원본 시간 매핑 | 원본·행동 경계·근거·일반 용례가 확인됨 |
| 3 | 작은 추출 프로토타입 | 원본 PTS·몸/손 특징·가림·샷 단절·실측 비용이 기록됨 |
| 4 | 긴 영상 후보 탐색 비교 | 짧은·무음·정지 제스처의 후보 누락과 예산 영향을 측정함 |
| 5 | 문맥·사례 포함 검수 비교 | 일반 VLM 대비 오탐·미탐·검수시간·비용 변화를 확인함 |
| 6 | 서버 연결 검토 | 완료/부분/실패 범위, 작업 재개, 원본 시간, 타임라인/API가 연결됨 |

수집·평가 계획은 공통 문서의 4~6주 초안을 따른다. 실제 시각 모델 개발과 운영 연결의 일정은 장비·파일럿 결과를 보고 별도로 산정한다.

기술 차별성 가설은 긴 영상의 순간 행동을 빠뜨리지 않는 후보 선택과, 비슷한 행동의 맥락 차이를 실제 대조 사례로 설명하는 능력이다. 데이터셋 구축 또는 공개 모델 추가만으로 우위가 입증됐다고 말하지 않는다. 고정한 평가셋에서 일반적인 시각 검토보다 유용한 결과가 나오는지 확인한다.
