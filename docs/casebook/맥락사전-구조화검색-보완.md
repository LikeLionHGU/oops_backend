# 맥락 사전 구조화 검색 보완

2026-10-16 · minwook · 로컬 검색 개선. 외부 API 호출 0회이며 모델 판단 개선 시험과 구별한다.

## 원인과 변경 범위

기존 검색은 고정된 `retrievalView.text`와 현재 원문의 문자 3조각이 3개 이상 겹칠 때만 예시 후보를 만든다. 속옷 질문과 사전의 성적 관계 질문은 의미상 비교할 여지가 있어도 문자 교집합이 0개였다. 반대로 집단 전체 표현에서는 `이라는`·`했다는`·`적으로` 등의 조각으로 쟁점과 다른 사례가 선택됐다. 이 누락은 최대 3개나 글자 예산에 도달하기 전에 발생했다.

v7에서는 기존 검색에 **작성된 개념 조합 검색**을 보완했다. 임베딩·벡터 DB·LLM 의미 검색이 아니며 학습한 모델도 아니다. 현재 2개 프로필만 다루므로 모든 논란 맥락을 포괄하지 않는다.

| 검색 프로필 | 현재 원문에서 찾는 조합 | 참고 사례의 조건 |
|---|---|---|
| 사적 신체 정보 질문 | 속옷·성생활 관련 표현 + 질문·색깔·공개 제안 등 | sexual-objectification에 연결되고, 고정 검색 문구에 성적 정보 질문 맥락이 있음 |
| 집단 전체 평가 | 집단 지칭 + 모두·전체 등 범위 + 부정 평가·공격 서술 | group-generalization에 연결되고, 고정 문구에 집단 일반화 맥락이 있음 |

프로필은 `oops-backend/src/main/resources/context-search-profiles.json`에 두며 사건 ID를 하드코딩하지 않는다. 현재 원문과 사전 문구 각각에 정규식 조합을 적용한다. 질문 대상이나 실제 관계를 이해하는 의미 판정은 아니므로 부정·인용·자기서사를 해석하는 최종 검증을 대신하지 않는다.

## 실행 계약

- Spring의 `structured-context-search-enabled` 기본 true, 환경변수 `STRUCTURED_CONTEXT_SEARCH_ENABLED=false`로 이전 검색 재현.
- v7에서만 사용하며, v1~v6와 과거 명시적 생성자 시험의 동작은 유지한다.
- 현재 원문은 같은 채널·검토 대상 구간만 사용한다. 여러 발언의 조건을 연결할 때는 20초 이내의 창을 사용해 먼 대화를 한데 합치지 않는다. 길이가 긴 단일 구간은 그 구간 자체로 비교한다.
- 사전에서는 **고정 검색 문구와 mechanismIds만 사용**한다. 판단용 flow·비판 가설·정상 해석을 수정했다고 검색이 조용히 바뀌지 않는다.
- 개념이 맞는 참고를 후보 풀에 추가하고 기본 문자 검색보다 먼저 고려한다. 선택적 LLM 라우터의 균형 선택에서는 유한한 0.20 가산점이며 강제 선택은 아니다. 기존 후보/근접 문맥 교차 배분은 유지한다.
- 채널·제외 family·최대 개수·전체 6000자·참고 3000자 예산을 우회하지 않는다. 예시는 잘라 넣지 않는다.
- `contextSelections.structuredSearch`에 카탈로그 개정·SHA256·활성 프로필·검색된 예시·최종 선택 예시를 남긴다. 원문이나 새 개인정보를 추가 기록하지 않는다.
- 프로필·점수·검색용 규칙은 판단 프롬프트에 추가하지 않는다. 기존과 같은 형태로 선택된 사례만 전달한다.
- 추가 검색 API 비용은 없지만, 참고가 0개에서 3개로 늘면 후속 판단의 입력 토큰은 늘어난다. 기존 크기 예산 안에서 제한하며 실제 최종 판단 비용 차이는 후속 비교에서 측정한다.
- 사전 JSON·원장·정답 승인·판단 프롬프트·대상 검증 계약은 변경하지 않았다. 코드 기본값 반영에는 Spring 재시작이 필요하며 이 작업에서 서버를 재시작하지 않았다.

## 무료 재현 결과

Groq 후속 점검의 고정 16조건·23검색 창을 같은 원문·같은 runtime SHA256으로 비교했다. 속옷 질문과 집단 전체 표현의 이전/새 전사 4조건·7검색 창에서 선택이 바뀌었고 정상 초안 6조건은 선택이 그대로였다. 전체 참고 payload 최대값은 3769자로 6000자 예산 안이다.

| 입력 | 이전 문자 검색 | 보완 후 |
|---|---|---|
| v4 속옷 질문 · 이전/새 전사 | 예시 0개 | 감스트·김원훈·이미주의 성적 질문 관련 참고 3개. 이전 전사의 마지막 비활성 배치는 여전히 0개 |
| v6 집단 전체 표현 · 이전/새 전사 | 군 복무·개인정보·신체 대상화 참고 | 고누리·장동민·침착맨의 집단 일반화 관련 참고 |
| v6 죽음 표현 · 이전/새 전사 | 예시 0개 | 그대로 0개. 직접 대응 사례를 새로 만들거나 강제로 연결하지 않음 |
| 정상 초안 6조건 | 기존 선택 | 모두 동일. 정상 판정 성공률을 측정한 것이 아님 |

관련 사례가 늘었다는 것은 참고 자료의 회수 개선이지 최종 검토 대상의 정답 판정이 아니다. 특히 성적 질문 사례들의 당사자·강요·동의 맥락은 현재 영상과 다를 수 있다. 집단 전체 평가 프로필도 사건 행위 비판·비판적 인용을 함께 회수할 수 있으며, 같은 대분류 안의 세밀한 순위는 아직 어휘 점수와 동점 순서에 의존한다.

비공개 결과: `datasets/controversy/experiments/groq-pipeline-audit-20261016/retrieval-structured-v1.json`. 원문·사전 해시와 실제 참고 prompt를 보관한다. 예산·정답 상태를 승격하지 않는다.

OFF 재현은 `retrieval-legacy-replay-v1.json`에 저장했다. 이전 23검색 창의 선택·trace·판단 계약 문구·파싱한 참고 JSON이 모두 같다. 기존 JSON 직렬화의 객체 필드 순서는 프로세스 간 달라질 수 있어 문자열 바이트 동일성을 주장하지 않는다.

최종 `./gradlew --offline test`는 807개 통과·실패 0·skip 0이다. 신규 10개 테스트는 문자 일치 없는 회수, 무관한 어휘 참고와의 순위, 단일 단어 비활성, 가까운/먼 대화 경계, 제외 사건·채널·검색 문구, 판단 설명 불변, 정상 인용의 참고 허용, 선택적 균형 점수, 구버전 유지, 실제 v7 예산·롤백을 확인한다. 실제 v7 파일이 없는 환경에서는 해당 로컬 사전 테스트를 건너뛴다.

재현 명령은 Spring 디렉터리에서 실행한다. `auditOutput`은 존재하지 않는 비공개 파일을 지정한다. `inspect`가 이전 검색, `inspect-structured`가 보완 검색이다. 두 모드 모두 외부 호출이 없다. `run` 모드는 이번 비교 대상이 아니므로 실행하지 않는다.

```bash
./gradlew --offline groqPipelineAudit \
  -PauditMode=inspect-structured \
  -PauditInput=../datasets/controversy/experiments/groq-pipeline-audit-20261016/pipeline-input.json \
  -PauditRuntime=../datasets/controversy/guidelines/runtime.json \
  -PauditOutput=../datasets/controversy/experiments/groq-pipeline-audit-20261016/NEW-retrieval.json
```

## 다음 검증

후속 [정상 경계·최종 판단 비교](../experiments/구조화검색-OFF-ON-정상경계-비교.md)는 총 32회·추정 $0.019863으로 완료했다. 정상 초안에서 경고는 없었으나 필수 출력값 실패는 OFF 1/12·ON 4/12였다. 최종 판단 우위는 미확인이며, 아래 계획의 1차 실행 결과로 읽는다. 신규 초안은 정식 사전 미승격이다.

정상 경계 자료를 검수하고, 같은 원문에서 검색 OFF/ON만 바꾼 최종 판단 비교로 오탐·미탐·출력 계약 실패를 분리 측정한다. 새 영상·정상 대조·제외 사건 평가도 필요하다. 유료 호출은 새 승인 범위에서 진행하며 이번 결과로 정확도·안정화 완료를 주장하지 않는다. 죽음 표현의 직접 사례 부족과 대상 관계 계약 실패는 별도 과제로 남는다.
