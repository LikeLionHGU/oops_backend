## 실제 첫 수집 확인 — 2026-10-09

사용자가 키를 설정한 터미널에서 수집기를 실행했고, 전달한 로컬 파일 `uploads/comment-collections/youtube-comments-20261009T110156485858Z.json`을 읽어 확인했다. 실제 API 호출은 사용자가 수행했다. 네 요청 모두 SUCCESS, 각 50개씩 총 200개 응답에서 commentId 중복 하나를 합쳐 **199개**가 남았다. SBS 99개 / JTBC 100개. COMPLETE_SAMPLE은 설정한 표본 요청이 성공했다는 뜻이지 전체 댓글 수집 완료가 아니다. 네 페이지 모두 hasMore=true였다.

상위 댓글만 수집했으며 작성자 메타데이터는 저장하지 않는다. 본문에는 자기소개·가족·거주지 언급 등이 있어 privacyReviewed=false를 유지한다. 이 파일을 통째로 공개하거나 학습에 전송하지 않는다. 댓글 작성 시각 범위는 2024-05-17~2026-10-02로, 사건 당시와 이후 반응이 섞여 있다. 좋아요 수를 정답 가중치로 사용하지 않는다.

첫 내용 검토에서 D 표현에 대한 직접 반응, C 메뉴·주는 대로 먹기 언급, 지역/생활/추억을 낮춘다는 사건 수준 반응, 정상 취향·풍자라는 반론, 인물 욕설·사과·복귀·다른 사건에 대한 반응을 확인했다. B의 정확한 롯데리아 대화에 직접 연결되는 비판 근거는 이번 표본에서 상대적으로 부족하다. 광범위한 지역 비하 반응을 임의로 B의 특정 문장에 배정하지 않는다. 댓글 속 식당 환경·상호 노출·업주 앞 발언 등의 주장은 추가 확인 없이 원영상 사실로 확정하지 않는다.

**실제 수집 자료 199개 / 승인된 논란 사례·독립 주석·합의 0건**이다. 실제 원장과 런타임 사례집은 여전히 EMPTY이며 자동 라벨링·모델 학습·프롬프트 편입은 하지 않았다. 다음은 발언 직접 반응/사건 전체 해석/인물 공격/반론/무관 자료를 검토하고 원문과 연결할 수 있는 사례만 초안으로 구성하는 단계다. 최종 사람 승인과 용도별 활용 조건 확인은 별도다.

파일의 refreshOrDeleteBy는 한국시간 **2026-11-08 20:01:53**이다. 자동 갱신·삭제·알림을 설정한 것은 아니며 기한까지 갱신하거나 삭제해야 한다. 댓글 원문은 Git 제외된 로컬 수집 파일에만 두고, 공개 문서에는 수집 메타데이터와 작업 상태만 남긴다.

## 로컬 수집 실행 준비 완료

`tools/collect_youtube_comments.py`를 추가했다. 사용자가 키를 export한 **같은 터미널**에서 실행한다. Python 표준 라이브러리만 사용하며 추가 설치는 필요 없다.

```bash
cd /Users/im_inwook/dev/oops_backend
python tools/collect_youtube_comments.py
```

기본 SBS·JTBC 두 영상에서 각각 relevance/time 순 최대 50개씩 조회한다. 최대 4회 요청·200개 상위 댓글이며 중복 commentId는 합친다. 답글·모든 페이지·전체 여론을 수집하는 기능은 아니다. 인기순과 최근순 모두 표본 편향이 있고 사건 당시의 반응만 조회하는 방식도 아니다. 원본 시청 여부는 수집 조건으로 사용하지 않는다.

기본 파일은 저장소 루트의 `uploads/comment-collections/`에 개인 읽기/쓰기 권한으로 새로 생성한다. uploads는 Git 제외 대상이다. 작성자 이름·프로필·채널 ID·키를 저장하거나 출력하지 않는다. **댓글 본문에 개인정보가 남아 있을 수 있으므로 수동 검수 전 외부 전송·커밋하지 않는다.** 출력은 수집 수·안전한 오류 코드·파일 경로만 보여준다.

권한/쿼터/댓글 비활성 오류 시 우회·자동 재시도하지 않는다. 부분 성공은 PARTIAL_SAMPLE, 전부 실패는 FAILED로 표시하고 실제 확보 자료만 저장한다. 30일 뒤 갱신/삭제 시각을 기록하지만 자동 삭제/갱신은 구현하지 않았다. 이 파일은 임시 검토 자료이며 승인 원장·학습·사례 검색에 자동 편입하지 않는다. 용도별 허용 범위 확인은 아래 정책 경계를 따른다.

이번 구현은 모의 API 응답 테스트만 실행했다. 실제 사용자의 키를 전달받거나 실 API 수집을 실행한 것은 아니다. 실행 후 출력의 savedTo 경로를 알려주면 접근 가능한 로컬 결과를 확인할 수 있다.

발견 링크는 `datasets/controversy/source-candidates.json`에 따로 기록했다. 이는 출처 후보 목록이며 실제 원장·학습 자료가 아니다. **수집 댓글 0건**, 독립 주석/승인 사례 0건, 런타임 사례집 EMPTY는 그대로다. 댓글 수집기·모델 호출·학습은 실행하지 않았다.

목표 자료는 논란 발언·상황과 그에 대한 네티즌 반응이다. 기자 해설은 제외하며 댓글 작성자가 원본을 직접 봤는지는 수집 요건으로 삼지 않는다. 발언별 비판, 반론, 인물·사건 전체에 대한 감정 반응을 서로 구별한다.

## 접근과 활용의 별도 확인

[공식 commentThreads.list](https://developers.google.com/youtube/v3/docs/commentThreads/list)는 영상 ID별 공개 댓글을 페이지 단위로 조회하는 수단이다. 현재 작업에서 사용할 자격 증명을 제공받거나 API를 호출하지 않았다. 키를 채팅에 붙여넣지 않는다.

[YouTube 개발자 정책](https://developers.google.com/youtube/terms/developer-policies)은 API 클라이언트의 직접/간접 스크래핑 금지(III.E.6), 일반 데이터의 30일 후 갱신/삭제(III.E.4.c/d), 파생 데이터 제한(III.E.4.h)을 명시한다. 따라서 API 키만 확보하면 댓글을 영구 데이터셋이나 모델 학습에 자유롭게 쓸 수 있다는 전제로 진행하지 않는다. 허용된 용도를 확인하거나 별도 허가·적합한 이용 조건의 자료를 확보한 후 원장에 편입한다.

다음 단계는 공식 API 접근 가능 여부와 해당 용도의 사용 조건 확인이다. 접근 차단 우회·비공식 댓글 엔드포인트·대체 스크래핑 경로는 사용하지 않았다. 이 문서는 법률 판단이나 사용권 승인 문서가 아니다.
