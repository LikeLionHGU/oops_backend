구체적 데이터 전송 승인을 받은 뒤 계획대로 실행했다. 사용량 추정 $0.025426, 런타임 예약 추정
$0.4762182, HTTP72회다. 비교안은 지역 흐름1/3 검토·66공방0/3 정상 PASS, 계약 실패5건으로
기본 적용을 보류했다. [전체 결과와 한계](판단-기준-비교안-40-결과.md)를 우선한다.
아래 실행 차단 내용은 전송 승인 전 준비 이력이다. 이후 추가 호출·서버 반영은 하지 않았다.

## 10/15 실제 비교 준비 상태

추가 추정 $5 예산을 사용자에게 승인받았다. 첫 묶음은 그 안에서 추정 $1 하위 상한, 12조건×두 안×3회=72회다.
기존 저장 요청이 없어 DB를 읽기 전용(IFEXISTS/ACCESS_MODE_DATA=r)으로 열어 전사·시간을 읽고,
수동 고정한 후보를 현재 엔진에 넣어 검증 입력을 새로 조립했다. 과거 요청의 재현이 아니다.
64 지역/신체 비유, 65 제품 리뷰, 66 공방은 사용자 검수 흐름 네 조건이며, 67의 위생 두 anchor/저속한
뜻풀이와 69의 순진함/위생/피해 행위 서술 두 구간/정치 비판은 미검수 여덟 조건이다.
정답/검수 상태는 모델 입력이 아닌 plan의 관리 메타데이터다. 두 안의 raw·역할·근거·참고는 같다.
홀수 반복은 기준선→비교안, 짝수 반복은 반대 순서다. 무작위 순서 시험이나 독립 gold 평가는 아니다.

준비 파일은 private experiments/context-policy-plan-40-20261015 아래에 있으며 사전 예약 추정은 약 $0.496이다.
요청/출력 한도와 HTTP 재시도를 포함하는 런타임 예약은 추정 $1/최대80시도에서 중단한다.
단가는 기존 설정 값(input $0.10/cached $0.01/output $0.50 per 1M)이며 실제 청구 보장값이 아니다.
이번 러너는 새 테스트 전용 ContextPolicyTrial이고 이전 $1 제한 러너의 예산 한도를 전역 확대하지 않았다.

유료 실행 도구 호출은 권한 검사에서 프로세스 시작 전에 차단됐다. 64/65/66/67/69의 전사 발췌·후보·
참고 사전을 OpenAI API로 보내는 구체적 데이터 전송 동의가 추가로 필요하다는 사유다. 우회하지 않았고
provider 호출/청구는 0이다. 새 결과 폴더나 측정 결과는 아직 없다. 승인을 받은 뒤에만 실행한다.

기준선은 실행 개정 39/기본 37이다. `ContextJudgmentPolicy`는 src/test에만 있어 Spring 업로드에
적용되지 않는다. env 플래그·모델·사전·카드 형식·근거 검사·처리 한도도 변경하지 않았다.
40은 비교안 식별자이지 다음 업로드의 실행 개정이 아니다.

## 무엇을 바꾸는가

기존 POLICY를 아래 판단 순서로 교체한다. 기존 지시문 뒤에 지침을 계속 누적하는 방식이 아니다.
POLICY 뒤의 탐색/검증 JSON 계약과 고정 참고 문자열은 그대로 유지한다.

1. 발화의 기능/귀속: 누가 한 행위인지, 화자가 서술·인용·비판·옹호·농담·직접 공격 중 무엇을 하는지
   원문으로 구분한다. 사건 서술자를 가해자로 바꾸거나 화자·친밀도·합의·억양을 추측하지 않는다.
2. 정상 해석과 구별되는 근거: 부정적인 단어가 남는다는 순환 설명이 아니라 실제 낮춤/조롱의 방식과
   대상을 설명한다. 별도 근거는 반드시 별도 문장이라는 뜻은 아니며 직접 모욕도 놓치지 않는다.
3. 판정 후 유형/점수: 근거가 없으면 PASS, 해석에 필수 정보가 빠지면 UNCERTAIN, 원문으로 설명되는
   구체적 검토 사유가 있으면 REVIEW_REQUIRED다. 단순 해석 차이를 무조건 보류로 돌리지 않는다.

농담·인용·정치 비판을 일괄 면책하지 않는다. 비판적 서술 안에서도 별도의 피해자 모욕/과도한 성적 재현은
검토할 수 있지만, 서술된 가해 행위를 곧바로 화자가 피해자를 대상화한 근거로 쓰지 않는다.
지역 생활·선택지 폄하는 주민 전체 일반화가 없어도 검토하며 신체 훼손 비유 자체에는 실제 폭력 의도를
요구하지 않는다. 특정 영상·유튜버·단어를 무조건 PASS시키는 예외는 없다.

## 비교 준비와 측정 범위

최초 검증 요청의 실제 원문/역할/후보/참고는 고정하고 system의 POLICY만 바꾼 두 요청을 만든다.
같은 후보로 하는 검증 비교는 탐색 누락·전체 파이프라인 성능을 측정하지 않는다. 그 검증 후 별도 승인으로
탐색+검증 전체 비교를 해야 한다. 기본 실행에 시험용 치환 클라이언트를 연결하지 않았다.

준비 도구는 실제 저장된 request-traces 응답 또는 Snapshot JSON만 읽는다. SHA 불일치·유실/잘림 기록·
다른 실행 개정·복구 요청은 거절한다. API 클라이언트 호출/서버 시작/자동 예산 승인 기능은 없다.
원문·참고 문자열·후보·입력 SHA는 동일하고 두 system SHA만 다르다. 입력 promptRevision은 원본39를
유지하며 plan의 schemaVersion에 비교안40을 기록한다. providerRequestBody/응답/판정 정답은 복사하지 않는다.
향후 실제 실행 시 원래 모델/샘플링/출력 한도 등도 별도로 고정해야 한다. 준비 성공만으로 실행 가능 모델이나
금액을 확인한 것은 아니다. 문자 수 변화와 실제 토큰·과금 변화도 구분해 측정해야 한다.

```bash
cd /Users/im_inwook/dev/oops_backend/oops-backend
export JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home
./gradlew prepareContextJudgmentComparison \
  -PtraceInput=/절대경로/실제로저장한-request-traces.json \
  -PtrialOutput=/Users/im_inwook/dev/oops_backend/datasets/controversy/experiments/새비교폴더
```

출력 폴더는 experiments 아래 기존 부모의 새 하위 폴더여야 한다. 실제 원문이 들어가므로 Git/공유 금지,
기존 진단 자료 폐기 정책을 적용한다. API 키/진단 토큰은 입력 파일이나 문서에 넣지 않는다.
현재 로컬에는 64~69의 저장 요청 파일이 확인되지 않아 **과거 요청 재사용 plan**은 만들지 않았다.
위 별도 ContextPolicyTrial plan은 저장 전사를 이용한 새로운 수동 후보 시험이다.
서버 재시작으로 사라진 진단/요청을 리포트에서 재구성해 동일 요청이라고 주장하지 않는다.

## 고정할 평가 기준

- 최소 양성 유지: 사용자 승인한 64의 지역 선택지 비하 흐름과 신체 훼손 비유. 특정 카드 문구/개수보다 근거와 흐름을 본다.
- 정상 대조: 65의 제품 리뷰, 66의 사용자가 정상으로 승인한 친근한 공방. 영상 전체 무문제 정답으로 확대하지 않는다.
- 67~69: 위생 공방, 저속한 뜻풀이, 사건의 비판적 서술은 미검수 경계 사례다. 먼저 발췌·필요 문맥·라벨을 검수한다.
- 새 근거 없는 해석 확대, 전사 오류 의존, 대상/서술자 혼동, HIGH 과대평가, 미확인/형식 실패를 별도 집계한다.
- 두 안의 반복 횟수와 입력을 고정하고 정상 대조의 경고가 줄어도 양성 미탐/보류가 늘면 개선으로 승인하지 않는다.
- 후보 미생성을 검증 PASS로, 계약 실패/예산 제외를 정상으로 세지 않는다. 개발에 사용하지 않은 영상도 후속 평가한다.

OpenAI Docs의 [평가 지침](https://developers.openai.com/api/docs/guides/evaluation-best-practices)을 참고해
기준선/변경 축/정답 상태/측정 범위를 분리했다. 이번 결과는 무료 조립·계약 테스트이지 모델 정확도 측정이 아니다.
