# 구조화 검색 OFF/ON · 정상 경계 비교

2026-10-16 · minwook · 사용자 승인: 새 설정 단가 기준 추정 상한 $1.00 및 저장·합성 텍스트의 OpenAI 전송. 실제 청구 상한 보장은 아니다.

## 고정 조건과 범위

이전 작업의 참고 회수 개선이 최종 판단에도 영향을 주는지 확인한다. 새 영상 업로드가 아니라 저장된 Groq STT 발췌와 합성 대조의 **후보 탐색·최종 근거 검증** 비교다. OCR·시각 검증·리포트 카드 병합·DB 저장은 범위 밖이다.

- 실제 발췌: v4 속옷 질문, v6 집단 전체 표현. 두 입력 모두 독립 사람 정답이 없는 잠정 검토 자료다.
- 합성 정상 초안: 자기 경험, 속옷 상품 설명, 사적 질문의 비판적 인용, 특정 관계자 비판, 집단 일반화의 비판적 인용, 이용자 대상 장애 안내.
- 8조건 × 검색 OFF/ON × 2회 = 32회 엔진 실행. HTTP 호출 수와 엔진 실행 수는 다르다.
- 모델은 `gpt-6-luna`, reasoning `none`. 판단 프롬프트·후보 엔진·v7 원장과 참고 예산을 고정한다. LLM 라우터·원문 관계 추가·시각 검증은 양쪽 모두 끈다.
- 1회차 OFF→ON, 2회차 ON→OFF로 순서를 바꾼다. 두 번으로 반복 안정성을 입증하지 않는다.
- 합성 대사는 정식 사전·정답셋·학습 자료에 승격하지 않는다. 기대 PASS·경계 설명·합성 라벨은 모델에 보내지 않는다.
- 검색 보완은 성적 질문·집단 평가 참고만 바꾼다. 정상 대조를 사전에 넣는 것까지 동시에 바꾸지 않아 효과를 분리한다.

정상 초안은 `oops-backend/src/test/resources/structured-search-boundaries.json`에 저장했다. 사적 신체 표현이나 ‘모두’가 포함돼 **검색 자체는 활성화되지만 최종 경고는 없어야 한다는 개발 가설**을 시험한다. 이 가설은 아직 사람이 개별 승인한 정답이 아니다.

## 측정과 실행 안전장치

각 실행의 요청·파싱 응답·선택 참고·후보 근거·검증 결과·미판정 ID·토큰 사용량·소요 시간을 보관한다. 정상 초안은 SUCCESS·경고 0·미판정 0일 때만 완전한 무경고 처리로 집계하며, FAILED/PARTIAL의 경고 0을 정상 통과에 합치지 않는다. 실제 발췌는 정답 재현율을 계산하지 않고 유지된 쟁점과 경고 근거를 직접 검토한다.

`StructuredSearchBoundaryTrial`은 기본 무료 준비 모드와 별도 승인 실행 모드로 나눴다. 실행은 고정 plan SHA256과 새 승인 문자열이 필요하며, 원문·사전·검색 카탈로그·판단 계약 해시가 다르면 중단한다. OpenAI의 지정 모델·텍스트 전용 endpoint만 허용한다. 모든 HTTP 시도 전에 보수적 예약을 기록하고 새 $1.00·160시도 한도를 넘기 전에 차단한다. 제공자/사용량 추적 실패 시 실험을 중단하며 자동 재시작하지 않는다.

요금 추정은 기존 설정 단가 입력 $0.10/캐시 $0.01/출력 $0.50 per 1M 기준이며 실제 가격·청구 확인이 아니다. 검색 호출이 추가되지 않아도 선택 참고가 늘면 판단 입력 토큰이 증가할 수 있다.

실험 설계는 경계 사례·단계별 평가·비교·사람 검토를 권고하는 [OpenAI 평가 지침](https://developers.openai.com/api/docs/guides/evaluation-best-practices)을 참고했다. 이번 비교는 개발 자료이며 범용 성능을 보증하지 않는다.

## 결과

32/32회 완료, HTTP 55시도와 사용량 추적 55건이 일치했다. 정책·사전·검색 프로필·서버 설정은 변경하지 않았다. 정상 초안 6개는 사전에 승격하지 않았다.

### 정상 초안 · 6조건을 각 2회

| 항목 | OFF | ON |
|---|---:|---:|
| SUCCESS·경고 0·미판정 0 | 11/12 | 8/12 |
| FAILED | 1/12 | 4/12 |
| 발행된 경고 수 | 0 | 0 |

실패 5건은 모두 빈 후보 응답의 `truncated`가 파싱 후 null인 경우다. 특정 관계자 비판 OFF 1회, 자발적 자기 경험 ON 1회, 사적 질문 비판적 인용 ON 2회, 집단 일반화 비판적 인용 ON 1회였다. 실패를 정상 판정으로 계산하지 않는다. 표본 내 ON에서 형식 실패가 더 많았으며, 적은 반복으로 검색이 실패의 원인이라고 확정하거나 정상 성능이 유지됐다고 주장하지 않는다.

### 실제 발췌 · 정답 미확정

| 입력 | OFF 1·2회 | ON 1·2회 | 확인 |
|---|---|---|---|
| v4 속옷 질문 | 경고 1·1, 모두 PARTIAL | 경고 2·1, 모두 PARTIAL | 질문 자체는 양쪽 2/2 유지. ON 추가 경고를 탐지 개선으로 계산하지 않음 |
| v6 집단 전체 표현 | 경고 0·0, PARTIAL·SUCCESS | 경고 0·0, 모두 PARTIAL | 관련 참고 회수가 경고 증가로 연결되지 않았고, 원래 전체 표현의 후보 유지도 불안정 |

v4 ON 1회의 추가 경고는 자발적 제안인 ‘보여드릴까요?’를 설명하면서 ‘보여 달라’는 방향으로 서술한 부분이 있다. 현재 전사에는 화자 분리·동의 확인이 없으므로 요청과 제안의 주체를 뒤집거나 강요를 보충하면 안 된다. 두 경고는 같은 대화를 공유하며 최종 리포트 병합 전 결과이므로 실제 중복 카드 수로 해석하지 않는다. 추가 경고가 별개 쟁점인지·원문 행위 방향이 유지됐는지 검수가 필요하다. 이 후보는 OFF 2회와 ON 2회 중 1회에서 `TARGET_EVIDENCE_REQUIRED`로 탈락해 형식·근거 계약 문제도 남았다.

v6 ON 1회에서는 ‘진영이 모두’라는 원래 표현 `groq-v6-140`이 후보로 유지됐지만 최종 검증은 정치적 행위 비판으로 PASS했다. ON 2회에서는 뒤의 다른 표현들이 대표 후보가 됐다. 검증 이유는 반복적으로 ‘열등하거나 우스운 대상으로 묘사한 근거가 없다’는 경계를 사용했다. **집단 전체에 행위를 귀속하는 일반화와 구체적 행위자 비판의 경계**를 검수해야 하며, 사전에 관련 사례가 있다는 이유로 경고를 강제하지 않는다. 실제 정답 승인 없이 이 결과를 확정 미탐/정상으로 집계하지 않는다.

## 결론과 다음 우선순위

검색 회수는 개선됐지만 최종 판단 품질 우위는 입증하지 못했다. 새 사례를 늘리거나 검색 규칙을 더 추가하는 것보다 아래 문제를 분리해 다룬다.

1. 빈 후보라도 필수 출력값을 반환하도록 출력 계약을 안정화한다. null을 조용히 false로 채우거나 실패를 PASS로 바꾸지 않는다.
2. 요청/제안·본인/상대·인용/직접 발언의 방향이 후보와 최종 이유에서 유지되는지 검사한다. 대상 근거 탈락은 별도 진단한다.
3. 집단 전체 단정과 특정 행위 비판의 판단 경계를 사람 검수로 구체화하고, 그 후 검색과 독립적으로 비교한다.

검색 기본값은 이번 작업에서 추가 변경하지 않았다. 정상 초안은 검수 전 상태이며, 이번 비교를 범용 정확도·안정화 완료로 보지 않는다. 무료 도구 회귀와 실제 모델 시험 결과도 분리한다.

전체 `./gradlew --offline test`는 811개 통과·실패 0·skip 0이다. 신규 테스트 4개는 입력 고정·초안 상태·모델 입력에서 메타데이터 제외·검색 활성·순서 교차·해시 변경 차단·예산/시도 상한을 검증한다. 이번 승인 실행은 완료됐으며 재시험은 별도 새 실행 승인 범위에서 진행한다.

## 후속 · 출력 계약 안정화 연결 (무료)

5건의 빈 후보 실패를 대상으로 탐색 응답에만 Structured Outputs를 요청할 수 있게 연결했다. [OpenAI 공식 문서](https://developers.openai.com/api/docs/guides/structured-outputs)에 따라 JSON 객체만 보장하는 모드와 필수 필드·타입을 지정하는 스키마 모드를 구분한다. 이 문서는 특정 Luna 계정·모델의 실제 지원 확인을 대신하지 않는다.

- 설정: `oops.openai.structured-discovery-output-enabled`, 환경변수 `STRUCTURED_DISCOVERY_OUTPUT_ENABLED`. **실제 제공자 호환 시험 전이므로 기본 false**다. 이 작업만으로 실행 중 서버의 출력 형식이 바뀌지는 않는다.
- 대상: `CandidateReviewEngine.Discovery`만 opt-in annotation을 갖는다. 검증·복구·선택적 라우팅·이미지 요청과 과거 명시적 2인자 클라이언트는 기존 JSON 모드를 유지한다.
- 스키마: `oops-backend/src/main/resources/candidate-discovery-output.schema.json`. 최상위 5개 필드를 모두 필수로 지정하고 `truncated`는 null 없는 Boolean이다. 빈 후보도 필드를 생략하지 않는다. true도 허용하며 임의로 false를 채우지 않는다.
- 일반 제안은 reason을, 원문 관계 실험 제안은 sourceRelations를 갖는 별도 구조로 정의한다. 서로 사용하지 않는 필드를 억지로 생성하지 않는다. 근거는 기존처럼 segmentId만 요구한다.
- 원문 ID·최대 후보 수·허용 창·근거·대상 검증은 서버에서 계속 검사한다. 형식 준수는 의미·논란 판단의 정답 보증이 아니다.
- 미지원 스키마/HTTP 오류를 기존 JSON 모드로 조용히 재전송하지 않는다. 거절·응답 중단도 실패로 남긴다.
- 기존 모드에서도 `truncated` 누락/null은 `INVALID_DISCOVERY / DISCOVERY_TRUNCATED_REQUIRED` 진단으로 구분한다. 실패를 PASS로 바꾸는 정책 변경은 없다.
- 타입을 받는 `replayRequestBody` overload는 실제 opt-in 요청과 같은 response_format을 재현한다. 기존 타입 없는 재현은 JSON 모드를 유지한다.

저장된 실패 5건의 빈 후보 파싱 응답을 오프라인 JSON Schema로 대조했고 모두 `truncated` 타입 한 곳에서만 거절됐다. 과거 응답은 수정하지 않았다. 모의 HTTP 테스트는 정상 false 통과, 누락/null 실패 보존, 허구 ID 거절, HTTP 400의 비전환, 거절/길이 중단 실패, DTO별 적용 범위, 스키마의 중첩 필수 필드를 확인한다.

이 단계는 **구현·무료 계약 검증**이며 실모델의 실패 감소를 검증한 결과가 아니다. 다음은 새 승인 범위의 소규모 실제 호환 시험 후 스위치 활성화 판단이다. 그 전에는 프로덕션 기본값을 켜거나 과거 32회 결과를 새 결과처럼 재집계하지 않는다. 사전·판단 프롬프트·원문·정상 초안 승인 상태·서버 배포는 변경하지 않았다.

후속 전체 회귀는 820개 통과·실패 0·skip 0이다. 신규 모의 HTTP/스키마 테스트는 9개이며 실제 모델 호출은 0회다. 과거 비교 도구의 명시적 클라이언트는 기본 JSON 모드이므로 환경변수만 바꿔 기존 승인 plan을 strict 시험으로 재사용하지 않는다. 새 시험에서는 출력 계약 여부를 별도 고정해야 한다.
