## 현재 구현 대조 — 2026-10-14

### 10/14 추가 구현: 공통 정의 분리

신규 빌드와 사건 추가는 `definitions/build.json`을 읽는다. 이 파일에는 카드/사전/catalog의 공통 메타·메커니즘 정의·기존 순서만 보존하고 사건 payload/메커니즘의 실제 sourceCaseIds는 넣지 않는다. 사례 매핑은 사건 파일에서 매번 재조립한다. 빠진 사건의 옛 sourceCaseIds가 잔존하지 않으며 미등록 메커니즘·중복 사건/발언을 거절한다.

기존 cards/plan/catalog를 읽는 것은 명시적 마이그레이션·과거 동치 검사 경로뿐이다. 신규 generate/add에 자동 fallback이 없다. 아래 'reassemble이 기존 템플릿을 읽음/단일 입력 미달'은 이 구현 전 상태다. compile 라이브러리는 재사용하고 기존 CLI 아카이브는 실제 이전 자료 동치 확인 후로 보류한다.

```sh
# 유효한 기존 공통 정의가 있는 데이터셋에서 1회만 명시적으로 실행. 기존 정의 덮어쓰기 금지.
python tools/incidents_migration.py --emit-definition --dataset-root /path/to/dataset
# 사건 파일이 준비된 뒤 입력에서 생성해 검사. runtime 저장은 --write를 별도로 명시.
python tools/build_incident_dataset.py --dataset-root /path/to/dataset --verify
```

현재 로컬 레거시 목록은 초기화돼 예전 6사건/메커니즘이 비어 있다. 위 명령을 자동 실행해 과거 내용을 복원하거나 빈 정의를 운영에 반영하지 않았다. 새 데이터셋의 공통 메커니즘 정의는 준비·검수해야 한다. 합성 자료의 실제 컴파일 결과/직렬화 동치와 레거시 파일이 없는 임시 디렉터리 빌드를 테스트했다. 과거 6사건 실자료 동치·아카이브 완료로 대체하지 않는다.

| 항목 | 확인한 구현 | 남은 경계 |
|---|---|---|
| 사건 입력 | incident-2 스키마·변환/emit·기사-only 추가 도구 존재 | 아래 목표 JSONC를 그대로 입력하지 않음 |
| 입력 형식 | catalogMeta와 statements; statement의 mechanismIds/topicTags와 legacyCard/legacyDictionaryCard 등 호환 필드 | 평탄한 excerpt/article 전용 형태로 전환 완료 아님 |
| 빌드 | incidents·definitions/build.json·snapshot에서 재조립, write/verify 분리 | compile 라이브러리 재사용, 실자료 동치/구형 CLI 아카이브 대기 |
| verify | 입력에서 재생성한 runtime과 저장 runtime 비교, refreshOrDeleteBy 제외 | 출력만 읽는 검증/항상 바이트 동일 검사는 아님 |
| 추가 | dry-run 기본; apply 후 생성 가능성 검사; 생성 실패 시 새 사건 파일 제거 | runtime 자동 갱신/저장본 동치 검사 아님 |
| 승인·운영 | 새 사건 미검수/승인 플래그 false, Java 출력 스키마 유지 목표 | 입력 저장·생성 성공은 배포·학습 승인과 별개 |

사용 순서는 **후보 공유·확인 → add_incident 미리보기 → apply → 별도 build write → verify**다. write는 로컬 runtime 변경이므로 반영 목적과 검수 상태를 확인한 뒤 실행한다. 이번 문서 갱신에서는 생성/쓰기 명령을 실행하지 않았다. 6단계 컴파일러 아카이브는 완료로 표시하지 않는다.

신규 generate/reassemble의 기존 출력 읽기는 제거했다. '사건=파일 하나'는 사건 입력 단위이며 공통 정의·출처 파일까지 없다는 뜻은 아니다. 명시적 마이그레이션/과거 동치 경로만 기존 자료를 읽는다.

## 0. 목표 요약

한 사건의 자료가 **6개 파일에 쪼개져 순환 참조**하는 현재 구조를, **사건 = 파일 하나
(`incidents/{incidentId}.json`)** 로 통합하고, 빌드를 **"생성(입력만 읽음) ↔ 검증(출력만 읽음)"**
으로 분리해 catalog↔cards 순환을 제거한다. runtime 출력과 Java는 그대로 둔다.

## 2. 목표 의미 구조 — 사건 = 파일 하나

아래 JSONC는 설계 당시 의미 구조이며 현재 incident-2 유효 입력 예제가 아니다. 실제 스키마는 catalogMeta와 statement별 legacy 호환 필드를 요구한다. 파일 생성은 add_incident 최소 스펙/미리보기를 따른다. 기사와 STT 출처 필드는 종류별로 분리하고 설명 필드를 동시에 채워 출처를 혼합하지 않는다.

경로: `datasets/controversy/incidents/{incidentId}.json`
사건 id 규칙: `{channel}-{topic}-{yyyymmdd}` (게시일 기준). 예 `pisik-yeongyang-20240511`.

```jsonc
{
  "schemaVersion": "incident-2",
  "incidentId": "pisik-yeongyang-20240511",

  // 승인 게이트 — 전부 false 로 생성. 사람만 승격한다.
  "status": "UNREVIEWED_DRAFT",
  "humanApproved": false,
  "runtimeEligible": false,
  "trainingUseAuthorized": false,

  "split": "DEVELOPMENT",
  "topicTags": ["지역", "음식"],              // 검색 주제(위험 라벨 아님)

  // 사건 안의 개별 논란 발언 = 발언근거(statement). 1:N.
  "statements": [
    {
      "id": "pisik-yeongyang-20240511#s1",
      "mechanismIds": ["local-life-devaluation"], // §9 메커니즘 전이 단위. 배열 — 한 발언이
                                                  // 둘 이상에 걸릴 수 있다(예: 지역비하+조롱).
                                                  // 비어 있으면 안 됨(최소 1개).
      "sourceKind": "STT_TRANSCRIPT",            // STT_TRANSCRIPT | NEWS_BODY | AUDIENCE_REACTION
      "statementKind": "SOURCE_UTTERANCE",       // SOURCE_UTTERANCE | AUTHOR_INTERPRETATION
      "excerpt": "이것만 매일 먹으면 햄버거가 천상의 맛일 것",
      "whyControversial": "지역 음식을 '매일 이것만' 처지로 그려 식생활을 낮게 취급.",

      // 출처 종류별로 하나만 채운다 (상호 배타)
      "article": {                               // sourceKind=NEWS_BODY 일 때
        "publisher": "데일리안", "url": "https://...",
        "publishedDate": "2024-05-25", "retrievedOn": "2026-10-13",
        "snapshot": "research/source-snapshots/dailian-...-extract.txt",
        "sha256": "..."                          // 발췌만 저장, 전문 금지(SHORT_EXTRACT_NOT_FULL_ARTICLE)
      },
      "transcriptWindowMs": [20500, 24000],      // sourceKind=STT_TRANSCRIPT 일 때만

      // 참조 전용 — 같은 family 평가 입력 금지 (치팅 차단). 코드 family 제외 그대로.
      "evaluationUse": "REFERENCE_ONLY_SAME_FAMILY_EXCLUDED"
    }
  ],

  // 댓글 반응은 선택(optional). 비어도 사건 성립 (§10.2).
  "reactions": [],

  // 적용 경계·정상 대조. 반론/가상 예문은 정상 영상으로 계산하지 않는다.
  "boundaries": ["부재·욕구·대체는 정상 설명에도 있다. ..."],
  "normalControlCases": [],

  "missingContext": ["저장 STT의 제한된 창. 원음·화자·억양 미확인. ..."],

  "provenance": {                                // 마이그레이션 추적용
    "migratedFrom": ["catalog.json", "drafts/cards.json#pisik-B", "guidelines/plan.json"],
    "legacySha256": "..."
  }
}
```

### 2.1 스키마가 결함을 어떻게 없애나
- **C 해소:** 사건의 catalog 항목·카드·mechanism 매핑·topicTags·기사 출처가 **한 파일 안**에 있다.
  교차 참조할 다른 입력 파일이 없으므로 A(순환)가 **구조적으로 발생 불가**.
- **B 해소:** `reactions` 가 선택이고 `collectionId` 가 사라진다. 댓글 없는 사건은 `reactions: []`.
  댓글이 있으면 `AUDIENCE_REACTION` sourceKind 또는 `reactions[]` 에 보강으로만 붙인다.
- **메커니즘 전이(§9) 준비:** `statements[].mechanismIds` 가 사건 안에 직접 있어, mechanism→statement
  역매핑을 별도 `plan.json` 없이 빌드가 수집한다. 배열이므로 한 발언이 복수 메커니즘(지역비하+조롱 등)에
  걸리는 경우를 단일→배열 마이그레이션 없이 처음부터 표현한다(수백 규모에서 반드시 발생).

## 3. 빌드 재구성 — 생성 ↔ 검증 분리 (A 순환 제거의 핵심)

현재: `build_bundle` 하나가 "옛 출력 검증 → 새 출력 생성"을 섞어 순환을 만든다.
확정: **두 함수로 쪼갠다.**

```
build.py --write      incidents/*.json  (입력만 읽음)
                        → build/cards.json → build/context-dictionary.json → guidelines/runtime.json
                      생성 단계는 기존 출력을 절대 읽지 않는다. 순환 불가.

build.py --verify     guidelines/runtime.json (출력만 읽음)
                        → 스키마·해시·mechanism 커버리지·family 제외 검증
                      검증 단계는 입력을 생성하지 않는다.
```

- 중간 산출물(`cards.json`, `context-dictionary.json`)은 `build/` 캐시로 숨긴다. 사람이 손대지 않는다.
- `runtime.json` **출력 스키마는 그대로**. Java `ReviewGuidelineLibrary`(review-guidelines-1~5) 변경 0.
- `catalog.json` 은 **생성물로 강등**(사건 목록은 `incidents/*.json` 글롭으로 자동 집계). 더 이상 수기 입력 아님.

## 4. 마이그레이션 — 되돌릴 수 있는 7단계

각 단계는 독립 커밋. 어느 단계든 `git revert` 로 되돌아간다. **사람 승인·런타임 편입·학습 사용은 전 과정 0 유지.**

1. **스키마 고정 커밋** — Git 에 올리는 것은 `tools/schemas/incident-2.schema.json`(소비자가 tools/ 의
   Python 데이터셋 도구이므로 그 트리에 배치; Java 런타임과 무관)과 이 문서뿐. 실제 `incidents/*.json`
   데이터는 `/datasets/` 아래 로컬 생성물로 Git 제외. 코드 영향 0.
2. **신규 빌드 경로 추가(병행)** — `build_incident_dataset.py` 신설. 기존 3개 컴파일러는 **그대로 둔다**.
   새 빌드가 기존과 **동일한 runtime.json 을 생성**하는지 바이트 비교 테스트부터 통과시킨다(동작 동치 증명).
3. **기존 6사건 변환** — `catalog + cards + plan 3개` → `incidents/{6개}.json`. 변환 스크립트는 1회용,
   결과를 사람이 눈으로 확인. 변환 후 새 빌드 산출 runtime.json == 기존 runtime.json(바이트 동일) 검증.
4. **생성↔검증 분리 적용** — §3. `--write`/`--verify` 분리. 순환 검증 제거.
5. **collectionId optional / reactions optional** — B 제거. **완료(2026-10-13).** 새 빌드 경로는
   catalog `UNKNOWN_COLLECTION` 을 안 타고, compile 은 빈 reactions 를 받아낸다. 실증 과정에서 드러난
   진짜 장벽은 `reassemble` 이 '원본에 없는 새 사건'을 cards/gplan 에 반영하지 못한 버그였고(2단계는
   기존 6사건 그대로라 안 드러남), 이를 "원본 순서 먼저 + 새 사건 뒤에" 로 고쳐 기사-only 신규 사건이
   전 체인을 통과함을 회귀 테스트로 고정했다.
6. **기존 3개 컴파일러 아카이브** — 새 경로가 동치임이 증명된 뒤에만 `tools/archive-*/` 로 이동(삭제 아님).
   Java·runtime 스키마는 이 단계에서도 불변.
7. **그 위에 `add_incident.py`** — "incidents/{id}.json 하나 작성 → build --write → build --verify".
   저장 규칙(사례 추가 전 **후보를 사용자에게 공유**)을 도구에 내장: 기본 dry-run, `--apply` 로만 기록.

### 4.1 동치 증명이 안전의 핵심
2·3단계의 "새 빌드 == 기존 runtime.json 바이트 동일"이 **마이그레이션 전체의 안전핀**이다.
이게 통과해야 "구조만 바꿨고 판정 동작은 안 바꿨다"가 증명된다. 통과 전에는 기존 경로를 지우지 않는다.

## 5. 범위 밖 (이번에 하지 않음)

- **§9 메커니즘 필터의 Java 구현**은 별개 작업이다. 이번은 데이터에 `mechanismId` 를 **담는 자리**까지만.
  라우팅 로직(`ContextExampleSelector` 가산점, 분류 1-pass)은 풀영상 벤치마크 후.
- **런타임 편입·학습 승격·사람 승인**은 0건 유지. 스키마의 승인 게이트는 전부 false 로 생성.
- **기사·댓글 사용 범위**(저작권·개인정보)는 기존 보안 운영정책과 매체 약관을 따른다. 발췌만 저장.
- **새 사건 추가**는 이 구조가 선 뒤(7단계) `add_incident.py` 로. 그 전에는 추가하지 않는다.

## 6. 결정 기록 (2026-10-13 세션)

### 확정된 결정
1. **사건 id = 사건 식별자, 카테고리 아님.** id 는 내부 큐레이션/빌드용 라벨이며 **사이트·모델 응답에
   노출되지 않는다**(런타임은 `mechanismIds`/`context`만 모델에 전달, 사건 id 는 로컬 진단 전용). 따라서
   기준은 "사람이 읽어 알아보기 쉬움 + 유일 + 불변"뿐이다. 카테고리(왜 논란인가)는 가변 해석이라
   id 가 아니라 발언의 `mechanismIds` 속성으로 분류한다. 식별과 분류를 분리한다.
2. **메커니즘은 배열(`mechanismIds`).** 한 발언이 복수 메커니즘(지역비하+조롱 등)에 걸리는 경우를
   처음부터 표현한다. 최소 1개, 빈 배열 금지. 단일→배열 후행 마이그레이션 회피.
3. **메커니즘은 사건에 종속되지 않는 독립 식별자.** 발언이 메커니즘을 "가리키고", 같은 메커니즘이
   여러 사건을 가로질러 축적된다(§9 전이 학습의 단위). 메커니즘을 사건 안에 폴더처럼 가두지 않는다.
4. **동치 증명을 머지 게이트로 삼는다** — "새 빌드 == 기존 runtime.json 바이트 동일"이 마이그레이션
   안전핀. 통과 전 기존 경로를 삭제하지 않는다.
