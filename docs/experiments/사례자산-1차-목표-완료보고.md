## 대표 메커니즘

기존 승인 자료만 재사용했다. 실제 저장 전사 2조건(R01-166 뜻풀이, 피해 경험 인용)과 합성 4조건(R04 직접 요청, R05 정의, R06 비판적 인용, R08 요청 후 중단)이다. 승인 범위는 해당 문맥의 개발 판단이다. 구조화한 설명은 개발자 초안이며 새 사용자 승인이나 독립 검수로 승격하지 않았다.

- 원문·기존 라벨·승인 범위는 `evidence.json`에만 보관한다.
- 작성한 상황·관계·성립/불충분 조건·정상 경계는 `references.json`에 보관한다.
- 서로 다른 소재의 관계 대조도 포함한다. 모든 연결이 같은 문장을 한 조건만 바꾼 최소 편집 쌍은 아니다.
- 다섯 사례를 서로 경쟁하는 개별 참고로 전송하지 않고, 비교 경계를 포함한 짧은 메커니즘 묶음 하나를 생성했다.
- 압축 참고의 관계 3문장과 경계 2문장에는 각각 지원 사례 ID를 연결한다. 이는 출처 연결 검사이며 의미적 참·거짓의 자동 검증은 아니다.
- 기존 승인 평가 자료를 사례 자산 개발에 재사용했으므로 해당 사례·원본 그룹을 향후 독립 평가로 보고하면 안 된다. `development-use-registry.json`에 표시했으며 기존 평가 실행기에 강제로 제외시키는 연결은 이번 범위에 포함하지 않았다.

실행 계약 호환 검사를 위해 기존 Java archive 형식의 **별도 preview-runtime.json**도 생성했다. 이는 43개 운영 사전을 덮어쓰지 않는 44참고 미리보기이며, 대표 피해 경험 참고를 맥락형으로 바꾸고 경계 묶음 1개만 추가한다. 공통 6개 판단 문구는 변경하지 않았다.

원문 분리는 이번 신규 메커니즘 자료와 교체한 대표 참고에 적용된다. 미리보기에 보존한 나머지 기존 참고까지 원문이 제거된 것은 아니다. 전체 43개가 맥락형으로 전환됐다고 해석하면 안 된다.

## 검색 검사: 발견한 실패를 구분한다

실제 `ReviewGuidelineLibrary`를 로컬에서 호출했다. Spring·영상 처리·LLM은 실행하지 않았다. 최대 3개·예시 3000 code point·전체 6000 code point와 구조화 검색 ON을 양쪽 동일하게 사용했고, 수동 routing hint·정답·예상 판정을 검색기에 전달하지 않았다.

### 43개 색인 자가 검사

현재 색인 문구 자체를 질의한 검사에서 43/43이 자기 참고를 회수했다. 화면 전용 1개는 편집 텍스트 역할을 가정한 색인 검사다. **이것은 로딩·색인 배선 검사이며 실영상의 의미 검색 성공률이 아니다.**

### 6개 저장 문맥 검사

| 입력 | 현재 사전 | 맥락형 미리보기 |
| --- | --- | --- |
| R01-166 뜻풀이 | 넓은 성적 주제 사례 3개 | 새 경계 묶음이 후보 풀에 있지만 최종 3개에서 탈락 |
| R04 직접 요청 | 넓은 성적 주제 사례 3개 | 동일한 순위 탈락 |
| R05 정의 | 넓은 성적 주제 사례 3개 | 동일한 순위 탈락 |
| R06 비판적 인용 | 넓은 성적 주제 사례 3개 | 새 경계 묶음 최종 선택 |
| R08 요청 후 중단 | 넓은 성적 주제 사례 3개 | 새 경계 묶음이 후보 풀에 있지만 최종 선택 탈락 |
| 피해 경험 인용 | 해당 기존 참고 선택 | 맥락형으로 바꾼 해당 참고 선택 유지 |

새 경계 묶음은 관련 질의 5개 모두의 구조화 검색 후보 풀에 진입했다. 그러나 최종 선택은 1/5였다. 네 건은 budgetSkipped=0이므로 문자 예산 초과가 아니라 순위·최대 선택 슬롯 단계에서 탈락한 것으로 확인했다. 공통 주제 일치가 관계 경계 적합성을 보장하지 않는다는 증거다. 정확도·판정 개선이나 의미 이해 성능은 측정하지 않았다.

이번 범위에서는 실패를 저장하고 중단했다. 검색기에 맞추기 위해 원문을 색인에 복사하거나 설명문에 단어를 계속 추가하는 식으로 반복하지 않는다. 후속은 관계 경계의 순위/다양성 선택을 별도 변경 축으로 설계해야 한다. 단순히 최대 개수를 늘려 해결했다고 간주하지 않는다.
