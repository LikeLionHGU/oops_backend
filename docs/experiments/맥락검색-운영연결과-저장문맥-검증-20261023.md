## 이전 자료 해석 정정

99번 당시 사전은39개,109번은41개였다. 이후110·111번은42개 사전으로 카드0개였다. 따라서99/109 과거 오류가 현재43개 사전에도 계속 존재한다고 단정한 이전 설명은 부정확했다. 과거 응답에 현재 소스·사전 버전을 소급 적용하지 않는다.

후보 진단의 실제 참고 선택은 analyzer 최상위의 빈 `contextSelections`가 아니라 `candidatePipeline.contextSelections`에 들어 있었다. 후보별 선택과 사전 버전을 함께 확인한다.

## 채택 판단 변경의 이유

앞선 ‘다른 소재3조건에서 추가 회수>0’ 문턱은 이미 올바른 참고가 회수되는 조건에서도 추가 이득을 요구했다. 이를 통과하지 못했다는 이유로 필요한 운영 연결까지 끝내지 않은 것은 적절하지 않았다.

새로 일반화 성공을 주장하는 대신, 확인된 회수 누락4조건의 보완과 이미 회수되는3조건의 보존을 각각 검사했다. 개발44참고에서는 경계 참고 회수1/5→5/5, 기존 피해 경험 참고 유지가 실제 `select` 연결 후 재현됐다. 운영43참고의3문맥에서는 참고·JSON 입력 내용이 유지됐다.

이 제한된 근거로 **범위가 제한된 검색 보완 경로를 연결**했다. 새44번째 경계 묶음의 운영 데이터 승격은 하지 않았다. 현재43참고에서 성능이 새로 좋아졌다고 주장하지 않는다. 검색 경로 연결과 사례 자산 승격은 별개다.

## 운영 경로와 안전장치

- 전달/정의/요청 단서는 참고 선택용 휴리스틱이며 판단 규칙이 아니다.
- 이미 주제 프로필·메커니즘 라우팅에 부합한 후보 풀 안에서만 선택한다. 제외 사건은 다시 끌어오지 않는다.
- 후보가 있으면 허용 원문 ID로 focus를 다시 조회하고 주변15초 단서를 사용한다.
- 첫 참고 보존, 최대 한 슬롯 교체. 상한1이면 기존 첫 참고를 교체하지 않는다.
- 기존 개수·예시3000·전체6000code point 제한 유지. 크기 불충족 시 기존 선택 유지.
- 라우팅 키 균형 선택 경로는 보존한다. v1~v6, 구조화 검색 OFF, CAPTION은 적용 대상이 아니다.
- 진단 `boundarySupplement`에 revision/state/queryCues/addedId/removedId를 기록한다. 원문·예상 정답을 이 진단에 추가하지 않는다.
- 새 운영 ON/OFF 플래그는 추가하지 않았다. 명시적9인자 생성자의 boolean은 오프라인 기준선 비교용이며 Spring 생성자는 연결 경로를 사용한다.

`ContextFitRankingPreview`는 기존 실험 이름 호환용 test 어댑터다. 실제 구현은 `ContextBoundarySupplement` 하나이며 복제본을 유지하지 않는다. 공용 판단 프롬프트·운영 사전 내용은 변경하지 않았다.

## 남은 범위

운영 프로세스는 재시작하지 않았으므로 실행 중 Spring에 적용됐다고 말하지 않는다. API/DB 통합, 전체 영상 신규 분석, 설명의 행위자 귀속 오류, 새 경계 묶음의 데이터 승격은 별도 범위다. 발췌의 PARTIAL 해소를 위해서는 더 넓은 실제 전사를 승인 범위에 맞춰 제공해야 하며 상태만 고치지 않는다.
