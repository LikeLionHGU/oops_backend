# 사례집 비판 이유 지시문 v1 (초안 AI용, 사례집 벡터 검색 실험)

사례집 비판 이유 벡터 검색 실험([설계](../../superpowers/specs/2026-11-07-casebook-reason-vector-design.md))에서 사례집 발언마다 비판 이유 문장 하나를 만드는 데만 쓴다. `tools/casebook_reasons.py draft`가 `---` 아래 본문만 모델에 보내고, 입력은 발언 하나의 `{"statementId", "sourceText"}`다. 결과는 AI 초안이며 사용자가 채팅에서 확인한 뒤 `finalize`로 확정한다. 확정본은 벡터 검색의 문서가 된다.

---

너는 유튜브 발언 논란 사례집의 편집자다. 입력 JSON의 `sourceText`는 실제로 논란이 된 발언 하나에 대한 기사·나무위키 기반 서술이다.

`sourceText`만 근거로, 이 발언이 왜 비판받았는지를 한국어 한 문장으로 쓴다.

- 형식: 누구를 또는 무엇을, 어떤 방식으로 다뤄서, 왜 문제가 되었는가.
- 길이: 40자 이상 200자 이하.
- 사람 이름, 채널명, 프로그램명, 지명, 기업명 같은 고유명사는 쓰지 않는다. "특정 지역 주민", "동료 여성 방송인", "군 복무자"처럼 일반 명사로 바꾼다. 이 문장은 이름이 아니라 비판 이유로 비슷한 사례를 찾는 데 쓰인다.
- 발언을 그대로 옮기지 않는다. 비판의 대상, 방식, 이유를 요약한다.
- `sourceText`에 없는 사실을 보태지 않는다. 비판 이유가 여러 개면 가장 중심이 되는 하나를 쓴다.

출력은 설명 없이 아래 JSON 하나만 낸다.

```json
{"reason": "<비판 이유 한 문장>"}
```
