# Groq 전환 후 전사·사례 회수·정상 대조·검증 점검

2026-10-16 · minwook · 원본 2개 재전사, 발췌 5쌍과 합성 정상 대조 6개를 1회씩 비교했다.

## 범위와 입력 보존

v4(약 627초)·v6(약 900초)를 현재 Python `stt.transcribe`로 전사했다. 기존과 같은 음성 추출, 600초 분할, 언어·프롬프트 힌트 없음, `verbose_json` 구간 시간 요청이다. 기존 OpenAI 대본은 이전 실험의 읽기 전용 스냅샷을 사용했다. 새 대본으로 DB나 기존 리포트를 덮어쓰지 않았다.

후속 비교는 현재 텍스트 후보 엔진과 v7 사전을 사용했다. 자동 키 분류·출처 관계 추가 기능은 OFF, 시각·OCR·최종 카드 병합은 범위 밖이다. 따라서 새 영상 ID의 전체 분석 결과가 아니다. 각 조건 1회여서 결과의 반복 안정성·모델 교체의 순수 인과 효과를 입증하지 않는다. 전사 모델 교체로 문구뿐 아니라 구간 분할과 배치 문맥도 달라졌다.

설정 확인 중 로컬 Python `.env`에 `STT_MODEL=whisper-large-v3ㄹ` 오타가 있어 `whisper-large-v3`로 바로잡았다. 키 값은 출력하거나 수정하지 않았다. `.env`는 Git 제외이며, 이미 실행 중인 서버는 설정을 다시 읽으려면 재시작해야 한다. 이 점검에서 서버를 재시작하지 않았다.

## 1. 전사 오류

| 항목 | 기존 OpenAI Whisper | 새 Groq Whisper Large v3 |
|---|---|---|
| v4 핵심 질문 | “오늘 팬티 묻은 색깔?” | “오늘 팬티는 무슨 색깔?” |
| v4 줄임말 | “오팸무” | “오펜무”: 자막의 “오팬무”와 여전히 다름 |
| v4 저장 구간 수 | 393 | 254 |
| v4 정확히 `와.` 또는 `아.`만 있는 구간 | 132 | 0 |
| v6 저장 구간 수 | 164 | 159 |

새 v4 대본에는 질문 뒤의 답변·집에서의 생활 습관·보여주겠다는 제안 등 기존에 감탄사로 반복되던 부분의 대화가 복원됐다. 위 표의 감탄사 수는 두 문자열의 정확 일치 집계이며 전체 오류율이 아니다. 다른 감탄사나 반복은 이 집계에 포함되지 않는다. 새 전사에도 줄임말 및 의심스러운 용어가 남아 있어 전체 오류 해결로 보지 않는다.

영상에 표시된 자막은 핵심 질문의 비교 근거다. 별도 청취자가 작성한 완전한 정답 전사는 없으며, WER·방언 정확도는 계산하지 않았다. 새 타임스탬프의 음수·역전·0길이는 0개이고 600초 이후 구간에도 원본 시간 오프셋이 붙었다. 실제 발음에 대한 정밀 정렬 오차는 미측정이다.

## 2. 관련 사례의 실제 회수

사전 파일 SHA256은 `b538b9fd80e3db6e55068552f6b028c57d11ba646520f324a626031f77b85e36`으로 이전 비교와 같다. 39개 예시와 6개 공통 기준을 로드했다. 선택은 현재 기본인 최대 3개·전체 6000자·예시당 3000자이며 어휘 기반 검색이다.

- **v4 속옷 질문:** 옛/새 대본 모두 선택된 사건 예시 0개다. 성적 사생활 질문과 관련된 `leemiju-mijupichu#s1-sexual`, `kimwonhun-nego#s1-sexual`은 사전에 있지만 이 발췌에서는 회수되지 않았다.
- **v6 죽음 표현:** 옛/새 대본 모두 사건 예시 0개다. 이 표현을 책임 비판과 구별하는 직접적인 사례 경계도 충분하지 않다.
- **v6 집단 전체 표현:** 옛/새 대본 모두 `jurure-gunbokmu#s1-dismissal`, `caracula-doryeochagi#s1-privacy`, `leegyeongsil-ieje#s1-sexual`이 선택됐다. 관련 집단 일반화 사례를 제대로 참조했다고 해석할 수 없다.

예시 0개여도 공통 기준 6개는 제공됐다. 사전 연결이 끊긴 문제와, 연결된 사전에서 적절한 예시를 선택하지 못하는 문제를 구분한다. 전사 변경만으로 회수 문제가 해결되지 않았다.

## 3. 정상 대조 보강과 실제 판단 비교

정상 대조는 자기 위생 경험, 자발적인 사적 경험, 성적 요구에 대한 비판적 인용, 특정 관계자의 행동 비판, 사망 후 책임 확인의 한계, 피해자 상황 설명의 6개로 보강했다. 관련 예시 ID와 함께 `pipeline-input.json.normalContrastProposals` 및 `summary.json`에 저장했다. 모두 합성 초안이며 사람이 승인한 정답이나 실제 사건 관측이 아니다. 정식 사전에는 승격하지 않았다.

| 실제 발췌 | 기존 전사 경고 수 | Groq 전사 경고 수 | 확인된 차이 |
|---|---:|---:|---|
| v4 위생·비데 대화 | 1 | 0 | 새 대본 후보 2개는 검증에서 PASS. 양쪽 전체 상태는 PARTIAL |
| v4 속옷 질문 | 1 | 1 | 옛 경고의 배설물 연상이 사라지고 실제 속옷 질문·보여주기 제안으로 근거가 달라짐. 양쪽 PARTIAL |
| v6 성적 가해의 비판적 서술 | 3 | 0 | 새 대본은 후보 없이 SUCCESS. 옛 대본은 성적 표현 경고 3개·PARTIAL |
| v6 죽음 표현 주변 | 1 | 0 | 죽음 표현 후보는 양쪽 모두 계약 탈락. 옛 대본의 경고 1개는 다른 집단 비판 문장 |
| v6 집단 전체 표현 주변 | 0 | 0 | 원래 전체 진영 표현을 대표하는 후보가 유지되지 않음. 양쪽 PARTIAL |

경고 수 감소를 정확도 개선으로 등치하지 않는다. 실제 영상 발췌는 독립 정답 승인이 없고, 특히 PARTIAL의 0개는 정상 통과가 아니다.

합성 정상 대조는 4개가 SUCCESS·경고 0개였고, 자발적 사적 경험·사망 후 책임 확인 2개는 FAILED·경고 0개였다. 실패 2개를 정상 통과로 집계하지 않았다.

## 4. 검증 단계 탈락과 쟁점 이동

### 정상 대조의 JSON 계약 실패

실패한 정상 대조 2개는 모두 검토한 ID와 빈 후보 목록을 반환했으나 `truncated`가 `null`이었다. 현재 `validDiscovery`는 이 Boolean을 필수로 요구하므로 해당 응답 전체를 채택하지 않았다. 내용 판단에서 논란으로 판정한 실패가 아니다. 원본 응답은 수정하지 않았고 자동으로 false를 넣지도 않았다.

### 죽음 표현의 대상 연결 실패

새 대본의 “비겁한 죽음으로 도망친 작자”는 발견됐고 모델의 초기·복구 응답 모두 REVIEW_REQUIRED였다. 그러나 `target=박원순`, `targetMention=작자`를 반환하면서 `targetRelation=EXPLICIT`로 표기했다. 현재 계약은 원문 지칭과 식별한 대상명이 다르면 CONTEXTUAL 연결을 요구하므로 초기·복구 모두 `TARGET_MENTION_RELATION`으로 탈락했다. 기존 전사에서는 복구 후 `TARGET_EVIDENCE_REQUIRED`가 남았다.

이는 전사를 다시 하면 없어지는 문제가 아니다. 모델의 대상 연결 표기와 검증 계약 사이의 불일치다. 이 후보가 실제 검토 대상인지에 대한 사람 판단과, JSON·근거 계약 통과 여부는 별도다. 검증을 느슨하게 하거나 모델 출력을 자동 교정하지 않았다.

### 집단 전체 주장에서 다른 평가로 후보 중심 이동

새 전사에는 “좌파진영이 모두”, “좌파진영 전체로부터”가 있다. 발견 응답은 이 구간들을 근거로 포함하면서 대표 anchor를 뒤의 “페미니스트를 자처한 자들” 문장으로 잡았다. 검증은 그 대표 문장을 해당 사건 행위자의 책임 비판으로 읽어 PASS했다. 원래 전체 진영으로 확장하는 표현이 후보의 중심으로 유지되지 않았다는 점을 확인했다. 모델이 해당 원문을 전혀 읽지 않았다는 뜻은 아니다.

속옷 질문의 중첩 배치에도 이미 처리한 anchor가 다음 배치의 primary 밖에 제안되는 `PROPOSAL_ANCHOR_NOT_REVIEWED`가 있었다. 다만 같은 핵심 후보가 다른 배치에서 살아 최종 경고는 발행됐다. 이 탈락을 쟁점 전체의 미탐으로 계산하지 않는다.
