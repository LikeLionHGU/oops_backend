### 3. 범위와 결론

후속 [참고 전달·경계 점검](#record-4)에서99 검증에는 구체 사례0개,114/116에는 청중 평가 사례가 전달됐음을 확인했다. 이미 승인·완료한 정상 경계 비교도 재확인했으므로 아래의 ‘먼저 확인’은 완료됐고 같은 시험을 반복하지 않는다.

- **최근 승인 양성에서 확인된 실패:** 99의 검증 판단 불일치. 후보 탐색 강화만으로 해결되는 문제가 아니다.
- **과거 추가 관찰에서 확인된 탐색 변동:** 메뉴 후보의 생성/미생성. 관련 사례가 검색 기록에 있는 상태에서도 발생했다. 현재 필수 탐지 목표로 재승격하지 않는다.
- **확인한 피식대학 실행의 현재 필수 두 흐름:** 후보와 최종 카드 존재. 이것을 다른 영상 전체나 최신48의 모든 입력에 일반화하지 않는다.
- **이번 범위의 후처리 누락:** 승인 양성의 REVIEW가 최종 단계에서 사라진 사례는 확인하지 못했다. 코드 전체에 누락이 없다는 증명은 아니다.

96/99/114/116은 같은 영상 계열이고,71/72/76/112/113도 같은 영상이다. 버전·OCR 설정 등이 다른 개발 기록이며 독립 표본이나 동결된 반복 평가가 아니다. 재현율/정확도 수치로 집계하지 않는다. 합성 승인 R04/R08의 검증 전용 실험도 전체 영상 후보 탐색 성공으로 계산하지 않았다.

다음 우선순위는 사례집의 **상품 설명 속 직접적인 대상 평가와 정상 독려의 적용 경계**를 점검하는 것이다. 99의 PASS 이유와114/116의 REVIEW 이유를 사례 구조에 대조해, 관련 참고가 실제 검증에 선택됐는지와 의미가 충분히 전달됐는지 먼저 확인한다. 메뉴 관련 보강은 역사적 탐색 변동 관찰로 분리한다. 공용 프롬프트 추가나 새 유료 반복은 이번 결과만으로 진행하지 않는다.

### 3. 현재 사례 구조에서 전달되는 것

원장 `context-units/mimiminu-audience-devaluation.json`과 관계 자료는 다음을 보존한다.

- 상황: 플래너 사용 기간·구성 이유 설명.
- 평가 대상: 현재 시청자의 공부량.
- 평가/연결: 상품 설명 중 현재 시청자의 공부량을 낮추는 평가를 한 대목. 이 제공 문맥의 사용자 승인 경계이며 모든 독려·설명·강한 말투로 확대하지 않음.
- 근거: source 해시, 원문48~52, 상황/평가 역할.
- 현재 정상 대조: “한 달 분량으로 나눴어요. 공부량에 맞게 쓰고 부족하면 다음 권을 이어 쓰면 됩니다.” 1개.

빌더는 위 내용을 runtime의 flow/criticismHypotheses/missingContext/normalContrasts와 relationProfile에 전달한다. 현재 runtime에도 이 필드들이 실제 존재한다. 정상 대조가 빌드에서 통째로 유실된 상태는 아니다.

### 4. 남아 있는 구조적 한계

1. **가장 가까운 승인 정상 대조의 연결 부족.** 기존 정상 비교에 쓴 ‘시청자를 직접 지칭하고 공부 부족을 언급하지만 낮추지 않고 재시작을 권함’은 평가 자료에 있으나 현재 이 runtime 사례의 normalContrasts에는 없다. 현재 대조는 제품 안내1개뿐이다. 승인 자료·출처를 연결해 같은 사례 경계 자산으로 재사용할 여지가 있다.
2. **설명 일부가 결론 중심.** interpretation과 relation.evaluation은 ‘낮추는 직접 평가’라는 결론을 반복한다. 새 영상으로 확장할 때는 현재 청중에 대한 평가인지, 행동 조언인지, 인용인지와 실제 연결 근거를 구분하는 설명이 필요하다. 그러나 직접 지칭·공부량 부족·‘너무’ 자체를 자동 경고 조건으로 만들면 안 된다. 기존 승인 사례 하나로 모든 독려의 경계를 확정할 수 없다.
3. **같은 원본에 대한 개발 재사용.** 자기 사례를 참고한 재판정은 연결 확인에는 유효하지만 새로운 소재로 일반화된다는 증거는 아니다. humanVerified=false·trainingUseAuthorized=false와 사용자 개발 판단 승인은 서로 다른 축이며 자동 승격하지 않는다.

### 결론·다음 작업
