## 검색-누락-진단과-메타데이터-정제

## 검색 누락 진단과 메타데이터 정제 — 2026-10-23

### 범위

운영43참고를 바꾸지 않고 기존44참고 개발 미리보기와 저장 개발 질의6조건을 검사했다. 같은 자료를 시안 작성에도 사용했으므로 독립 평가·최종 탐지 정확도 검증이 아니다. 외부 호출은0회다.

### 누락 단계

테스트 전용 `ContextRetrievalGapAudit`는 개발자가 지정한 기대 참고 ID의 위치를 다음으로 구분한다. 기대 참고는 검색 목표이며 PASS/REVIEW 정답이 아니다.

| 단계 | 뜻 |
| --- | --- |
| ASSET_ABSENT | 지정 참고가 검사한 사전에 없음 |
| CHANNEL_EXCLUDED | 참고가 해당 채널 대상이 아님 |
| FAMILY_EXCLUDED | 설정한 사건 제외 목록에 포함 |
| NOT_RETRIEVED | 참고는 있으나 검색 후보 풀에 없음 |
| RETRIEVED_NOT_SELECTED | 후보 풀에는 있으나 최종 선택에서 빠짐 |
| SELECTED | 최종 선택에 포함 |

`RETRIEVED_NOT_SELECTED`만으로 순위 때문이라고 단정하지 않는다. 크기 예산·균형 선택 등도 별도 확인해야 한다. 의미상 맞는 참고가 무엇인지 자동 승인하는 도구도 아니다.

### 저장 개발 입력에서 확인한 병목

| 입력 | 기대 참고의 후보 순위 | 최종 선택 | 마지막 슬롯 교체 시 크기 충족 |
| --- | --- | --- | --- |
| 뜻풀이 답변 | 4 | 미선택 | 충족 |
| 직접 사적 요청 | 4 | 미선택 | 충족 |
| 정의 설명 | 4 | 미선택 | 충족 |
| 비판적 인용 | 1 | 선택 | 충족 |
| 요청 뒤 중단 | 4 | 미선택 | 충족 |
| 학원 피해 경험 전달 | 1 | 기존 피해 경험 참고 선택 | 충족 |

네 미선택 조건은 참고 부재나 후보 회수 누락이 아니다. 세 슬롯 바깥인4위이며, 마지막 참고를 교체한 조합도 예시3000·전체6000code point를 충족한다. 크기 상한을 늘리는 것이 이 자료의 필수 해결책은 아니다.

### 검색 메타데이터 정제 비교

기존 경계 참고의 검색 설명에는 성적 사생활 질문·뜻풀이와 일반적인 과거 모욕·학원 회고 단서가 함께 있었다. 학원 피해 경험은 별도 참고가 이미 있으므로 다음처럼 검색 역할을 나누는 시안을 만들었다.

- 경계 참고: 사생활 질문의 뜻풀이·비판적 전달과 현재 답변 요청의 차이.
- 기존 피해 경험 참고: 과거 모욕을 들은 경험·반응과 현재 공격의 차이.

테스트가 임시 미리보기를 생성한다. 경계 참고의 retrievalView.text와 대응 SHA256만 바꾸며 원문·비교 경계·판단 자료·라벨·ID·참고 개수는 유지한다. 정제 문구는 개발자 초안이지 새로운 검수 승인이나 운영 반영이 아니다.

정제만으로는 네 조건의4위·미선택이 바뀌지 않았다. 비판적 인용 순위는1→2지만 선택은 유지됐고, 피해 경험 참고도 유지됐다. 검색 설명을 짧게 정리했다는 이유로 회수 성능이 좋아졌다고 주장하지 않는다.

기존 마지막 한 슬롯 보완 시안과 조합하면 원본/정제 양쪽 모두 기대 참고6개가 선택된다. 이 결과 역시 개발 검색 평가이며 최종 판단 정확도는 측정하지 않았다.

### 다음 판단

이 자료에서는 설명 정제보다 **비교 경계 참고가 최종 선택에서 밀리는 문제**가 직접 병목이다. 그렇다고 정제 문구를 되돌려 잡다한 키워드를 더 붙이거나 공용 프롬프트를 늘리지는 않는다.

운영 연결 전에는 다른 소재에서 검수한 비교 경계가 있는 참고를 확보하고, 경계 보완이 필요한 경우·불필요한 경우를 고정해야 한다. 이전 합성6조건의 무관 참고 미추가는 안전장치 검사일 뿐 충분한 일반화 증거가 아니다. 새 운영 플래그나 유료 시험은 추가하지 않았다.

### 검증

전체 Java1186개 통과(실패/오류/skip0), Python tools167개 통과·기존6skip·36subtests통과. 사전 빌드 --verify 통과, 운영 runtime SHA256 `6f330d24cd557197f66a9d8b0f9f7bc80c02dfea7bd83da61f526c08a2f94d1b` 유지. 서버 재시작·배포·유료 호출은 하지 않았다.

## 맥락-적합성-검색-보완-시안

## 맥락 적합성 검색 보완 시안 — 2026-10-23

> 아래는 시안 개발 이력이다. 후속으로 실제 선택 경로에 연결했다. 현재 구현 범위·실호출·한계는 [운영 연결 후속](#record-4)을 따른다. 새44번째 경계 참고는 여전히 개발 미리보기다.

### 범위

기존 미리보기에서 새 경계 참고는 관련 질의 5개 모두의 후보 풀에 있었지만 최종 선택은 1/5였다. 같은 주제의 사례들이 비교 경계를 담은 참고를 밀어냈다. 이번에는 판단 기준·사례·후보 풀·최대3개·문자 예산을 고정하고 **마지막 한 슬롯의 경계 보완**만 오프라인으로 시험했다.

`ContextFitRankingPreview`와 그 테스트는 src/test에만 존재한다. 운영 검색·설정에는 연결하지 않았고 새 OFF 플래그도 만들지 않았다. LLM·임베딩 호출은 없다.

### 선택 방식

1. 현재 원문에서 뜻풀이·전달·직접 요청을 시사하는 제한적 표현 단서를 확인한다.
2. 기존 검색 후보 풀에서 주제 프로필 또는 라우팅에 이미 부합한 참고만 사용한다. ‘뜻’ 같은 단어로 새 주제 후보를 만들지 않는다.
3. 고정된 검색 설명에 전달/설명과 요청의 비교 경계가 있는지 확인한다. 가변 판단 설명·정답·사례 ID는 점수에 쓰지 않는다.
4. 이미 경계가 포함돼 있으면 유지한다. 없으면 선두 참고를 보존하고 최대 한 슬롯만 교체한다.
5. 예시3000·전체6000 code point·최대3개를 충족하지 못하면 기존 선택을 유지한다.

이는 한국어 표현 패턴의 제한적 휴리스틱이다. 의미를 이해하는 범용 관계 분류나 안전 판정이 아니며, 부정·반어·화자 입장을 확정하지 않는다. 탐색 단서를 관측 사실이나 위험 판정으로 쓰면 안 된다.

### 무료 비교

같은 44참고 미리보기와 저장 개발 입력6조건을 사용했다. 실제 운영 사전은43개 그대로다.

| 입력 | 기존 | 한 슬롯 보완 |
| --- | --- | --- |
| R01-166 뜻풀이 | 경계 미선택 | 경계 포함 |
| R04 직접 요청 | 경계 미선택 | 경계 포함 |
| R05 정의 | 경계 미선택 | 경계 포함 |
| R06 비판적 인용 | 경계 포함 | 유지 |
| R08 요청 후 중단 | 경계 미선택 | 경계 포함 |
| 피해 경험 인용 | 해당 참고 포함 | 유지 |

관련5조건의 경계 선택이1/5→5/5로 바뀌었다. 네 조건은 기존 첫 두 참고를 유지하고 마지막 하나만 바꿨다. 선택 payload는4047, 피해 경험 인용은3047 code point다. **판정 정확도·오탐 감소·실영상 일반화는 측정하지 않았다.** 작성에 재사용한 개발 자료이므로 독립 평가가 아니다.

합성 테스트로 단서 없음·주제 일치 없음·후보 풀 없음·크기 불충족·최대0에서 강제 보완하지 않는 것, 최대 한 슬롯 변경, 반복 결정성, 먼 문맥의 전달 단서 결합 방지를 확인했다. 이 소수 대조로 범용성을 보장하지 않는다.

private 보고서: `datasets/controversy/experiments/speech-act-mechanism-20261023-verified/context-fit-audit.json`. 새 저장 경로를 `CONTEXT_FIT_AUDIT_OUTPUT`으로 지정해 `ContextFitRankingPreviewTest`를 재실행한다.

시안의 합성/실자료 검색 검사4개를 포함한 전체 Java 회귀1167개 통과(실패/오류/skip0), Python tools167개 통과·선택적6개skip을 확인했다. 운영43참고의 빌드 해시 검증도 유지됐다. 시각 분기 지침 수정은 이 검색 비교의 입력이나 점수에 사용하지 않았다.

### 운영 연결 전

다른 소재의 실제 발언·인용·정의, 비슷하지만 관계가 다른 정상 대조, 관련 참고가 없는 경우를 추가 검수해야 한다. 단서를 검수된 검색 asset 메타데이터로 옮길지도 결정해야 한다. 사례별 예외를 공용 프롬프트에 붙이지 않는다. 유료 최종 판단 비교는 별도 승인 후 수행하며, 검색 성공을 탐지 성공으로 보고하지 않는다.

### 후속: 후보 주변 문맥과 첫 참고 보존

운영 연결 전 시안 자체의 두 경계를 보강했다. 운영 소스·사전·판단 프롬프트는 그대로다.

- 후보 검증용 호출은 focus를 받을 수 있다. focus ID를 허용 원문에서 다시 찾고, 해당 원문 기준 앞뒤15초 이내 segment 시작점만 단서 검사에 사용한다. 운영 검색의 근접 창 규칙과 맞췄으며 의미 관계가 입증됐다는 뜻은 아니다.
- 호출자가 전달한 focus의 텍스트·시간은 단서의 근거로 쓰지 않는다. 원문에 없는 focus뿐이면 전체 원문으로 되돌아가지 않고 `FOCUS_NOT_IN_RAW`로 유지한다.
- 후보가 없는 탐색 단계는 기존 전체 입력 방식을 유지한다. 전체 입력의 단서가 모든 후보에 적절하다고 보장하지는 않는다.
- 상한1에 기존 참고가 있으면 교체하지 않는다. 빈 슬롯에는 적합한 참고를 넣을 수 있다. 따라서 ‘첫 참고 보존’과 ‘마지막 한 슬롯 보완’의 충돌을 없앴다.

무료 합성 회귀3개 추가: 먼 단서 차단/가까운 단서 허용, focus 텍스트 주입·미등록 ID 차단, 단일 슬롯 보존·빈 슬롯 보완. 기존 저장 개발 입력6조건의 미리보기 검사도 통과했다. 정답 라벨을 새로 승인하거나 최종 카드 정확도를 측정한 작업은 아니다.

다음 연결 조건은 고정 검색 메타데이터의 비교 경계 표현을 검수하고, 다른 소재에서 후보 주변 검색과 전체 검색을 비교하는 것이다. 현재 regex 단서는 검색 보조 시안이며 범용 맥락 이해기로 승격하지 않는다.

### 다른 소재 검색 점검

같은44참고 미리보기에 작성한 합성 검색 질의6개를 넣었다. 사용자 승인 판정셋이나 독립 실영상 평가는 아니다. 각 질의 전체를 focus로 사용했으므로 근접 창 효과 비교가 아니라 소재 간 참고 추가 여부 검사다.

무료 회귀는 기존 선택 동일성·첫 참고 보존·후보 풀 안에서만 추가·예시3000/전체6000code point 제한을 확인한다. 운영 연결은 보류하며, 다음은 구체적 대상·발언·전달 관계가 있는 다른 소재 자료에서 기존 참고 회수와 새 경계 참고의 필요성을 각각 확인하는 것이다.

## 맥락검색-승격판정-기준선-20261023

## 맥락 검색 승격 판정·기준선 — 2026-10-23

> 이전 보류 판단 기록이다. 이때1~5단계를 전체 완료로 처리한 것은 정정했다. 현재 구현·검증은 [운영 연결 후속](#record-4)을 따른다.99/109는 각각39/41참고 당시의 과거 관측이며 현재43참고에서도 실패한다고 단정할 수 없다.

### 결론

### 이전 자료 해석 정정

99번 당시 사전은39개,109번은41개였다. 이후110·111번은42개 사전으로 카드0개였다. 따라서99/109 과거 오류가 현재43개 사전에도 계속 존재한다고 단정한 이전 설명은 부정확했다. 과거 응답에 현재 소스·사전 버전을 소급 적용하지 않는다.

후보 진단의 실제 참고 선택은 analyzer 최상위의 빈 `contextSelections`가 아니라 `candidatePipeline.contextSelections`에 들어 있었다. 후보별 선택과 사전 버전을 함께 확인한다.

### 채택 판단 변경의 이유

앞선 ‘다른 소재3조건에서 추가 회수>0’ 문턱은 이미 올바른 참고가 회수되는 조건에서도 추가 이득을 요구했다. 이를 통과하지 못했다는 이유로 필요한 운영 연결까지 끝내지 않은 것은 적절하지 않았다.

새로 일반화 성공을 주장하는 대신, 확인된 회수 누락4조건의 보완과 이미 회수되는3조건의 보존을 각각 검사했다. 개발44참고에서는 경계 참고 회수1/5→5/5, 기존 피해 경험 참고 유지가 실제 `select` 연결 후 재현됐다. 운영43참고의3문맥에서는 참고·JSON 입력 내용이 유지됐다.

이 제한된 근거로 **범위가 제한된 검색 보완 경로를 연결**했다. 새44번째 경계 묶음의 운영 데이터 승격은 하지 않았다. 현재43참고에서 성능이 새로 좋아졌다고 주장하지 않는다. 검색 경로 연결과 사례 자산 승격은 별개다.

### 운영 경로와 안전장치

- 전달/정의/요청 단서는 참고 선택용 휴리스틱이며 판단 규칙이 아니다.

### 대표 메커니즘

기존 승인 자료만 재사용했다. 실제 저장 전사 2조건(R01-166 뜻풀이, 피해 경험 인용)과 합성 4조건(R04 직접 요청, R05 정의, R06 비판적 인용, R08 요청 후 중단)이다. 승인 범위는 해당 문맥의 개발 판단이다. 구조화한 설명은 개발자 초안이며 새 사용자 승인이나 독립 검수로 승격하지 않았다.

- 원문·기존 라벨·승인 범위는 `evidence.json`에만 보관한다.
- 작성한 상황·관계·성립/불충분 조건·정상 경계는 `references.json`에 보관한다.
- 서로 다른 소재의 관계 대조도 포함한다. 모든 연결이 같은 문장을 한 조건만 바꾼 최소 편집 쌍은 아니다.
- 다섯 사례를 서로 경쟁하는 개별 참고로 전송하지 않고, 비교 경계를 포함한 짧은 메커니즘 묶음 하나를 생성했다.
- 압축 참고의 관계 3문장과 경계 2문장에는 각각 지원 사례 ID를 연결한다. 이는 출처 연결 검사이며 의미적 참·거짓의 자동 검증은 아니다.
- 기존 승인 평가 자료를 사례 자산 개발에 재사용했으므로 해당 사례·원본 그룹을 향후 독립 평가로 보고하면 안 된다. `development-use-registry.json`에 표시했으며 기존 평가 실행기에 강제로 제외시키는 연결은 이번 범위에 포함하지 않았다.
