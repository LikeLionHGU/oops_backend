## 전체 저장 전사 재분석 114·115 — 2026-10-23

### 실행 범위

사용자가 새 합계 추정$1.00과 전체 저장 전사·선택 사례집의 OpenAI 전송을 승인했다. 각 원본에서1회만 실행했고,114 완료 확인 후15초를 기다린 뒤115를 시작했다. 새 STT·영상/음성 전송·전체 OCR·프레임 검토는 하지 않는 로컬 전사 재사용 경로다. `gpt-6-luna`, 현재43참고를 사용했다.

### 범위·비용·기록

## 후보-탐색-변동-115-117-점검

## 후보 탐색 변동 점검 — 115·117

2026-10-23. 저장 결과와 코드 변경 내역만 비교했다. 추가 모델 호출·프롬프트 수정·사전 변경은 없다.

### 확인한 차이

| 항목 | 115 | 117 |
| --- | --- | --- |
| 원본 / 전사 | 109 / 439구간 | 동일 |
| 후보 탐색 / 탐색 완료 구간 | 26회 / 439구간 | 동일 |
| 후보 / 검증 | 0건 / 0회 | 1건 / 1회 |
| 최종 카드 | 0 | 0 |
| 검증 실패·보류·예산 제외·후보 잘림·복구 | 모두0 | 모두0 |

변동 지점은 `stt-index-234`, 444.869~455.284초다. “저 친구 원래 저러고 다녀요? … 평생 저러는 모습이 아니셔가지고. 아우 무섭네.” 흐름에 대해 115는 NO_CANDIDATE, 117은 TARGET_TREATMENT 후보를 만들고 검증에서 PASS였다. 117의 이유는 낯선 모습에 대한 놀람·가벼운 반응으로 읽히며 구체적으로 낮추거나 조롱하는 표현이 확인되지 않는다는 것이다. 이는 모델의 판단 기록이지 새 사람 정답 승인은 아니다.

### 입력·검색·설정 비교

- 전체 저장 전사 JSON은 순서·원문·시간까지 동일하다.
- 기록된 모델은 모두 `gpt-6-luna`, 요청 개정은 모두 `2026-10-23-candidate-repair-contract-48`이다.
- 공통 탐색 `discovery-1`~`discovery-26`의 참고 선택 진단을 requestKey로 맞춰 비교한 결과 **26/26 완전 동일**했다. 선택 사례 ID뿐 아니라 검색 방식·크기·구조화 검색·경계 보완 기록까지 비교했다.
- 상위 guidelineReference와 별도 caseRetrieval, mechanismRouting 기록도 동일하다. 해당 두 실행의 사례집 해시는 `776c8967b33f8986e03bd071f4969ee5b4f4fcce8be33659b19f3b08ad80ed99`다. 다른 과거 문서나 실행의 해시로 대체하지 않는다. 이 실행의 availableExampleCount는42다.
- 117에만 `unit-candidate-1` 검증용 참고 선택이 추가됐다. 구체 사례는0개, 공통6개 기준을 사용했다. 이는 후보 생성 이후의 처리이므로 탐색 차이의 선행 원인으로 볼 수 없다.
- 문맥 제한 분리 커밋 `cc57dd8`의 후보 엔진 변경은 partial/unresolved 기록과 안내 생성뿐이다. 이 변수들은 다음 탐색 요청 구성에 사용되지 않는다. 요청 생성·창 구성·후보 채택·검증·카드 병합 코드는 바꾸지 않았다.

따라서 **전사 변경·저장된 검색 선택 차이·후보 한도 초과·검증 실패로 사라진 후보**는 이번 차이의 설명이 아니다. 차이는 탐색 모델의 후보 제안 단계에서 드러난다.

### 확정할 수 없는 부분

탐색 요청/응답 전문과 실제 provider 설정 전체는 두 결과 스냅샷에 없다. `ReviewRequestTraceStore`도 초기 텍스트 **검증** 요청만 보관하며 메모리/1시간 만료이므로 탐색 응답을 소급 복원하는 장치가 아니다. 전사·검색 진단이 같다는 사실을 실제 HTTP 본문 바이트 완전 동일의 증거로 확대하지 않는다.

`OpenAiClient.requestBody` 코드는 Luna reasoning effort가 none일 때 temperature0.1을 넣는다. 당시 실제 환경변수와 provider 내부 버전·처리 조건은 이 기록만으로 확정할 수 없다. 모델 응답 변동이 유력한 설명이지만, 두 번의 결과만으로 원인·발생률을 입증하지 않는다. temperature를 조정하는 새 실험도 이번에는 하지 않았다.

개별 segment 진단은 최대400개만 저장해 439개 전체 상태 목록은 없다. 두 스냅샷 모두 analyzer.truncated=true이며, 이는 candidatePipeline.truncated=false·exploredSegments=439와 구분한다. 이번 비교 지점234는 저장 범위 안이다. 마지막39구간을 개별 진단으로 모두 확인했다고 주장하지 않는다.

### 판정과 다음 기준

이번 한 쌍은 **정상일 수 있는 후보를 더 넓게 탐색한 뒤 검증에서 제외한 최종 결과 동일 사례**다. 중간 후보 수 일치를 목표로 맞출 필요는 없다. 현재 근거만으로 탐색 프롬프트나 사전을 수정하지 않는다.
