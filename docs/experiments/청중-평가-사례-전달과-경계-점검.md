## 2. 이 비교는 일부 이미 끝난 작업이다

10/22의 [99번 참고 보강6회 비교](99번-사전-보강-전후-비교.md)를 다시 확인했다. 동일한 재구성 후보·원문·판단 지침에서 참고 부분만 바꿨고, 보강 전 PASS/PASS/REVIEW, 보강 후 REVIEW3회였다. 이 결과는 현재 사례가 전달됐을 때 판단에 영향을 줄 수 있다는 제한적 개발 증거다. 원래99의 가설을 복원한 실험은 아니며 독립 정확도 시험도 아니다.

더 가까운 정상 경계도 [기존16회 비교](정상-경계-사전-보강-전후-비교.md)에 이미 있다. results.json을 직접 집계해 아래와 같음을 확인했다.

| 승인 조건 | 보강 전2회 | 보강 후2회 |
| --- | --- | --- |
| 상품 분량·사용 기간 안내 — 합성 PASS | PASS2 | PASS2 |
| 계획 실천을 돕는 재시작 독려 — 합성 PASS | PASS2 | PASS2 |

정상 두 합성 대사의 현재 저장 상태는 `USER_APPROVED_DEVELOPMENT_BOUNDARIES`, `humanApproved=true`, `expectedDecision=PASS`다. 미승인 초안으로 되돌려 다시 승인을 받거나 동일한 비교를 재실행할 이유가 없다. 기존 비용 수치를 이번 신규 사용량으로 세지 않는다.

## 3. 현재 사례 구조에서 전달되는 것

원장 `context-units/mimiminu-audience-devaluation.json`과 관계 자료는 다음을 보존한다.

- 상황: 플래너 사용 기간·구성 이유 설명.
- 평가 대상: 현재 시청자의 공부량.
- 평가/연결: 상품 설명 중 현재 시청자의 공부량을 낮추는 평가를 한 대목. 이 제공 문맥의 사용자 승인 경계이며 모든 독려·설명·강한 말투로 확대하지 않음.
- 근거: source 해시, 원문48~52, 상황/평가 역할.
- 현재 정상 대조: “한 달 분량으로 나눴어요. 공부량에 맞게 쓰고 부족하면 다음 권을 이어 쓰면 됩니다.” 1개.

빌더는 위 내용을 runtime의 flow/criticismHypotheses/missingContext/normalContrasts와 relationProfile에 전달한다. 현재 runtime에도 이 필드들이 실제 존재한다. 정상 대조가 빌드에서 통째로 유실된 상태는 아니다.

## 4. 남아 있는 구조적 한계

1. **가장 가까운 승인 정상 대조의 연결 부족.** 기존 정상 비교에 쓴 ‘시청자를 직접 지칭하고 공부 부족을 언급하지만 낮추지 않고 재시작을 권함’은 평가 자료에 있으나 현재 이 runtime 사례의 normalContrasts에는 없다. 현재 대조는 제품 안내1개뿐이다. 승인 자료·출처를 연결해 같은 사례 경계 자산으로 재사용할 여지가 있다.
2. **설명 일부가 결론 중심.** interpretation과 relation.evaluation은 ‘낮추는 직접 평가’라는 결론을 반복한다. 새 영상으로 확장할 때는 현재 청중에 대한 평가인지, 행동 조언인지, 인용인지와 실제 연결 근거를 구분하는 설명이 필요하다. 그러나 직접 지칭·공부량 부족·‘너무’ 자체를 자동 경고 조건으로 만들면 안 된다. 기존 승인 사례 하나로 모든 독려의 경계를 확정할 수 없다.
3. **같은 원본에 대한 개발 재사용.** 자기 사례를 참고한 재판정은 연결 확인에는 유효하지만 새로운 소재로 일반화된다는 증거는 아니다. humanVerified=false·trainingUseAuthorized=false와 사용자 개발 판단 승인은 서로 다른 축이며 자동 승격하지 않는다.

## 결론·다음 작업

현재 근거는 **사례가 미연결되어 실패 중**이라는 진단을 지지하지 않는다. 현재 사례가114/116 검증에 선택됐고 승인된 검토 판단이 나왔으며, 가까운 정상 대조의 과탐 비교도 이미 소규모로 끝났다. 같은 유료 시험이나 공용 프롬프트 수정을 반복할 단계가 아니다.

다음 보강은 기존 승인 정상 안내·독려를 provenance와 함께 현재 사례에 연결하는 범위로 제한하는 것이 적절하다. 새 필수 판정 규칙·새 정답을 만드는 작업은 아니다. 연결 시에는 기존 검색 회수·입력 크기·빌드 재현성을 무료 확인하고 실제 새 영상에서 같은 메커니즘의 실패가 나타날 때만 추가 모델 비교를 고려한다. 이번 점검에서는 연결/빌드/운영 변경을 하지 않았다.
