### 목적과 조건

앞선5개 롱폼 중101·103·104·105는 OCR 결과를 받지 못했다. 사용자는 메모리 제약을 고려해 앞으로 한 편씩 확인하기로 했고, 우선101번 원본 제미나이 아카데미(16:19)만 새106으로 재측정했다. 다른 영상을 이어서 등록하지 않는다.

사용자는 이번 새 추정 상한 $2.00과 음성의 Groq·추출 텍스트/필요 프레임의 OpenAI 전송을 승인했다. 서비스 분석1회만이며, 실제 청구액 보장 상한이 아니다. 기존 $10 승인을 재사용하지 않는다.

이것은 OCR의 인과 효과만 분리한 OFF/ON 시험이 아니다. 서버 재시작·실행 시점·모델 응답 변동도 다르므로 카드 변화가 OCR 때문이라고 단정하지 않는다. 원음·장면 직접 검수나 새 정답 확정도 아니다.

### 요청 전 확인

- 처음 Python health가 지연됐지만 재확인에서 Spring/Python UP·STT/OCR 가용true를 확인하고 등록했다.
- 새 서버 PID는 Spring19084/Python19087이다. 기존 Python과 다른 새 프로세스였고 초기 관측 CPU는 거의 유휴였다. Spring의 `analysis-` 스레드는 아직 없었다.
- 이력105개에서 PROCESSING은0개였다. 오래된 PENDING13개는 남아 있지만 실제 실행 확인과 구별했고 취소·삭제하지 않았다. 대표84번 상태 API도 분석 미시작이라고 응답했다.

### 완료 후 Python 잔류 추론 관측

Spring에서 COMPLETED가 된 뒤에도 Python CPU96~100%가 관측됐다. 1초간 읽기 전용 프로세스 샘플에서 `paddle::AnalysisPredictor::ZeroCopyRun`, `paddle::framework::NaiveExecutor::Run`, CPU convolution 실행 스택을 확인했다. 따라서 단순히 메모리만 유지된 상태가 아니라 Paddle 추론이 실제 계속 실행 중이었다. 이 서버의 OCR 경로에서 Paddle을 사용하며, 다른 새 분석 요청은 없었다. 스택에 job ID가 붙어 있는 것은 아니므로 요청 단위 완전 추적과는 구별한다.

그 뒤 CPU0.1%의 유휴 관측으로 바뀌었지만 RSS는 약7.34GiB가 남았다. 모델 캐시·네이티브 할당자·누수 중 무엇인지는 아직 판별하지 않았다. 프로세스를 종료하거나 강제로 메모리를 비우지 않았고, 다른 영상도 등록하지 않았다.

1. 한 편씩 처리하는 원칙은 유지한다. 하지만 Spring 완료 뒤15초만 기다리는 것으로 Python OCR 작업 종료까지 보장되지는 않는다.

## OCR 작업 격리·종료·로컬 대기시간 개선

현재 설정은 [로컬 OCR 제한 해제·단계 측정](#record-4)을 따른다. 아래 local20분/Spring25분 OCR 설명은 당시 이력이며 현재 local OCR은 별도 클라이언트에서 전체 시간 제한 없이 기다린다. 연결 종료·취소 정리는 유지한다.

2026-10-22 · minwook · 추가 유료 호출0회

### 근거와 범위

[106·107 단독 재측정](#record-1)에서도 약10분 OCR 단계 뒤 결과 수신 실패가 반복됐다. Spring이 완료된 뒤 Python에서 Paddle 추론이 계속됐고 RSS는 약7.4GiB까지 증가했다. 시간 제한과 작업 종료 전달의 구조적 문제는 코드로 확인했지만, 각 실행의 상세 HTTP 예외를 확보하지 않아 과거 실패 원인·메모리 누수를 확정하지 않는다.

이번에는 같은 조건의 유료 반복 대신 실행 경로를 수정했다. 프롬프트·사례집·STT 모델·프레임 간격·프레임 수 상한·원본PTS·OCR 텍스트 필터·영역 좌표·추적 계약은 변경하지 않았다. 새 실영상의 OCR 성공·속도·최대 RSS 감소는 아직 미검증이다.

### 구현

#### 1. OCR 요청별 프로세스

`app/ocr_jobs.py`가 요청마다 `python -m app.ocr_worker`를 시작하고, 다운로드·프레임 추출·Paddle 초기화·인식을 그 안에서 수행한다. 완료 응답은 작업 전용 임시 JSON으로 받는다. 모델 로그와 결과 JSON을 stdout에 섞지 않으며, 대량 이미지나 모델 객체를 부모 프로세스로 보내지 않는다.

- 종료·실패·시간 초과·HTTP 연결 종료·ASGI 작업 취소의 모든 경로에서 자식 프로세스를 회수한다.
- macOS/Linux에서는 작업용 새 세션 전체를 종료해 실행 중인 ffmpeg 등 하위 프로세스도 남기지 않는다. Windows 분기는 직접 자식 종료만 제공하며 하위 트리 보장은 이번 검증 범위가 아니다.
- 회수 이후에만 작업 임시 디렉터리를 지운다. 원본 업로드와 외부에 보존한 프레임은 임의 삭제하지 않는다. 실패 중 일부 저장된 프레임도 정상 완료 산출물처럼 사용하지 않는다.
- 실패를 빈 `items`의 정상 결과로 바꾸지 않는다. HTTP504 `OCR_TIMEOUT`, HTTP503 `OCR_BUSY`/`OCR_WORKER_FAILED`, 연결 종료499를 구분한다.
- 프로세스당 OCR 동시 실행은1개다. 두 번째 요청은503으로 거절하며 몰래 대기열에 쌓지 않는다. 이 제한은 **uvicorn 프로세스별**이므로 로컬에서는 기본 단일 worker를 사용한다. 여러 `--workers`를 띄우면 전역1개 보장은 없다.

한 요청의 Paddle/native 할당이 다음 요청까지 같은 서버 프로세스에 계속 남는 것을 작업 프로세스 수명으로 끊는다. 단일 작업 중 RSS를 OS 하드 제한한 것은 아니며, 최대 메모리 개선 폭은 별도 실측해야 한다.

#### 2. OCR 메모리·관측

- health는 Paddle 모델을 초기화하지 않고 설치 의존성만 확인한다. `ocrAvailabilityCheck=DEPENDENCIES_ONLY_NOT_MODEL_READY`를 추가해 모델 로딩·작업 성공 보증과 구별한다.
- health의 `ocrBusy`는 현재 서버 프로세스의 OCR 슬롯 상태, `ocrJobIsolation`은 `SUBPROCESS_PER_JOB`이다. 모델 설치가 돼 있어도 가중치·네이티브 초기화 실패는 실제 작업에서 발생할 수 있다.
- 인식 배치는 `OCR_REC_BATCH_NUM=1`을 기본으로 둔다. 실제 설치 PaddleOCR2.9.1과 [공식 소스의 rec_batch_num 옵션](https://raw.githubusercontent.com/PaddlePaddle/PaddleOCR/v2.9.1/tools/infer/utility.py)을 확인했다. 해당 옵션은 인식 묶음 크기이며 프레임을 버리거나 탐지 기준을 바꾸는 설정이 아니다. 수치·성능 동등성이 완전히 보장된다는 뜻은 아니다.
- `[ocr-job] started/reaped/deadline/disconnected`에 pid·경과 시간을 기록하고, 인식 중에는25성공 프레임마다 `[ocr-progress]`를 남긴다. 원문·API 키를 새 로그에 추가하지 않는다.

#### 3. 대기시간 정렬

| 실행 설정 | Python OCR 전체 작업 제한 | Spring 분석 서버 읽기 제한 |
|---|---:|---:|
| 기본 | 540초(9분) | 기존10분 유지 |
| 명시적 local | 1200초(20분) | 25분 |

Python 제한에는 미디어 다운로드·모델 시작·프레임 처리까지 포함한다. `OCR_TIMEOUT_SEC`으로1~3600초 범위에서 명시 재정의할 수 있지만 Spring 제한보다 여유 있게 짧아야 한다. 제한을 늘리기만 한 것이 아니라 연결 종료 감지와 프로세스 종료도 함께 구현했다. ASGI 이벤트 루프가 감지한 연결 종료를 기준으로 하며 프록시가 즉시 연결 종료를 전달하지 않는 환경까지 보장하지는 않는다.

Spring은 HTTP504의 `OCR_TIMEOUT` 설명을 유지한다. 전송 예외의 원인 체인에서 연결 실패는 `WORKER_CONNECTION_FAILED`, 응답 시간 초과는 `WORKER_READ_TIMEOUT`으로 구별한다. 리포트의 기존 상위 경고 코드 `OCR_UNAVAILABLE`은 호환성을 위해 유지하며 구체적 이유는 메시지에 포함한다.

발언은40/40탐색이지만 문맥 제한1배치·검증 문맥 제한6후보로 PARTIAL이며 report의 미확인6구간 표시도 보존했다. 일부 구간 상세에서 NOT_RETURNED와 PASS 결정이 함께 남아 후보별 PASS와 구간 집계가 완전히 일치하지 않는 점을 확인했다. 이번 시험에서 원본 진단을 덮어쓰거나 집계 코드를 수정하지 않았고, 이를 새 형식 오류6건으로 해석하지 않는다.

모델은 gpt-6-luna, 발언 개정46이다. API5종·승인 계획·비교 JSON은 Git 제외 `experiments/v1-speech-first-20261023-kutVZF/`에 보존했다. 비용·시간·탐지율의 일반 보장이나 독립 영상 정확도 시험은 아니다. 다음 점검은 STT에 존재하는 메뉴 흐름의 후보 미생성과, 구간 상태/후보 판정 집계의 차이를 분리해서 확인하는 것이다.

### 이번 구현 범위

STT 후보 탐색에 `visualCandidates`를 추가했다. 텍스트만으로 위험을 증명하지 못해도 화면을 봐야 해석이 달라지는 비교·평가를 별도로 제안한다. 국가명·지역명·지시어 자체는 선별 이유가 아니다. 기존 텍스트 후보와 별도이며 배치 제안 합계 12개, 전체 검증 후보 기본 24개에 함께 포함된다. 이미지 후보는 추가로 영상당 최대 3개다.

```text
STT 시간순 읽기 → 텍스트 후보 → 기존 텍스트 근거 검증
              └→ 화면 확인 필요 후보
                    → Python /scene-frames에서 원본 JPEG 추출
                    → STT 문맥 + 실제 이미지 + 원본 프레임 시간
                    → 화면 관찰 / 발언 연결 / 대조 해석 / 판정
                    → 원문·프레임 ID·출력 계약 검증 → 카드 또는 미확인
```

Spring `CandidateReviewEngine` → `VisualContextReviewer` → `AnalysisServerClient.sceneFrames` → Python `scene_frames.sample` → `OpenAiClient.completeWithImagesAsJson` 순서다. 이미지 경로 문자열을 보여주는 대신 JPEG를 Base64로 실제 전달한다. 현재 설정 모델을 유지하며 공식 GPT-6 Luna 문서는 이미지 입력 지원, 오디오·비디오 입력 미지원, 파인튜닝 미지원을 명시한다. 계정·프록시에서 실제 동작하는지는 별도 실영상 검증이 필요하다. [공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-6-luna), [이미지 입력 문서](https://developers.openai.com/api/docs/guides/images-vision).

### 프레임·비용·보안 한도

- 업로드 원본만 지원한다. YouTube 링크는 매 후보마다 재다운로드하지 않도록 이번 경로에서 명시적으로 미확인 처리한다.
- anchor 중간 시간은 유지하고, 탐색 후보의 원문 인용에 연결된 다른 발언 시점에서 최대 2장을 우선 선택한다. anchor와 먼 인용부터 선택하되 이미 선택한 시간과 2초 미만으로 겹치는 시점은 제외한다. 남은 슬롯만 anchor -2초/+2초로 보충하고 영상 범위 안으로 제한한다. 최대 3장은 유지한다. 인용 없는 전체 문맥이나 OCR 간판을 임의로 시각 근거로 선택하지 않는다.
- Python 저장소 `videos/` 아래 실파일만 허용하며 기존 경로 검증을 재사용한다. 임의 URL·외부 파일·OCR framePath를 이미지 입력으로 쓰지 않는다.
- ffmpeg 최대 20초/프레임, 최대 768×768 안의 JPEG, 프레임당 512,000바이트다. 실제 `showinfo pts_time`을 반환하고 요청 시간과 1초 넘게 다르면 실패한다. OCR 설치 여부와 무관하다. 임시 작업 디렉터리는 정리하며 새 프레임 파일을 영구 저장하지 않는다.
- 모델에는 low detail로 최대 3장을 보낸다. 작은 자막·미세 표정·짧은 장면 전환에는 부족할 수 있다. 영상당 기본 이미지 검증 최대 3요청이며 기존 클라이언트의 전송 재시도는 별도다. 입력 이미지/토큰·시간·비용이 늘 수 있으며 정확한 비용 절감이나 상한 금액은 주장하지 않는다.
- 기본 `visual-context-enabled=true`, `VISUAL_CONTEXT_ENABLED=false`로 끌 수 있다. 꺼진 상태에서도 화면 필요 후보를 정상 PASS로 바꾸지 않는다. 후보 예산 초과·영상 길이 미확인·이미지 누락·시간/출력/인용 실패는 부분 검토로 남긴다.
- 장면에는 개인정보가 있을 수 있다. 이 기능은 해당 영상의 일부 화면도 기존 외부 AI 공급자에게 전송한다. 서비스의 사용자 안내·동의·보관 정책에 이를 포함해야 한다. 진단에는 이미지 바이트·저장 경로·키·공급자 원문 응답을 남기지 않는다.

### 관찰과 해석의 분리

#### 개정 19: 지칭어·해석 대상 분리와 화면 의존성 확인

탐색의 동일 요청 안에서 모든 primaryIds에 대해 위험 후보 여부와 화면 의존성 여부를 별도로 확인하도록 지시한다. 국가명·지역명 단독 규칙이나 특정 벤치마크 문장 하드코딩은 없다. 별도의 독립 장면 탐색기나 결정적인 라우팅 알고리즘을 추가한 것은 아니므로 모델이 화면 필요 후보를 누락할 가능성은 남는다.

검증 응답의 `targetMention`은 TARGET 원문에 실제 존재하는 지칭어, `target`은 문맥상 해석 대상이다. 둘이 다르면 CONTEXTUAL 관계와 다른 발언 ID의 CONTEXT 인용, 구체적인 targetReason을 요구한다. EXPLICIT 관계에 서로 다른 이름을 반환하거나 원문에 없는 지칭어·연결 인용을 반환하면 실패한다. 기존 직접 지칭 응답의 null targetMention은 target을 원문 지칭어로 사용하는 호환 경로다. PASS/UNCERTAIN에는 targetMention도 null이어야 한다.

원문 일치·허용 문맥·유형·대조 해석 검증은 유지한다. 이 계약은 모델의 대상 해석이 의미적으로 맞다는 보증이 아니다. 연결이 불명확하면 UNCERTAIN을 반환하도록 요구한다. 공개 카드/DB 스키마는 유지하며 원문 근거와 해석 대상은 기존 evidence/target/targetReason으로 전달한다. targetMention 별도 DB 저장이나 독립 페르소나 모델은 추가하지 않았다.

프레임 선택은 인용 시간 기반 휴리스틱이다. 장면 전환 검출·영상 전체 분석·시각적 중복 검출은 아직 구현하지 않았다. 이미지 수/후보 한도/요청 구조는 유지하지만 새로 선별되는 후보가 늘면 총비용은 늘 수 있다.

`observations(frameId, description)`는 제공된 화면에서 보이는 내용, `connectionReason`은 발언과의 연결 해석이다. 실제 프레임 ID·길이·원문 인용·anchor·대상·대조 해석을 서버에서 검증한다. 이 검증은 모델의 화면 설명이나 비판 해석이 사실이라는 의미적 보증은 아니다.

한적한 거리와 국가 언급이 함께 있어도 자동 차별 판정하지 않는다. 위치 질문·중립 비교와 구별되는 평가 연결이 필요하다. 억양·추가 장면이 필수라면 UNCERTAIN이다. 모델이 묘사한 관찰은 프레임 ID와 함께 진단에 남기고 카드 이유에도 선택적 장면 검증임을 표시한다. 기존 카드 유형·DB는 유지한다. 공개 coverage의 `sceneAnalyzed`는 전체 장면 분석 구현을 뜻하므로 이 선택적 보충만으로 true로 바꾸지 않았다.

### 실패 진단

기존 `VERIFICATION_FAILED` 상태 아래 `failureCode`를 추가했다. 요청/HTTP/연결/한도/JSON 파싱/거부/중단, 후보 누락·중복·예상 외 후보, 출력 필드 조합·대상 근거·원문 인용·게시 계약 실패를 구분한다. 누락 응답과 구조 검증 실패를 정상 판단으로 바꾸지 않는다. ID 20의 원래 모델 응답은 보관되지 않았으므로 새로운 코드를 과거 실행에 적용해 정확한 원인을 복원할 수 없다.

### 아직 하지 않은 것

음성 억양·웃음·효과음, 독립적인 장면 후보 탐색, 영상 전체 시청, 포즈·행동 분석, 댓글 수집·사례 검색·모델 학습은 이번 구현 범위가 아니다. 텍스트 탐색이 이미지 후보를 놓치면 여전히 화면 검증은 실행되지 않는다. 이후 장면 전환 표본 기반 탐색이 이 빈틈을 보완할 수 있지만 별도의 비용/미탐 평가가 필요하다.

다음 실험에서는 중국 발언에 화면 필요 후보가 생기는지, 실제 프레임과 발언 연결이 적절한지, 정상 국가·지역 비교에 과탐지가 생기는지를 확인한다. 중국 발언 카드가 무조건 나오는 것을 정답 조건으로 고정하지 않는다. 텍스트 전용/이미지 보충을 같은 STT와 사람 라벨로 비교한다.

Spring과 Python 둘 다 새 코드를 실행하도록 재시작해야 한다. 이번 작업은 실제 서버 재시작·유료 분석·배포를 수행하지 않았다.
