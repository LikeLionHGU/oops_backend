## D 검증 수정 — 개정 35

최종 GRAPHIC_METAPHOR 판정은 표현 자체의 검토가 가능하므로 탐색 axis가 TARGET_TREATMENT여도
target이 없다는 이유만으로 거절하지 않는다. 다른 대상 평가 유형의 대상·인용·관계 검증은 유지한다.
코드가 원문 특정 단어나 피식대학 이름을 보고 자동 경고하거나 축을 변경하지 않는다.
탐색/검증 프롬프트에도 신체 훼손 비유와 사람을 공격하는 발언을 구분하도록 명시했다.

가상 입력에서 잘못된 탐색 축의 GRAPHIC_METAPHOR가 대상 생성이나 복구 호출 없이 통과하는지,
MOCKERY/BELITTLEMENT/STRONG_NEGATIVE_REVIEW의 대상 누락은 여전히 거절되는지 검증했다.
실제 D가 다음 모델 응답에서도 같은 category를 반환하고 발행되는지는 아직 미측정이다.

## C 검증 범위와 사례 해석

공통 판단/검증 기준에서 가게·서비스·메뉴·상품도 평가 대상임을 명시한다. 식당 메뉴·서비스의
모욕·조롱을 검토할 때 지역/주민 비하까지 요구하지 않는다. 맛·가격·특색 불만, 단일 메뉴 안내,
정상적인 선택 조건 설명은 검토 근거 자체가 아니다. 특정 문장을 무조건 경고하도록 만들지 않는다.

## 비판 가설 입력/빌드

incident-2 statements의 선택 필드 criticismHypotheses에 구조화된 객체를 저장한다.
필드와 검증은 tools/schemas/incident-2.schema.json 및 tools/criticism_hypotheses.py를 따른다.

- text: 비판 해석
- basis: USER_REVIEWED_DEVELOPMENT_EXPECTATION / SOURCE_INTERPRETATION / AUDIENCE_REACTION_INTERPRETATION
- status: DRAFT. 사람 의미 검수/학습 승격 아님
- evidenceRefs: 해당 발언 카드의 실제 segmentId만 참조
- sourceRefs: 해당 카드 evidence.sources의 실제 sourceId만 참조
- supportingReactionIds: 실제 CONTENT/CRITICISM_SUPPORT/EXACT_POINT 또는 SCENE_OR_FLOW 반응만 참조
- requiredCurrentEvidence / normalContrast / missingContext: 적용 조건·정상 해석·자료 한계

기사 해석 basis는 sourceRefs, 댓글 해석 basis는 supportingReactionIds를 요구한다. 개발 기대 기준은
출처 없는 여론·원음 근거로 위장하지 않고 별도 basis로 보존한다. 가짜 댓글 ID·누락 출처·반론·
사건 전체 감정·사후 대응 참조를 내용 비판의 근거로 만들어 넣지 않는다.

빌드 흐름:

```text
statement.criticismHypotheses
→ 사건 재조립의 카드별 계획
→ context dictionary의 interpretationMaterial.criticismHypotheses
→ runtime example.context.criticismHypotheses (짧은 문자열 배열)
→ 기존 Java 사례 선택/프롬프트 전달
```

출력은 출처 성격 + 비판 해석 + 적용 근거 + 정상 대조 + 미확인 내용을 결정적으로 조립한다.
최대 16개/항목 350코드포인트 계약을 유지하며 초과는 빌드에서 거절한다. 임의로 자르거나 모델로
내용을 추측 요약하지 않는다. 신규 필드를 저장만 하고 빌드가 무시하는 경로를 제거했다.
사건 추가 도구·왕복 마이그레이션에서도 보존하고 양쪽에 다른 사본이 있으면 충돌로 거절한다.
신규 필드가 없는 기존 사건은 이전 컴파일 내용 그대로 유지한다.
