# 승인 검토 대상의 후보 누락 점검

2026-10-23. 기존 저장 JSON의 후보·구간 판정·최종 카드를 비교했다. 새 유료 호출, 프롬프트·사전 변경, 새 정답 승격은 없다. 과거 B/C/D 필수 정답셋 시험을 재개한 것이 아니다.

## 1. 최근 명시 승인 사례: 시청자 평가

사용자 승인 파일 `evaluation/mimiminu-second-five-user-approved-20261021.json`은96번의 “여러분들 공부를 너무 안 하셔.”를 제공 문맥의 REVIEW_REQUIRED로 기록한다. HIGH 강도·영상 전체·다른 독려 발언까지 승인한 것은 아니다.

| 실행 | 해당 후보 | 검증 판단 | 최종 해당 카드 | 요청 개정 |
| --- | --- | --- | --- | --- |
| 96 | 있음, anchor50 | REVIEW_REQUIRED | 있음 | 45 |
| 99 | 있음, anchor50 | PASS | 없음 | 46 |
| 114 | 있음, anchor50 | REVIEW_REQUIRED | 있음 | 48 |
| 116 | 있음, anchor50 | REVIEW_REQUIRED | 있음 | 48 |

**확인한 네 실행에서는 후보 누락이 없다.** 99번은 상품 구성 설명 속 과장된 지적으로 해석해 검증에서 PASS로 제외됐다. 사람 승인과 어긋난 단계는 후보 탐색이 아니라 정상 해석과 직접적인 낮춤 평가를 가르는 검증 판단이다. 이후114·116에서 카드는 돌아왔지만 버전이 달라 개선의 단일 원인을 입증하지 않는다.

99의 같은 실행에는 다른 anchor16/17/24의 VERIFICATION_FAILED3건이 있다. 이것을 anchor50의 탈락 원인으로 합쳐서는 안 된다. anchor50에는 실제 PASS 응답이 있고, 당시 NOT_RETURNED 표시는 별도의 문맥 제한 집계 문제였다. 후처리가 REVIEW 카드를 삭제한 사례가 아니다.

## 2. 피식대학: 필요한 흐름과 과거 추가 관찰을 분리

사용자가 최종적으로 지역 선택지 비하와 신체 훼손 비유 두 쟁점이면 충분하다고 정한 방향을 유지한다. 메뉴를 다시 필수 합격 조건으로 올리지 않는다. 아래는 발언이 어느 단계에서 사라졌는지 추적하는 역사적 관찰이다.

| 실행 | 지역 선택지 anchor12 | 신체 비유 anchor37 | 메뉴 anchor34 |
| --- | --- | --- | --- |
| 71 | 후보→REVIEW→카드 | 후보→REVIEW→카드 | NO_CANDIDATE, 카드 없음 |
| 72 | 후보→REVIEW→카드 | 후보→REVIEW→카드 | 후보→REVIEW→카드 |
| 76 | 후보→REVIEW→카드 | 후보→REVIEW→카드에 포함 | 후보→REVIEW→카드 |
| 112 | 후보→REVIEW→카드 | 후보→REVIEW→병합 카드 | NO_CANDIDATE, 카드 없음 |
| 113 | 후보→REVIEW→카드 | 후보→REVIEW→카드 | NO_CANDIDATE, 카드 없음 |

신체 비유는 anchor36의 선행 표현도 함께 검증될 수 있어 대표 카드 문장·시작 시각이 anchor37과 반드시 같지 않다. 76·112에서도 신체 비유 카드와 관련 근거가 있으므로 대표 문장만 비교해 후처리 누락으로 세지 않았다. 과거 신체 카드 중복은 별도 문제이며 위 표를 카드 개수의 정확도 지표로 사용하지 않는다.

71·72는 저장 전사 전체가 같고 요청 개정44·상위 사전 해시도 같았다. 두 실행에서 메뉴가 들어 있는 탐색 참고 선택 기록 모두 `pisik-yeongyang#u-menu`를 포함했다. 112·113의 탐색 참고 선택 기록에도 이 사례가 있다. 따라서 메뉴는 **사례가 검색 기록에 있어도 후보 제안으로 이어지지 않은 관찰**이다. 단순히 사전 항목 부재나 검색 실패라고 단정할 수 없다.

각 실행의 invalidProposals/verificationFailed/budgetSkipped/truncatedBatches는0이고 전체40구간이 탐색됐다. 메뉴 anchor34에 실제 PASS/UNCERTAIN 응답이 있는 것이 아니라 후보가 없다. 이를 검증 PASS나 병합 누락으로 해석하면 안 된다. 다만 탐색 요청/응답 전문은 없어 해당 창을 읽고 어떤 이유로 제안하지 않았는지까지 소급 확정할 수 없다.

## 3. 범위와 결론

- **최근 승인 양성에서 확인된 실패:** 99의 검증 판단 불일치. 후보 탐색 강화만으로 해결되는 문제가 아니다.
- **과거 추가 관찰에서 확인된 탐색 변동:** 메뉴 후보의 생성/미생성. 관련 사례가 검색 기록에 있는 상태에서도 발생했다. 현재 필수 탐지 목표로 재승격하지 않는다.
- **확인한 피식대학 실행의 현재 필수 두 흐름:** 후보와 최종 카드 존재. 이것을 다른 영상 전체나 최신48의 모든 입력에 일반화하지 않는다.
- **이번 범위의 후처리 누락:** 승인 양성의 REVIEW가 최종 단계에서 사라진 사례는 확인하지 못했다. 코드 전체에 누락이 없다는 증명은 아니다.

96/99/114/116은 같은 영상 계열이고,71/72/76/112/113도 같은 영상이다. 버전·OCR 설정 등이 다른 개발 기록이며 독립 표본이나 동결된 반복 평가가 아니다. 재현율/정확도 수치로 집계하지 않는다. 합성 승인 R04/R08의 검증 전용 실험도 전체 영상 후보 탐색 성공으로 계산하지 않았다.

다음 우선순위는 사례집의 **상품 설명 속 직접적인 대상 평가와 정상 독려의 적용 경계**를 점검하는 것이다. 99의 PASS 이유와114/116의 REVIEW 이유를 사례 구조에 대조해, 관련 참고가 실제 검증에 선택됐는지와 의미가 충분히 전달됐는지 먼저 확인한다. 메뉴 관련 보강은 역사적 탐색 변동 관찰로 분리한다. 공용 프롬프트 추가나 새 유료 반복은 이번 결과만으로 진행하지 않는다.
