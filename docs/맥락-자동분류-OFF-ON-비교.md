## 결론

자동분류 호출·검색 키 전달은 실제로 동작했다. 그러나 **이번 표본에서 추가 탐지 이득은 확인하지 못했다.**
지역 흐름과 신체 훼손 비유는 OFF/ON 모두2/2 탐지했고, 66 공방 경고도 양쪽2/2 남았다.
기본 OFF를 유지한다. 분류기 추가 자체를 정확도 개선으로 간주하지 않는다.

## 무엇을 비교했나

- 동일한 v6 사전39예시·검색 키3개를 양쪽에 사용했다. v4→v6 변경 효과는 이번 비교 대상이 아니다.
- 지역36줄/2배치, 신체 비유15줄/1배치, 제품 리뷰19줄/1배치, 66 공방26줄/2배치의 저장 STT 발췌다.
- 각 조건 OFF/ON 2회씩, 총16회 엔진 실행. 두 번째 반복은 ON부터 실행해 순서를 바꿨다.
- `gpt-6-luna`, reasoning none, temperature0.1, JSON mode. 라우팅 출력1024/그 외8000 completion tokens 상한이다.
- 원문 ID·시간·텍스트를 보존하고 후보는 모델이 직접 발견했다. 이전 실험의 고정 후보/기대 판정을 전송하지 않았다.
- 공통 POLICY·관계39·validator·후보 상한24·근거 상한0·같은 원문 창을 유지했다.
- 프레임·음성·OCR·검색·사실대조·DB 저장·report fusion은 실행하지 않았다.
  아래 findings는 **엔진 검증 통과 결과, 최종 리포트 병합 전**이다. 같은 쟁점의 중복 결과를 독립 적중으로 세지 않는다.
- 66의 영상 수준 정상 피드백은 비교 참고이며, 발췌 텍스트의 정보 충분성까지 승인한 gold로 확대하지 않는다.
- 같은 사건을 사전에 포함한 개발 시험이다. 미공개 사건 일반화 성능/독립 holdout 성능은 측정하지 않았다.

미판정과 PASS를 구별하고, 이 차이를 바로 분류기의 효과로 주장하지 않는다.

## 분류→검색 연결에서 확인한 실제 병목

분류 호출12회 중6회 ROUTED,6회 EMPTY, 응답 형식 오류0이다.
지역은 local-life-devaluation, 신체 비유 구간은 service-choice-devaluation/graphic-body-metaphor를 선택했다.
제품·66공방은 EMPTY여서 기존 어휘 검색으로 돌아갔다. 이 분류는 위험 판정이나 통계적 분류 정확도가 아니다.

**대응하는12개 발견 요청의 system과 input JSON은 OFF/ON 모두 동일했다.**
선택 사례 ID/순서도12/12 동일했다. 따라서 발견 결과의 형식 오류·후보 개수 차이는
이 표본에서 검색 자료가 개선된 효과라고 설명할 수 없다. 동일 요청의 실행 변동을 포함한다.

특히 신체 비유 발견 배치의 경로가 다음과 같았다.

```text
분류: 메뉴 평가 + 신체 훼손 비유
    ↓ 두 키의 사례가 검색 순위에 올라옴
발견 단계의 사건 family 다양성 우선 선택
    ↓ 같은 피식대학 family의 두 번째 사례를 뒤로 미룸
최종 참고: 메뉴 단위 + 다른 사건의 당근 사례
    ↓ 신체 비유 단위는 발견 단계 참고에서 빠짐
후보별 선택: 신체 비유 단위 + 메뉴 단위로 회복
```

`ReviewGuidelineLibrary.select`의 발견 단계2-pass family 다양성이 `ContextExampleSelector`의
routed 우선순위보다 뒤에서 다시 선택 순서를 바꾼다. 키가 맞아도 실제 payload에 들어간다는 보장이 없었다.
별도 합성 무료 재현에서 상위2개가 모두 routed인데도 `[routed A, non-routed C]`가 선택되는 것을 확인했다.
후보별 경로는 같은 family 제약을 적용하지 않아 `[A,B]`가 된다. 재현 테스트는 현 제한의 기록이지 바람직한 계약이 아니다.

지역 반문 후보에는 분류기가 주로 햄버거 대체 흐름의 ID를 붙여, 반문 후보의 근거 ID와 안 겹치면 키를 넘기지 않았다.
후보 간 오염 방지 경계가 작동한 것이지만, 지역 반문까지 포괄하는 키 설명/범위도 별도 검토 대상이다.
66은 대응 파일럿 키가 없고 어휘 검색에서 당근 사례가 유지돼, 자동분류를 추가해도 경고를 줄이지 못했다.

## 후속: 검색 우선순위 수정 — 무료 회귀

`ReviewGuidelineLibrary.select`의 선택 순서를 다음처럼 바꿨다.

1. routed 사례 묶음에서 먼저 선택한다. 발견 단계의 사건 다양성도 이 묶음 안에서만 우선 적용한다.
2. 같은 사건의 남은 routed 사례까지 검토한 뒤 비일치 어휘 후보 묶음으로 넘어간다.
3. 남은 슬롯에는 기존 어휘 후보를 채운다. 후보별 참고 선택의 interleaving도 각 묶음 안에서 유지한다.

지역명·사건명·특정 키를 하드코딩하지 않는다. 키가 없거나 미지 키뿐이면 routed 묶음이 비어
기존 어휘 검색 순서/payload를 유지한다. 최대2예시·예시3000/전체6000 codepoints·family 제외·채널 조건은 그대로다.
큰 routed 사례를 통째로 제외하더라도 작은 관련 사례/어휘 후보 선택을 계속하며, 예시를 잘라 끼워 넣지 않는다.
분류가 틀리면 잘못된 참고가 우선될 위험은 남으므로 분류를 판정으로 바꾸지 않고 기본OFF도 유지한다.
