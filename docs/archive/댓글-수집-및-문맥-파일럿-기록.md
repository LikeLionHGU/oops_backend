## 1. 목적과 라벨의 의미

이미 알려진 논란의 발언·상황을 중심으로, 실제 부정적 반응이 무엇을 문제 삼았는지 연결한다. 이를 다른 게시 전 영상에서 찾아볼 수 있는 **발생 조건 가설**로 정리한다. 객관적 유죄·도덕적 잘못을 다수결로 확정하는 데이터셋이 아니다.

소수의 구체적 비판도 사례에 포함할 수 있다. 반론은 별도 참고자료이며 비판 취소·다수결·점수 차감에 사용하지 않는다. 확인자는 댓글의 진위·관련성·원문 연결·과도한 일반화를 점검한다. 단순 인물 욕설·사과 이후 여론·다른 사건 비판을 해당 발언의 근거로 승격하지 않는다. 댓글 작성자의 원본 시청 여부를 수집 조건으로 사용하지 않는다.

기존 [KOLD형 운영](../KOLD형-사례-데이터셋-운영.md)의 BLIND/합의 판단은 초기 설계다. 이번 수용 반응 파일럿은 **서로 다른 별도 스키마**이며 기존 원장의 REVIEW_REQUIRED/PASS 합의와 동일한 의미로 취급하지 않는다. 사람이 2명 동의하지 않았다는 이유로 관찰된 비판의 존재를 없애지 않는다. 구조 검증·사람 검수·사용권 확인·실제 탐지 성능 검증은 각각 별도 책임이다.

## 3. 사례 → 반응 → 범용 조건

### B: 시설 부재가 결핍·대체 생활로 연결되는 이야기

매장 부재 → 그곳 젊은 사람의 원하는 음식 → 현지 음식으로 대신함 → 못 먹기 때문에 조합한다는 흐름을 인용 ID로 연결했다. 중간의 가정식 추억·건강을 위한 선택 발언도 보존했다. 이 대화의 인과 연결을 읽기 위해 필요한 내용이지 비판을 취소하는 반론 투표가 아니다.

범용 가설: **시설·상품의 부재를 사람들의 결핍과 대체 생활 이야기로 연결하여 그 음식·선택·삶을 낮은 대체물로 받아들이게 하는 맥락**.

지역 음식의 기억·삶을 보잘것없게 만든다는 반응을 연결했지만, 이번 발췌에는 특정 롯데리아 대화를 직접 지목하는 반응이 없다. SCENE_OR_FLOW/INCIDENT_ONLY로 표시한다. 이것이 B의 알려진 논란 자체를 취소한다는 뜻은 아니며, **현재 연결한 댓글의 설명 범위가 좁다는 뜻**이다. 시설 부재나 취향만으로 패턴을 적용하지 않는다.

### C: 상품 평가에서 제공자의 선택·운영을 낮추는 흐름

특색 부족 → 메뉴에 의미 없음 → 주는 대로 먹기라는 연결과 이를 직접 묶어 비꼼으로 받아들인 반응을 연결했다. 맛 불만 자체보다 제공자 앞 평가·식별 가능한 사업장의 공개 평가를 문제 삼은 다른 반응도 보강 자료로 둔다.

범용 가설: **상품·서비스 평가가 제공자의 선택·노력·운영 자체를 무의미하게 취급하는 흐름으로 이어져 공개적 비꼼이나 하대로 받아들여지는 맥락**.

업주가 실제 들었는지, 상호가 노출됐는지, 식당 운영 사정이 무엇인지 등은 댓글 작성자의 주장과 영상에서 확인된 사실을 구분한다. 제공된 텍스트에 없으면 입력 사실로 만들지 않는다. 부정적인 메뉴 평가만으로 경고하는 규칙을 만들지 않았다.

### D: 감각 표현에 사람의 신체 훼손 이미지를 사용하는 비유

음식 맛 묘사와 사람의 살을 뜯는 이미지의 연결, 그리고 표현을 직접 지목한 기괴함·혐오감 반응을 기록했다.

범용 가설: **맛·냄새·질감 설명에 사람의 신체 훼손 이미지를 비유로 사용하여 불쾌감·무례함을 일으키는 표현**.

사람·가족·노인을 언급했다는 이유로 패턴을 적용하지 않는다. 실제 폭력 의도나 은어 의미도 추정하지 않는다. 가족 음식의 추억과 신체 훼손 비유를 구별한 비판 역시 직접 반응으로 보존한다.

세 패턴의 본문에는 사건명·지역명·브랜드명을 조건으로 넣지 않았다. 출처 사례에는 원문을 그대로 보존한다. 이름을 제거했다고 범용성이 증명되는 것은 아니므로 모두 `HYPOTHESIS_NOT_VALIDATED`다.

## 4. 반응 연결 범위

- EXACT_POINT: 해당 표현/연결을 직접 지목한 반응.
- SCENE_OR_FLOW: 음식 장면 등 연결 흐름에 대한 반응. 특정 문장을 직접 지목했다는 뜻은 아니다.
- INCIDENT_ONLY: 사건 전체에 대한 비판·해석. 직접 발언 근거로 승격하지 않는다.

세 범위는 작성자가 원본을 봤는지와 무관하다. `CRITICISM_SUPPORT`는 사례 보강 자료, `COUNTER_REFERENCE_ONLY`는 참고자료다. 비판 이유의 원문 연결을 AI가 추측해 넓히지 않도록 사람이 범위를 검토한다.

### 문맥을 충분히 넘기는 데 추가로 필요한 구분

기존 원문·연결 가설·댓글 주장 분리 위에 **대화 / 장면·자막 / 게시 시점·외부 상황 / 문화적 연상**의 문맥 층을 구분한다. 이는 4개 AI 에이전트나 호출을 추가한다는 뜻이 아니라 사례마다 필요한 입력을 명시하는 메타데이터다.

- 복무 제약 놀림과 당시 사고 때문에 생긴 반응은 같은 댓글에서 함께 나타나더라도 이유를 나누어 매핑한다. 한 댓글을 여러 카드에 연결할 수 있지만 출처 ID를 보존하고 독립 반응 수로 중복 집계하지 않는다.
- 외부 사건은 **과거 사례의 상황**이다. 새 영상에 그대로 붙이지 않고 예정 게시일과 그 시점에 확인된 사건을 별도로 확보한다. 정보가 없으면 필요한 문맥으로 표시한다.
- 기사에서 소개한 문구는 원영상 확인 전에는 전사가 아니다. 원클립이 뉴스에 일부 남아 있다면 해당 구간만 추출하고 기자 해설은 제외한다. 뉴스 편집으로 잘린 앞뒤는 누락으로 남긴다.
- 자막을 음성 발언으로 바꾸지 않는다. 편집자가 제공한 자막 파일 또는 확인한 원본 프레임으로 별도 증거를 작성한다. OCR·STT를 무조건 연결하는 구현은 아니다.
- 같은 사건의 카드·뉴스·재편집본은 같은 family로 유지한다. 싱글벙글 두 카드를 서로 다른 사건처럼 학습/평가로 나누지 않는다.

## 8. 워크맨 실제 반응과 범용 조건 가설 — 2026-10-09

### 실제 수집·매핑

사용자가 갱신한 `.env`를 **실행하지 않고** 수집기의 `--env-file .env`로 키 설정 하나만 읽었다. 명시한 파일은 기존 셸 환경변수보다 우선하므로 이전 키 export가 남아 있어도 갱신한 파일을 사용한다. 따옴표·주석 형태를 지원하며 중복 키·셸 치환·과도한 파일 크기·공개 권한·심볼릭 링크를 거절하고, 다른 설정은 가져오지 않는다. 오류에는 키/파일 내용/응답 본문을 출력하지 않는다. 추가 라이브러리가 필요 없다.

공개 웹 검색으로 워크맨 뉴스 유튜브 ID를 확보하지 못해 공식 `search.list`를 **2회**, 각 최대 후보 5개로 사용했다. 자동 검색 루프·페이지 순회·후보 전체 댓글 수집은 하지 않았다. 검색은 댓글 조회와 별도 요청/쿼터이며 [공식 문서](https://developers.google.com/youtube/v3/docs/search/list)를 기준으로 한다. 댓글 수집 권한이 학습·영구 보관 허가를 뜻하지 않는 기존 경계는 유지한다.

실제 반응에서 자막의 부자연스러운 용어 선택, 숫자·발음을 이어 읽었을 때의 연상을 지목한 이유를 확인했다. 제작진의 해명을 믿지 못하겠다는 반응은 **사후 해명 반응**으로 분리했다. 제작진의 의도·소속·과거 이력을 새 영상의 직접 탐지 근거로 일반화하지 않는다. 참고 의견은 통상 업무 의미·다른 언어유희라는 해석을 보존하지만 비판 취소·감점에 쓰지 않는다. `~노` 단독 탐지를 복구하지 않는다.

### 범용 기준을 쌓는 단위

`datasets/controversy/research/pattern-hypotheses.json`에 사건별 프롬프트 대신 **조건 가설과 사례 연결 원장**을 작성했다. 모든 항목은 `HYPOTHESIS_NOT_VALIDATED`이며 모델 프롬프트/판정 규칙으로 연결하지 않았다.

| 비교 축 | 봐야 할 연결 | 현재 사례 | 반드시 필요한 자료 |
|---|---|---|---|
| 대상 취급 | 평가·부재·제약 → 대상의 삶·선택을 낮추거나 놀리는 흐름 | 피식대학 B/C, 싱글벙글 복무 제약 | 대상·대화 순서·관련 장면·댓글 연결 범위 |
| 표현 이미지 | 감각 설명 → 구체적인 신체 훼손 이미지 | 피식대학 D | 실제 원문·비유 상황·표현 직접 반응 |
| 문화적 연상 | 통상 상황 → 표현 조합/배치 → 문화적 의미로 받아들임 | 워크맨 자막 | 원자막·작업 상황·조합을 지목한 반응·당시 의미 |
| 공개 상황 보조 조건 | 영상 내용 → 예정 게시 시점의 외부 사건 | 싱글벙글 공개 시점 | 예정 게시일·당시 확인된 사건·시점 반응 |

이는 모든 논란을 세 유형으로 확정 분류하거나 4개 에이전트를 추가한 것이 아니다. 현재 사례에서 비교할 수 있는 축만 적었다. 표현 자체·대상 취급·외부 상황을 분리하여 **왜 문제로 받아들여졌는지** 원문으로 추적하는 구조다.

사건명·특정 지역·브랜드가 같은지가 아니라 연결 구조를 비교한다. 피식대학 B/C는 같은 family라 독립 사건 2개로 세지 않는다. 대상 취급 축에 3카드가 연결되지만 **서로 다른 사건은 2개**뿐이며, 이것도 범용성 입증은 아니다. 나머지 축은 아직 단일 사건이다.
