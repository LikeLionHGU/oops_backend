# 논란 맥락 사전 — 구조 재설계 (3층 분리)

> 상태: 설계안 (ASSISTANT_DRAFT, 사람 미승인) · 작성 2026-10-13 · 브랜치 minwook
> 목적: 확장 전에 뼈대를 다시 잡는다. 아직 코드/스키마를 바꾸지 않았다. 이 문서는 목표 스키마의 합의용이며,
> 승인 후 별도 마이그레이션 단계에서 `drafts/cards.json` / `guidelines/plan.json` /
> `research/context-dictionary-plan.json` / 컴파일러(`tools/build_context_dictionary.py`,
> `tools/controversy_cards.py`)와 테스트를 함께 옮긴다.

## 1. 왜 바꾸나 — 현재 구조의 문제

현재 한 사건의 자료가 4개 파일에 쪼개져 서로를 참조한다.

```
drafts/cards.json                     사건·카드·evidence.sources 정의
guidelines/plan.json                  mechanism -> sourceCaseIds 역매핑
research/context-dictionary-plan.json card별 topicTags + documents(기사 발췌)
research/source-snapshots/*.txt       기사 발췌 원문(발췌만, sha256으로 무결성)
```

확인된 구체적 문제:

1. **네이밍이 "사건-카테고리" 혼종.** `pisik-B / pisik-C / pisik-D`에서 B/C/D는 사실
   카테고리(지역 생활 비하 / 리뷰 속 모욕 / 신체 훼손 비유)인데 사건 이름(pisik)에 붙어 있다.
   `pisik-B`가 "사건의 B번째 카드"인지 "지역비하 카테고리"인지 불명확하다.
2. **1 사건 : N 논란이 표현되지 않는다.** 영양 영상 하나에 지역비하·신체비유에 더해
   뉴스에서 확인된 발언(공무원 발령, 똥물 등)이 더 있는데, B/C/D 3칸에는 더 담을 자리가 없다.
3. **pisik 카드만 `evidence.sources`가 비어 있다.** sgbg/workman/chim 등은 기사 소스가 등록됐으나
   피식대학(개발 벤치마크)만 비어, 기사 발췌를 사전 documents에 넣으려다 컴파일러의
   `SOURCE_DOCUMENT_REFERENCE_REQUIRED`/`SOURCE_ORIGIN_MAPPING_INVALID`로 막혔다.
4. **벤치마크 클립과 사건 전체의 혼동.** 저장 STT 창(v1.mp4, 롯데리아 대화 22~61초)에는
   기사가 가장 강하게 지목한 발언("공무원 발령", "매일 이것만", "똥물")이 없다. 그런데 사건 라벨은
   영상 전체 기준이라, "B 미탐"이 모델 실패인지 클립 누락인지 구조가 구분하지 못한다.

## 2. 목표 — 3층 분리

사건(무엇이 올라왔나) / 발언근거(어느 발언이 문제인가) / 메커니즘(왜 논란이 되는가)을 분리한다.

```
① 사건 Incident        영상/업로드 1개 = 사건 1개
     │ 1:N
② 발언근거 Statement    사건 안의 개별 논란 발언 + 출처(기사 발췌 / STT 전사 구간)
     │ N:1 (각 발언근거가 하나의 메커니즘을 가리킴; 한 발언이 복수 메커니즘이면 발언근거를 나눔)
③ 메커니즘 Mechanism    사건을 가로질러 공유되는 "왜 논란인가"의 범용 조건
                       = 전이 학습/참조의 단위
```

- **전이의 단위는 메커니즘**이다. "지역 생활 비하(local-life-devaluation)"가 여러 사건에 쌓이면,
  그것이 다른 미공개 영상에서 재현되는지 평가한다. 사건명/지역명/브랜드명은 전이 조건에 넣지 않는다.
- **발언근거가 사건과 메커니즘을 잇는 다리**다. 각 발언근거는 (a) 어느 사건의 어느 구간/기사 발췌인지,
  (b) 어느 메커니즘인지, (c) 출처 종류(STT 전사 / 기사 서술 / 댓글 반응)를 명시한다.

## 3. 네이밍 규칙

| 층 | 규칙 | 예 |
|---|---|---|
| 사건 Incident | `{channel}-{topic}-{yyyymmdd}` (게시일 기준) | `pisik-yeongyang-20240511` |
| 메커니즘 Mechanism | 의미 기반 영문 kebab-case | `local-life-devaluation`, `graphic-body-metaphor` |
| 발언근거 Statement | `{incidentId}#s{seq}` | `pisik-yeongyang-20240511#s1` |

- `familyId`는 이미 `{channel}-{topic}-{date}` 형태이므로 **사건 id로 승격**한다(중복 개념 제거).
- `pisik-B / pisik-C / pisik-D`는 **폐기**한다. "B"는 발언근거의 `mechanismId: local-life-devaluation`로 표현한다.
- 메커니즘 id는 지금 쓰는 값(`local-life-devaluation`, `constraint-mockery`, `graphic-body-metaphor`,
  `symbolic-association`, `publication-context`, `group-inferiority`, `concern-dismissal`,
  `third-party-harm-dismissal`)을 그대로 승계한다. 네이밍이 이미 의미 기반이라 바꿀 필요 없다.

## 4. 발언근거(Statement) 스키마 (제안)

```jsonc
{
  "id": "pisik-yeongyang-20240511#s2",
  "incidentId": "pisik-yeongyang-20240511",
  "mechanismId": "local-life-devaluation",
  "sourceKind": "NEWS_BODY",            // STT_TRANSCRIPT | NEWS_BODY | AUDIENCE_REACTION
  "statementKind": "AUTHOR_INTERPRETATION", // 전사면 SOURCE_UTTERANCE, 기사면 AUTHOR_INTERPRETATION 등
  "snapshot": "research/source-snapshots/dailian-pisik-...-extract.txt",
  "sha256": "...",                      // 발췌만 저장, 무결성 보장
  "excerpt": "공무원인데 여기 발령 받으면 여기까지 하겠다 ...",
  "whyControversial": "그 지역에 사는 것 자체를 기피·형벌처럼 취급.", // 근거 한 줄
  "source": { "publisher": "데일리안", "url": "...", "publishedDate": "2024-05-25", "retrievedOn": "2026-10-13" },
  "transcriptWindowMs": null,           // STT 출처일 때만 [start,end]
  "evaluationUse": "REFERENCE_ONLY_SAME_FAMILY_EXCLUDED" // ① 참조만, ② 같은 family 평가 입력 금지
}
```

핵심 규칙(기존 원칙 승계):
- **① 참조용 / ② 평가 입력 금지 분리.** 기사·댓글(사후 자료)은 참조 사례(①)로 쓰되,
  같은 사건(family) 영상의 게시 전 탐지 평가(②)에는 입력·정답으로 넣지 않는다. family 제외로 강제.
- **발췌만 저장.** 기사 전문을 저장하지 않는다. 발췌 텍스트 파일 + sha256로 무결성만 보장한다
  (`SHORT_EXTRACT_NOT_FULL_ARTICLE`).
- **출처 종류를 섞지 않는다.** STT 전사(원발언)와 기사 서술(기자 해석)과 댓글(수용 반응)을
  `sourceKind`로 구분한다. 기사 서술을 원발언 전사로 승격하지 않는다.
- **벤치마크 클립 ≠ 사건.** 사건은 영상 전체이고, 평가에 쓰는 클립(v1.mp4)은 그 일부다.
  발언근거에 `transcriptWindowMs`가 있으면 "이 발언이 어느 클립에 포함되는지"를 추적할 수 있어,
  B 미탐이 모델 실패인지 클립 누락인지 구분된다.

## 5. 확장 시나리오 — 이 구조가 푸는 것

영양 영상에서 뉴스로 추가 발언을 더 찾았을 때:

```
pisik-yeongyang-20240511
  #s1  롯데리아 대화(STT, 22~61초)      -> local-life-devaluation   [v1.mp4 포함]
  #s2  "공무원 발령받으면 여기까지"(기사) -> local-life-devaluation   [v1.mp4 미포함]
  #s3  "매일 이것만 먹으면"(기사)         -> local-life-devaluation   [v1.mp4 미포함]
  #s4  "강이 똥물"(기사)                 -> local-life-devaluation   [v1.mp4 미포함]
  #s5  "할머니 살을 뜯는 것 같다"(기사)   -> graphic-body-metaphor    [확인 필요]
```

- B/C/D 3칸 제약 없이 **발언을 무한히 추가**할 수 있다.
- 같은 `local-life-devaluation`이 #s1~#s4로 쌓여 **메커니즘 근거가 풍부**해진다 → 전이 평가가 탄탄해진다.
- 각 발언의 `v1.mp4 포함 여부`가 명시되어, **벤치마크 클립을 어떤 발언이 든 풀영상으로 교체·보강**할지 결정할 수 있다.

## 6. 마이그레이션 순서 (승인 후, 아직 안 함)

1. 이 설계 합의 → 목표 스키마 확정.
2. `drafts/cards.json`을 incident/statement 구조로 변환. pisik 사건에 발언근거와 기사 소스를 채운다.
3. `guidelines/plan.json`의 mechanism→sourceCaseIds를 mechanism→statementIds(또는 incidentIds)로 조정.
4. `research/context-dictionary-plan.json`을 새 구조에 맞게 재생성.
5. 컴파일러(`build_context_dictionary.py`, `controversy_cards.py`)와 테스트를 새 스키마로 수정.
   `--verify` 통과 확인.
6. 영양 풀영상에서 찾은 추가 발언(#s2~)을 발언근거로 추가.

## 7. 하지 않은 것 / 경계

- 이 문서는 설계안이다. 코드·스키마·데이터 파일을 아직 바꾸지 않았다(롤백 완료 상태).
- 사람 승인·런타임 편입·학습 사용은 0건으로 유지한다.
- 기사·댓글의 사용 범위(저작권·개인정보)는 기존 보안 운영정책과 YouTube/언론사 약관을 따른다.
- 메커니즘을 "확정 분류 체계"로 고정하지 않는다. 사건이 쌓이며 메커니즘은 분화·병합될 수 있다.
