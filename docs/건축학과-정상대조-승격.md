## 데이터와 provenance

각각 `context-sources/`, `context-units/`, `context-relations/`에 파일을 추가했다. 승인 기록·원본119 결과의 경로와 해시, 원문 구간 ID/시간/순서, 판단 근거를 연결했다. 두 사례의 sourceGroupId는 같은 YouTube 영상이므로 서로 독립적인 두 영상 표본으로 세지 않는다.

각 사례는 기존 STT에서7구간씩 선택했다. 그림 비교의 전사 오류도 그대로 보존했다. 화면 편집 자막 관찰은 별도 provenance이며 원음 청취 확인으로 표시하지 않았다. source·approval SHA와 선택14구간의 원문/시간이 저장119와 일치함을 무료 대조했다.

상태는 기존 방식의 DRAFT, humanVerified=false, trainingUseAuthorized=false를 유지하고 developmentDecision=PASS와 USER_APPROVED_DEVELOPMENT_BOUNDARY를 명시했다. 사용자 개발 판단 승인과 독립적인 품질 검증은 별개다.

실제 승인 정상 사례를 넣기 위해 합성 대사를 새로 지어내지 않았다. 빌더가 출처 연결된 v2 PASS 단위에 한해서 normalContrasts 빈 배열을 허용하도록 보완했다. REVIEW 단위의 기존 대조 요구는 유지한다. runtime에는 정상 경계 설명과 원문을 제공하고, 경고 가설을 새로 추가하지 않는다.

## 적용

사전 데이터는 Git 제외 로컬 파일로 반영됐고 빌더·회귀 테스트·문서는 Git 대상이다. 다른 환경에는 로컬 사전 데이터도 별도 전달해야 한다. **Spring 재시작 후 새 분석부터 적용**되며 Python 재시작은 필요 없다.119 결과나 STT를 소급 변경하지 않았다. 추가 유료 호출·재분석은0회다.
