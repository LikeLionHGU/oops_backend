# 사용자 승인 개발 경계의 사전 연결

## 사례집의 범위와 식별자

운영 개념은 '콘텐츠 검수 맥락 사례집'이다. 실제 논란 사건과 원영상에서 팀이 먼저 검토한 정상/검토 경계를 함께 보관한다. `pisik-yeongyang` 같은 기존 출처·가족 ID는 바꾸지 않는다. 출처의 종류와 검수 판단은 별개이며, 팀의 검토 대상 승인을 실제 공개 논란 발생이나 대중 전체의 동의로 바꾸지 않는다. 저장 사례의 정상/검토 경계를 비교하되 현재 입력의 독립적인 근거로 최종 판단한다.

## 보강 내용

### 후속: OCR 생성 지시 정상 경계 — 개정24

ID108 프레임3124의 생성 지시·외모 묘사 경계를 공통 프롬프트의 구체 예시 대신 선택 참고에 옮겼다. `mimiminu-dev#generation-description`은 **개발자 프레임 검토 초안·사용자 정답 미승인**이며 공개 논란 사건·학습 정답으로 등록하지 않는다. OCR 원문·시간은 저장 응답의 인덱스와 그대로 대조하고, 별도 화면 관찰은 원문 인용으로 바꾸지 않는다. 합성 정상 예시와 합성 배제 표현 대조도 실제 관측과 구분했다.

저장은 `context-sources/ocr-generation-description-20261022.json`과 `context-units/ocr-generation-description.json`이다. 프레임·OCR 응답·출처 JSON 해시, 원문 일치·출처 인덱스·프레임 URL을 검증한다. 기존 사건32·기준6개는 유지하고 참고41→42개로 빌드했다. 로컬 runtime은 `2026-10-22-development-ocr-boundaries-v2`, SHA256 `2d03106fcf836bdb84a7e14a32cc83c0ebdd9a636e0a964a67ce0c31944c5df9`다. `--write`·`--verify`로 실제 반영을 확인했다. 원본 JSON·프레임은 Git 제외다.

새 참고는 CAPTION 전용이다. 로더는 v6/v7 참고 채널을 상위 기준의 허용 채널 안에서 좁힐 수 있게 하되 빈 채널·중복·알 수 없는 채널은 거절한다. 구버전의 완전 일치 계약은 유지한다. 일반 검색으로 해당 OCR 발췌에서 회수되는지 무료 테스트로 확인하며, 검색 키를 강제로 주입하거나 모델을 호출하지 않는다. 회수는 판정 성공·새 문장 일반화 증명이 아니다.

화면 프롬프트 개정24는 역할·관계를 확인한다는 짧은 원칙 두 줄만 유지한다. 같은 시각 OCR 문맥 우선 전달 코드는 보존했다. 사례집 전체를 요청에 넣지 않으며 선택될 때만 기존 최대3개·총6,000자 예산 안에서 참고가 들어간다. 참고 선택에 따라 입력량이 달라 실제 비용 감소는 아직 측정하지 않았다. Spring 재시작이 필요하며 AWS 데이터 배포는 별도다.

무료 검증: Python 도구157통과·기존6건 건너뜀, Spring 전체1,153통과·실패0. OCR 원문 교정·잘못된 프레임 연결·출처 변경·사용자 승인으로의 승격을 거절하는 테스트와 CAPTION 회수·SPEECH 비선택·6,000자 예산 테스트를 포함한다. 첫 연결 실행은 로더가 모든 사례 채널을 상위 기준과 완전히 같게 요구해 사전을 거절했다. v6/v7에서 허용 범위 내 채널 축소를 지원한 뒤 기존 사례 연결까지 재검증했다. 새 모델 호출은0회이며 기존108 카드 결과는 그대로다.

| 참고 | 제공 맥락에 대한 승인 | 기존 연결 패턴 |
|---|---|---|
| 94/98번 피해 경험 인용 | PASS. 과거 모욕을 충격·각성의 경험으로 전달. 현재 동조·재공격과 구별 | 모욕·조롱 |

두 영상이 실제 공개 논란 사건이라고 주장하지 않는다. 사건 원장32개는 그대로이고 로컬 런타임 참고39→41개, 관계 프로필4→6개, 검색 키3→5개다. 공통 판단 패턴은6개 그대로다. 99번 모델의 PASS를 승인 정답으로 바꾸지 않았다. 특정 문구를 무조건 잡거나 통과시키는 코드도 추가하지 않았다.

## 저장과 연결

`context-sources/mimiminu-*-20261022.json`은 저장 STT의 선택 발췌와 기원·사용자 승인 범위를 담는다. 원음 검수 여부는 false이며, 원문을 교정하지 않았다. `context-units/mimiminu-*.json`에 독립 개발 경계 형식 `context-reference-unit-2`를 사용한다. 기존 사건의 하위 발언으로 잘못 귀속시키지 않고 명시한 기존 mechanismIds에 연결한다. 검색용 설명·관계 프로필은 원문 근거와 분리한다.

개발 경계는 `referencePurpose=DEVELOPMENT_BOUNDARY_NOT_PUBLIC_CONTROVERSY`와 사용자 승인 범위를 요구한다. PASS는 비판 가설로 바꾸지 않고 '사용자 승인 개발 정상 경계(원문 아님·독립 검수 아님)'라고 표시한 해석으로 전달한다. REVIEW_REQUIRED는 개발 검토 경계라는 접두어를 붙인다. 합성 정상 대조는 실제 관측처럼 표시하지 않는다. `humanVerified`, `trainingUseAuthorized`, 전체 `humanValidated`는 false로 유지한다.

원본 해시·가족 ID·승인 결정 일치·기존 패턴 매핑·길이 상한을 확인한 뒤 기존 사건 빌드가 두 단위를 결합한다. 기존 형식과 출력 v7 스키마는 유지한다. 이전 출력은 빌드 도구의 해시별 이력 보관으로 복구할 수 있다. 현재 runtime SHA는 `d08211e3531cfd70c1338ee99e1056603c214e5f699c6cafd87f4b1b7668b8ca`다.

## 검증과 한계

- Python 무료 테스트: 136개 실행, 130개 통과·기존6개 건너뜀. 새3개는 독립 경계·정상/검토 표현·미승인 또는 잘못된 매핑 차단을 확인한다.
- 사건 빌드 `--write`와 `--verify` 통과. 사건32·참고41·기준6, 원본 출처 해시와 출력 manifest 일치를 확인했다.
- Java 전체1,139개 통과. 로컬 사전은 READY_WORKING_REFERENCE로 로드됐으며 두 저장 발췌에서 각 목표 참고가 선택됐다. 수동 검색 키·관계 기록·LLM 분류 없이 기존 검색 경로를 사용했고 요청 참고 예산6000자도 지켰다. 같은 발췌 회수는 연결 확인일 뿐 새 표현 일반화나 모델 판정 개선의 증명이 아니다. 비공개 입력이 없는 환경에서는 해당 로컬 연결 테스트만 건너뛴다.
- 두 영상은 이제 사전 작성에 사용한 개발 자료다. 이후 같은 영상 시험은 사전 연결/회귀 확인이며 독립 성능 평가로 세지 않는다. 실제 배포 전에는 별도 영상과 정상 경계가 필요하다.

원본 JSON은 Git 제외다. 코드 push로 AWS 사전이 갱신되지 않으며, 실행 중 Spring도 자동 갱신되지 않는다. 로컬 재시작과 비공개 파일의 배포는 별도다. 이번 작업은 추가 모델 호출·서버 재시작·AWS 전송을 하지 않는다. OCR의 읽기 불가→PASS 문제는 별도 미해결 항목이다.

## 99번 저장 문맥의 검증 요청 연결 점검

2026-10-22 후속 무료 점검에서 다음을 구분했다.

1. 저장 진단의 anchor `stt-index-50`, 후보 상태PASS, 허용 문맥 ID22개와 해당 저장 STT·기존 PASS 이유를 고정했다. 출처와 현재 사전의 SHA를 개인 `experiments/quotation-ocr-followup-20261022-cZy7vL/frozen-window-99.json`에 기록했다. 원문·정답·사전은 수정하지 않았다.
2. 이22구간과 대표 발언을 기존 검색 경로에 넣었을 때 `mimiminu-dev#audience-devaluation`이 선택됐다. 수동 검색 키나 LLM 호출은 사용하지 않았다.
3. 별도의 명시적인 재구성 후보를 만들고 전체 저장 전사를 실제 CandidateReviewEngine에 넣어, 탐색·검증 호출만 mock으로 대체했다. 새 개발 검토 경계가 검증 system 요청에 포함되고, 원문 user 요청에 정답 필드를 주입하지 않는 것을 확인했다. 가짜 판정 응답을 만들어 정확도 개선으로 세지 않았다.

당시 탐색 가설·제안 근거의 실제 문자열·완전한 system/user 요청은 이 저장 진단에 없다. 해시만 보고 복원하지 않으며 재구성 입력을 당시 요청으로 취급하지 않는다. 따라서 이번 결과는 '사전 회수와 검증 요청 전달' 확인이지, 완전한 당시 요청 재생이나 사전 보강의 판단 효과 검증이 아니다. 저장 자료의 `paidComparisonReady`도 false다. 새 모델 비교를 하려면 원본 요청을 확보하거나, 재구성한 고정 요청이라는 범위를 명시하고 별도 전송·비용 승인을 받아야 한다.

Java 전체 테스트 통과와 사전 빌드 `--verify`를 확인했다. 공급자 호출0회, 사전 SHA 불변, 서버 재시작·Apple 도구 개발 없음이다.

후속 신규 승인 비교6회에서는 [보강 전1/3·후3/3 검토 대상 일치](99번-사전-보강-전후-비교.md)를 관측했다. 이는 같은 원본에서 작성한 참고를 사용한 재구성 검증 시험이며, 위 무료 연결 점검이나 독립 영상 성능 평가와 구분한다.

그다음 [정상 경계16회 비교](정상-경계-사전-보강-전후-비교.md)에서는 참고가 회수된 정상 안내·독려를 PASS로 유지했고, 기존 실제 검토 대상과 정상 인용도 승인 기준에 맞았다. 이 결과로 독립 영상 정확도나 전반적인 안정화 완료를 선언하지 않는다. 사전·운영 판단 지침은 변경하지 않고 다음 실제 영상 검수로 넘어간다.
