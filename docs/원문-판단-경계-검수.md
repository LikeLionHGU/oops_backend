## 실제 발췌에서 확인할 쟁점

아래 짧은 인용은 저장 STT 그대로이며 오인식·비문을 추측 교정하지 않는다. 전체 제공 창은 JSON에서 시간순으로 읽는다. 두 발췌는 같은 대화의 겹치는 창이므로 독립 사건 두 개로 세지 않는다.

### R01 · 질문 문장인가, 표현의 뜻풀이인가

앞에 “오펜무가 뭐예요?”가 나오고 “오늘 팬티는 무슨 색깔?”이 이어진다. 이후 “근데 이거는 내가 답변을 드릴 수가 없어요.”, “없을 무 자를 써서”, “그러니까 저는 집에 있을 때는 안 입어요.” 같은 내용도 제공 창에 있다.

- **검토 가설:** 사적인 속옷 질문을 실제 상대에게 던져 성적·사생활 소재로 다루는 흐름인가?
- **정상 해석:** 질문 문장 자체가 줄임말의 뜻을 설명하는 인용이며, 실제 상대에게 같은 질문을 한 것은 아닌가?
- **필수 확인:** 뜻 설명과 실제 질문을 구분할 원문 연결이 있는가? 누가 누구에게 묻는지는 확정할 수 있는가? 성적 소재 언급을 넘어서는 별도 검토 이유가 무엇인가?
- **확정하지 않을 것:** 답변 거절이라는 말만으로 강압을 만들거나, 자발적 답변이라는 해석만으로 모든 검토 이유를 없애지 않는다. 원음이 필수면 필요한 부분을 적고 UNCERTAIN을 선택할 수 있다.

기존 2회는 경고·계약 통과, 새 2회는 PASS·통과다. 후속 사용자 승인은 **제공 문맥에 구체적인 검토 이유가 없으므로 PASS**다. 새 2회가 이 개발 경계와 일치한다. 전체 원음이나 같은 표현의 모든 용례를 정상으로 승인한 것은 아니다.

### R02 · 자기 공개 제안과 타인 공개 요구를 구분

앞에 위 속옷 관련 대화가 있고 “살짝 보여드릴까요?” 다음에 “형만, 그러니까 살짝 형만.”이 이어진다. 뒤에는 “근데 이게 진짜로 건강에 좋아요.” 등 건강 관련 설명이 있다.

- **검토 가설:** 구체적인 공개 내용이나 대화 상대를 취급하는 방식에 독립적인 검토 이유가 있는가?
- **정상 해석:** 자신의 생활·공개에 대한 자발적인 농담·제안이며 상대에게 신체 공개를 요구한 것은 아닌가?
- **필수 확인:** 말의 형식은 제안이지만 앞뒤 줄이 모두 같은 화자인지는 STT만으로 확정하지 않는다. 듣는 사람을 성적 대상화의 대상으로 썼다면 그 연결을 원문으로 설명할 수 있어야 한다.
- **확정하지 않을 것:** 제안이 있었다는 이유로 실제 노출·상대 동의·강요·악의를 만들지 않는다. 실제 실행이 없어도 표현 자체의 검토 이유가 있을 수 있지만 무엇인지 독립적으로 설명해야 한다.

기존은 경고 2회 중 1회 계약 탈락, 새 계약은 경고/계약 탈락 1회와 PASS/통과 1회다. 후속 사용자 승인은 **제공 문맥에 구체적인 검토 이유가 없으므로 PASS**다. 단지 target 필드를 채운 응답을 더 올바르다고 선택하지 않는다. 새 계약도 이 경계에 2/2로 안정화된 상태는 아니다.

### 기록 필드

- `expectedDecision`: REVIEW_REQUIRED / PASS / UNCERTAIN 중 하나. 처음에는 모두 null이다.
- `evidenceIds`·`reason`: 현재 제공 원문 ID와 판단 이유. 과거 사건 설명·댓글·모델 이유를 발화 사실로 빌리지 않는다.
- `relationNotes`: 누가 무엇을 하는지, 실제로 구분 가능한 관계와 불명확한 관계.
- `normalInterpretation`·`independentReviewReason`: 가능한 정상 해석과 그것만으로 설명되지 않는 검토 이유. 검토 이유가 없으면 없다고 적는다.
- `missingInformation`: 필수 원음·화자·장면 등. 정보가 없다는 사실을 가해·강압의 증거로 쓰지 않는다.
- 검수자·시각·모델 응답을 먼저 봤는지 기록한다. 사용자 개발 승인은 독립 복수 검수나 학습 권한 승인과 별개다.

## 기존 B/C/D와 연결하는 방식

기존 사용자 승인 경계는 재작성하지 않는다. B의 지역 생활·선택지 낮춤과 단순 부재/대체 설명, C의 메뉴·선택지 일축과 일반 리뷰/단일 메뉴 안내, D의 구체적 신체 훼손 비유와 추억 표현을 구분하는 기준을 유지한다. [B 및 정상 경계 이력](B-정상-대조-근거-검수.md)을 참조한다.

새 발췌의 경계가 승인되면 이들과 함께 고정 회귀에 연결한다. 기존 사용자의 개발 라벨도 독립 정확도 정답으로 확대하지 않는다. 원본과 맥락을 새로 확인해야 하는 영상은 따로 구분한다.

| 계약에 통과한 경고 | 3/4 | 0/4 |
| 계약 탈락·미평가 | 1/4 | 1/4 |

이 두 발췌의 사용자 개발 경계에서는 새 계약이 더 일치했다. ‘새 계약의 경고가 모두 사라졌다’는 뜻은 아니며 탈락한 경고 1개는 PASS가 아니다. R01은 새 2/2 PASS·통과, R02는 새 1/2 PASS·통과다.

이는 **기존 결과를 본 뒤 확정한 개발 라벨로 하는 사후 집계**다. 겹치는 대화 창 2개를 독립 사건 2개나 범용 정확도 75%로 표시하지 않는다. 전체 정상 초안 완전 처리의 새 계약 11/12, EXPRESSION_CONTENT 응답 0건, 출력 계약/판단 가드의 혼합 변경이라는 기존 한계도 유지한다. 기본 OFF 유지이며, 이 관측은 다음 비교 설계의 근거로만 사용한다.

재평가 파일은 같은 비공개 폴더의 `stored-response-evaluation.json`이다. 원문 검수본 해시·사용자 승인 양식 파일 해시·원래 결과 해시와 각 응답의 판정/계약 상태를 연결했다. 승인 2·미확정 6, 원문/시간 불변, 정답의 모델 입력 미혼입, 집계 수치의 무료 검사를 통과했다. 새 API 호출·추가 비용은 0이며 사전/학습 자료로 승격하지 않았다.

## 후속 · 8항목 승인과 전체 저장 응답 재평가

사용자가 R03/R07·R05/R06에 각각 ‘둘 다 PASS에 동의’, R04/R08 묶음 질문에 ‘검토 대상’으로 답했다. 마지막 답변은 **두 항목 모두 REVIEW_REQUIRED**로 해석하고 사용자에게 명시했다. R08은 거절 뒤 중단을 보존하며 강압·지속 요구로 확대하지 않는다.

PASS 기대는 **실제 발췌 2개와 합성 4개**를 합친 것이다. 과거 56회 시험의 별도 정상 초안 6개×2회(기존 12/12·새 11/12)와 이름·분모가 비슷하지만 다른 집합이므로 섞지 않는다.

새 계약은 이 개발 세트에서 더 일치했다. R02의 경고/계약 탈락 1회와 R08의 대상 지칭 계약 탈락 1회는 남아 있으며 PASS로 바꾸지 않았다. R08은 양쪽 모두 2회 검토 판단이나 각각 1회만 검증 통과했다. ‘당신’이라는 지칭어와 ‘질문을 받은 상대’라는 해석 대상의 계약 표기를 의미 판정과 분리해 점검해야 한다.

이 수치는 이미 본 응답에 새 사용자 기준을 적용한 사후 평가다. 독립 정확도나 실서비스 개선율이 아니며 최종 카드·B/C/D의 전체 회귀도 아니다. 출력 계약과 판단 가드 효과가 섞였다는 한계, EXPRESSION_CONTENT 응답 0건, 별도 정상 초안 출력 누락을 고려해 **기본 OFF를 유지**한다. 자동 ON 승격이나 사전·학습 권한 승인은 하지 않았다.
