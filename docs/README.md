# OoPs?! 문서 안내

> 2026-10-14 · minwook · 현재 작업은 사례 입력 구조 정비와 풀영상 평가 재구축이다. 구현·계획·과거 시험을 구분하며 AWS 배포 상태를 확인한 문서는 아니다.

## 현재 상태

- 현재 텍스트 후보 실행 개정은 37이다. 개정 36의 허용 원문 창·가설·참고 고정을 유지하고 대상 계약의 이름/지칭어/설명/역할/연결 실패를 진단에 분리한다. 복구에는 실패 세부 조건만 전달하고 ID·역할 출력 예시를 맞췄다. B 사례·프레임 경로는 유지했으며 실영상 개선은 미측정이다. [현재 코드 경계](AI-분석-로직.md#현재-코드-경계--2026-10-14-개정-37)를 따른다. ID 57은 개정 36의 관측이다.

- 현재 기준은 [구조 재설계](논란맥락사전-구조-재설계.md)와 [확정 스키마·마이그레이션](논란사례-구조-확정-및-마이그레이션.md)이다. 사건 → 복수 발언 → 복수 메커니즘을 분리하고, 사건 입력을 `incidents/{incidentId}.json` 하나로 관리한다. 댓글은 선택 보강이며 기사 근거만으로 수집할 수 있다. 사건 추가 전 후보를 사용자에게 공유한다.
- 신규 빌드는 incidents/*.json·definitions/build.json·참조 snapshot만 읽는다. 현재 32사건·37발언·6기준에서 기존 runtime과 재생성 동치를 확인했고 과거 파일은 legacy로 이동했다. --write는 직전 runtime 보관과 입력/출력 해시 manifest 기록, --verify는 최신 입력과 저장 출력의 일치를 검사한다. apply는 사건 저장·생성 검사까지만이다. [현재 파일 관리·빌드·서버 반영](데이터셋-파일-관리.md)을 따른다.
- Java가 사건#발언 ID를 거절해 실제 사전을 INVALID_ARCHIVE로 처리하는 호환 문제를 수정했다. 사례 ID에만 # 구분자를 허용하고 시작 시 로드 상태·버전·원장 해시·예시 수를 로그로 표시한다. Spring 재시작 후 확인하며 배포/유료 분석 완료와 구분한다.
- 인용 계측 버전 ID 55에서 11개 인용이 실제 수용됐고 A/B 카드 3개, C PASS, D 대상 필드 계약 실패였다. 개정 35는 신체 훼손 비유 자체에 공격 대상을 강제하지 않고 메뉴/서비스 검토와 지역 평가를 구분한다. 비판 가설 선택 입력→빌드→runtime 연결과 C 개발 가설 1개를 구현했다. [대상 범위·비판 가설 연결](발언-검증-대상-범위-및-비판-가설-연결.md)을 따른다. 새 기준집 버전은 2026-10-14-menu-hypothesis-v1-patterns-4이며 변경 후 실제 분석은 다음 ID에서 확인한다.
- v1 짜깁기 클립은 사건 전체의 주 벤치마크로 사용하지 않는다. 실제 논란 발언·앞뒤 맥락이 포함된 풀영상과 별도 정상 대조로 평가 입력을 재구축한다. 이전 B/C/D 시험은 과거 입력의 관측·계약 디버깅 이력으로 보존하며 사건 전체 탐지율·전이 성능의 근거로 쓰지 않는다.
- 다음은 기존 메커니즘을 보강하는 후보 사례 검토와 풀영상 평가 구성이다. 소재가 아니라 문제 연결 구조로 사례를 묶고, 새 메커니즘을 무작정 늘리지 않는다. LLM 1-pass 메커니즘 분류 → 사례 검색 가산점 → 최대 2예시 전달은 설계이며 아직 운영 구현·성능 검증 완료가 아니다.
- 기사·댓글은 참조 사례의 근거이고 현재 영상의 STT/화면 근거로 바꾸지 않는다. 같은 사건의 사후 자료가 평가 입력에 섞이지 않도록 제외 family를 명시하고 실제 선택을 확인한다. 기사-only 입력이나 빌드 통과는 사람 승인·운영 적격·학습 권한을 부여하지 않는다. Java 런타임 스키마 변경·배포는 이번 문서 작업에 포함하지 않는다.
- 분석 기본 경로는 맥락·표현 검수다. 외부 검색은 선택 프로필 external-review에 분리했고, 욕설/논쟁 표현 등장 목록은 별도 저장/API로 제공한다. 결과/완료 원자적 저장·오류 분리·경고 누적·검증 인용 기반 병합은 유지한다. 프론트 표현 필터, 포즈/행동 분석, 편집 기능, Rails 전환, 마인드맵 UI는 후속/보류다.
- 서버 안전성 구현은 [코드 정리](코드-정리-및-안전성-개선.md)를 따른다. 업로드 준비는 DB 밖, 등록/atomic rename은 짧은 트랜잭션, 분석 접수는 health 확인 뒤 잠금 재검사·bounded 실행이다. 시작 복구는 단일 인스턴스용이며 공유 DB의 다중 Spring에서는 꺼야 한다. 영속 큐/분산 소유권·고아 업로드 수거는 후속이고 프레임 수거는 기본 OFF다.
- request-traces는 기본 OFF·local/loopback·별도 토큰·크기/건수/보존 시간 제한이 있다. 실제 provider 요청/응답을 민감 자료로 관리하며 로그/DB/외부 자료를 자동 승인 정답으로 보지 않는다. [실제 요청 기록](성공-버전-회귀-비교.md#로컬-실제-요청-기록--구현-새-영상-검증-대기)을 따른다.
- 데이터 원장/실험 JSON은 Git 제외다. 과거 6사건·9카드·30반응 매핑·518댓글 표본은 당시 작업 참고 자료이지 학습 완료 데이터가 아니다. 사용자 개발 라벨, assistant 관찰, 독립 의미 승인, 운영 승인 상태를 구분한다. 알려진 원사건 재현을 독립 영상의 범용 정확도로 발표하지 않는다.
- 유료 시험의 승인·예약·사용량 환산·실제 청구를 구분한다. 이전 시험 예산은 과거 이력이며 새 풀영상 시험의 승인으로 재사용하거나 합치지 않는다. 이번 문서 갱신은 모델 호출·추가 과금 없이 수행했다.
- 상세 결과와 과거 ID/버전/예산은 [실험 기록](AI-분석-실험-기록.md)에 누적한다. 이 안내에는 현재 상태만 두며 과거의 여러 ‘최신’을 반복하지 않는다.

## 관리 원칙

현재 구조는 AI 분석 로직, 사전 계약은 범용 기준집, 표현 필터는 표현 탐지 설계, 실행 결과는 실험 기록을 단일 기준으로 관리한다. 나머지는 상세 설계/운영 또는 과거 근거다. 코드·데이터·API가 바뀌면 해당 기준 문서와 링크를 함께 갱신한다.

설계 필드/가상 예문을 실제 API나 검수 정답으로 표시하지 않는다. 이전 기록에는 당시 버전을 명시한다. local 진단은 인증을 제공하지 않으므로 루프백에서만 사용하고 공개 운영에서 끈다. 문서의 제안만으로 유료 호출·배포·외부 전송을 수행하지 않는다.
