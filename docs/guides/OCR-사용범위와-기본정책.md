## OCR-사용범위와-기본정책

## OCR 사용 범위와 기본 정책 — 2026-10-23

### 결론

현재 주력인 발언·맥락 검수에서는 **전체 영상 OCR을 필수 경로로 두지 않는다.** 기존 코드는 기본 OFF이며 삭제하지 않는다. 이번 작업에서 서버 실행 설정을 바꾸거나 재시작하지 않았다. 직전 ON 비교 이후 실제 실행값은 별도로 확인해야 한다.

이는 OCR이 항상 쓸모없다는 결론이 아니다. 음성과 별개로 화면에만 존재하는 글자를 검수하려면 텍스트 확보 수단이 필요하다. 필요한 서비스 범위를 먼저 선택하고, 화면 글자를 검수하지 않았으면 결과에 이를 명시해야 한다.

### 언제 필요한가

| 검수 목적 | 우선 입력 | OCR의 역할 |
| --- | --- | --- |
| 발언의 비하·인용·뜻풀이 맥락 | STT와 앞뒤 대화 | 기본적으로 불필요. 읽기 오류를 조용히 교정하거나 발언 증거를 늘리는 용도로 사용하지 않음 |
| 음성에 없는 편집 자막·화면 문구 | 편집자가 제공한 타임라인 자막/텍스트, 없으면 OCR | 화면 전용 표현을 찾는 별도 선택 검수 |
| 주소·전화번호·신분증·채팅창 등 화면 정보 노출 | 확인할 장면·영역 | 글자 추출에 도움. 얼굴·이미지 자체 정보나 실제 민감성 판정까지 OCR이 해결하지 않음 |
| 발언과 화면 문구의 불일치 | 발언과 출처·시간이 확인된 자막 | 자막 자료가 없을 때 보조. OCR 결과가 모두 발언 자막이라는 가정 금지 |
| 무음·텍스트 중심 영상 | 사용자 제공 텍스트 또는 화면 글자 | 화면 검수 기능을 제공하려면 중요. STT가 비었다고 자동 안전 판정하지 않음 |
| 말투·표정·웃음·삭막한 분위기 | 필요 구간 원음/이미지 | OCR 용도가 아님. 이미지/음성 검토와 구분 |
| STT 인식 오류 | 해당 원음 재확인 | 간판·메뉴판·편집 문구를 발언으로 대체하지 않음 |

SRT도 발언 자막인지, 화면 효과 자막인지, 전체 편집 문구를 담았는지 확인해야 한다. 자막 파일 하나가 있다고 화면 전체 검수를 마쳤다는 뜻은 아니다.

### 현재 구현과 제안의 구분

- 구현: `full-screen-ocr-enabled=false`이면 전체 OCR과 화면 글자 검수를 건너뛰고 미검수 경고를 저장한다.
- 구현: true이면 STT 이후 전체 프레임 OCR을 수행하는 기존 경로다. 사용자 선택 UI/API가 아니라 서버 설정이다.
- 구현: 일부 발언 후보는 별도 이미지 확인을 사용한다. **후보 이미지 확인은 PaddleOCR이 아니다.**
- 미구현 제안: 화면 전용 선택 검수 작업, 사용자 지정 타임라인/영역 OCR, 발언 후보에 대한 필요 구간 OCR. 현재 코드가 자동으로 필요한 부분만 OCR한다고 설명하면 안 된다.
- 미구현 제안: OCR을 별도 작업으로 지연 실행하고 발언 리포트와 독립 완료 상태를 관리하는 경로.

### 관측 근거와 한계

[v1 112/113 비교](../experiments/OCR-실행안정성과-성능기록.md#record-6)에서 전사는 같았고 OCR ON은 약50초에서75초로 늘었다. 메뉴 흐름은 둘 다 후보가 없었으며, 두 쟁점이 세 카드가 된 것은 신체 비유 중복이었다. OCR 101행은 배경·출처 불확실로 분류돼 자막 표현 검토에서 제외됐다. 한 번의 비교로 OCR이 중복·오탐의 원인이라고 단정하지 않는다.

발언 우선 롱폼 시험에서도 화면 미검수를 명시하면서 시간이 단축됐지만 화면 전용 위험에 대한 검출률은 측정하지 않았다. OCR ON이 더 안전하다거나 OFF와 검수 범위가 같다고 주장하지 않는다.

### 향후 채택 기준

OCR의 가치는 발언 카드 개수 증가가 아니라 **화면에만 있던 실제 검토 대상의 추가 발견**으로 평가한다. 화면 전용 검토 대상과 정상 간판·메뉴·효과 문구 대조를 고정한 뒤, 추출 성공·편집/배경 역할·최종 오탐/미탐·추가 시간·메모리를 따로 본다.

현재는 텍스트 맥락 사례와 검색 적합성을 먼저 보강한다. OCR 범위 확장이나 추가 유료 비교는 이번 작업에 포함하지 않는다.

## 이미지-검토-필요조건과-호출정책

## 이미지 검토 필요조건과 호출 정책 — 2026-10-23

### 원칙

**현재 판단에 필수이며 선택 이미지에서 관측할 수 있는 사실이 있을 때만 호출한다.** 더 많은 정보가 있으면 좋겠다는 이유만으로 모든 후보에 이미지를 붙이지 않는다. OCR, 선택 이미지 검토, 원음 검토는 서로 다른 입력과 목적이다.

| 현재 부족한 정보 | 적절한 경로 | 이미지 호출 여부 |
| --- | --- | --- |
| ‘이것/여기’가 가리키는 사물·공간과 발언의 연결 | 해당 후보 주변 선택 프레임 | 구체적 연결이 판단에 필수일 때 |
| 화면 문구가 편집 자막인지, 인용 자료·메뉴판·배경인지 | 제공 텍스트의 출처·배치 확인 | 그 역할이 판단을 바꾸고 대상 프레임이 있을 때 |
| 발언과 화면에 제시된 물건·표시의 비교 | 특정 화면 사실 확인 | 사실을 구체적으로 질문할 수 있을 때 |
| 이미지에 정보가 실제 보이는지 | 선택 구간 화면 확인 | 특정 의심 구간이 있을 때. 전체 영상의 노출 검사를 대신하지 않음 |
| 비꼬는 억양·웃음소리·말투 | 원음/연속 클립 검토 | 정지 이미지로 해결하려고 호출하지 않음 |
| 표정으로 추정한 악의·불쾌감·동의 | 현재 자료로 확정 불가 | 추측 보강용으로 호출하지 않음 |
| 사건의 실제 발생·외부 시기·의도 | 확인된 외부 맥락 또는 추가 자료 | 이미지가 사실 대조를 대신하지 않음 |
| 텍스트만으로 충분한 위협·신체 비유·인용 관계 | 기존 텍스트 경로 | 기본 불필요 |
| 텍스트 후보 없이 화면에만 있는 문제 | 별도 화면 검수 기능 | 현재 발언 후보 보충 경로로 전체 화면 검수를 보장하지 않음 |

국가·지역명과 한적한 배경을 결합했다고 자동 비하가 되지 않는다. 예를 들어 공간을 보고 국가를 묻는 발언에서 이미지는 공간의 사물·표시를 보충할 수 있지만, 그것만으로 경멸 의도나 특정 국가를 낮춰 보는 의미를 증명하지 못한다.

### 실제 프롬프트 변경

사용자가 이미지 호출 정책도 다듬도록 요청하여, 이전 동결의 **시각 분기 두 부분만** 수정했다.

1. `CandidateReviewPrompts.DISCOVERY_PROMPT`의 visualCandidates 선별 문단을 교체했다.
   - 필요한 화면 사실과 그 사실이 해석을 바꾸는 이유를 reason에 작성.
   - 텍스트로 충분한 후보는 텍스트 경로 유지.
   - 원음·연속 행동만으로 해결할 누락은 uncertainSegments로 구분.
2. `VisualContextReviewer.PROMPT`의 관측 지침을 교체했다.
   - 선택 프레임에서 보이는 사실 → 발언과 연결 → 남은 불확실성을 분리.
   - 표정·국가·의도·음성 추정 금지, 작은 글자는 추측하지 않기.
   - 프레임 밖 사실과 연속 장면을 만들지 않기.

후보 엔진 개정은 `2026-10-23-candidate-visual-necessity-47`이다. 공용 POLICY·텍스트 VERIFICATION_PROMPT, 사례 정답·운영 사전·이미지 수·모델·출력 JSON 구조는 바꾸지 않았다. 재시작 후 새 분석부터 적용되며 이번 작업에서 서버를 재시작하거나 유료 호출하지 않았다.

이번 변경은 **LLM에게 주는 호출 선별 지침**이다. 서버가 이미지 필요성을 의미적으로 검증하는 새 하드 게이트를 구현한 것은 아니다. 후보가 과도하게 생성될 가능성은 남는다. 실제 호출 수·오탐·미탐·시간 개선은 아직 측정하지 않았다. 시각 경로는 여전히 업로드 영상만 지원하며 YouTube URL의 VISUAL_UPLOAD_ONLY 제한을 해결한 작업이 아니다.

### 출처와 한계

OpenAI Docs의 [Images and vision](https://developers.openai.com/api/docs/guides/images-vision)은 작은 글자·비라틴 문자·공간 판단·잘못된 묘사 가능성 등의 한계를 설명한다. 이 문서는 이미지 입력의 한계를 확인하는 데 참고했으며, 특정 모델의 현재 계정 접근성·가격이나 우리 서비스의 정확도를 검증한 자료는 아니다.

실제 프롬프트 전문은 [요청별 전문](현재-AI-요청별-프롬프트-전문.md)과 [검색 보충 전문](../casebook/사례-검색-프롬프트-전문.md)을 코드 스냅샷 테스트와 함께 유지한다.

### 무료 검증

이미지 요청 모의 검사·시각 필요조건 문구·전문 스냅샷과 전체 Java 회귀1167개가 통과했다(실패/오류/skip0). 기존 문구를 고정 검사하던 테스트1개는 교체한 호출 필요조건을 검사하도록 갱신했다. Python tools167개 통과·선택적6개skip을 확인했다. 실제 모델 응답이나 호출 감소를 측정한 테스트는 아니다.

이전 동결267개 중 변경은 시각 분기 소스2개와 개정 문자열이 있는 엔진1개뿐이다. POLICY·텍스트 VERIFICATION_PROMPT의 소스 문자열은 이전 커밋과 같음을 별도로 대조했다. 이전 freeze 파일을 새 기준으로 덮어쓰지 않았다.

## 발언우선-전체OCR-선택분리

## 발언 우선 분석과 전체 OCR 선택 분리

2026-10-23 · 기본 파이프라인 변경 · 실제 영상 속도·탐지 유지 비교 전

### 변경한 기본 경로

```text
영상 등록 → 길이 확인 → STT → 유형 판별·발언 후보 탐색/검증
                                     └─ 필요한 후보의 선택적 장면 확인
                         → 병합·리포트
```

기본값에서 전체 OCR 추출·화면 글자 룰/LLM 분석을 실행하지 않는다. STT 성공 뒤 OCR 결과를 기다리지 않고 진행하며, 장르 감지에도 화면 글자가 아닌 현재 대본이 전달된다. 기존 후보 기반 VisualContextReviewer는 별도 경로로 유지한다. 이 기능은 현재 UPLOAD 원본만 지원하며 URL 영상의 VISUAL_UPLOAD_ONLY 제한은 이번에 해결하지 않았다. 이미지 확인과 OCR 글자 인식은 같은 기능이 아니다.

전체 OCR을 명시적으로 켜려면 서버 실행 환경에 `FULL_SCREEN_OCR_ENABLED=true`를 지정하거나 `--oops.analysis.full-screen-ocr-enabled=true`를 사용한다. 기본은 false다. true이면 기존 STT→전체 OCR→분석 순서·프레임 보존·처리 상태 계약을 유지한다.

**현재 선택 단위는 서버 설정이다.** 영상별 요청 옵션·화면 검수 별도 API·독립 비동기 OCR job은 아직 구현하지 않았다. true 모드는 여전히 같은 분석 job 안에서 OCR을 기다린다. 전체 OCR을 따로 예약하는 제품 기능까지 완료했다고 설명하지 않는다. 재시작한 서버의 이후 분석에 적용되며 과거 리포트를 소급 수정하지 않는다.

### 리포트 계약

- 기본 분석에서는 OCR와 SCREEN_TEXT_REVIEW를 NOT_ENABLED로 저장한다.
- `coverage.screenTextAnalyzed=false`이며 warnings에 `OCR_NOT_ENABLED`, `SCREEN_TEXT_REVIEW_NOT_ENABLED`를 표시한다.
- 메시지는 화면에만 있는 표현·개인정보를 확인하지 않았음을 명시한다. 미선택을 OCR 실패·키 없음·글자 없음으로 바꾸지 않는다.
- 전체 장면 검수와 선택적 후보 장면 확인도 계속 구분한다. 카드0개를 전체 영상 안전으로 읽지 않는다.
- STT가 비면 기본 분석은 실패한다. 몰래 전체 OCR을 실행하거나 대본 없는 성공을 발행하지 않는다.

화면 글자 분석기가 enabled-analyzers 목록에 남아 있어도 기본 모드에서는 실행하지 않는다. 기존 OCR 결과가 ThreadLocal에 남아 있어도 미선택 경로에서 이를 조회해 실패로 승격하지 않는다. 결과 저장·취소·프레임 수명·발언 사전·프롬프트는 기존 계약을 유지한다.

#### 실제 서비스 확인 — ID111
