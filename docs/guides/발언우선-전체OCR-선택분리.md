# 발언 우선 분석과 전체 OCR 선택 분리

2026-10-23 · 기본 파이프라인 변경 · 실제 영상 속도·탐지 유지 비교 전

## 변경한 기본 경로

```text
영상 등록 → 길이 확인 → STT → 유형 판별·발언 후보 탐색/검증
                                     └─ 필요한 후보의 선택적 장면 확인
                         → 병합·리포트
```

기본값에서 전체 OCR 추출·화면 글자 룰/LLM 분석을 실행하지 않는다. STT 성공 뒤 OCR 결과를 기다리지 않고 진행하며, 장르 감지에도 화면 글자가 아닌 현재 대본이 전달된다. 기존 후보 기반 VisualContextReviewer는 별도 경로로 유지한다. 이 기능은 현재 UPLOAD 원본만 지원하며 URL 영상의 VISUAL_UPLOAD_ONLY 제한은 이번에 해결하지 않았다. 이미지 확인과 OCR 글자 인식은 같은 기능이 아니다.

전체 OCR을 명시적으로 켜려면 서버 실행 환경에 `FULL_SCREEN_OCR_ENABLED=true`를 지정하거나 `--oops.analysis.full-screen-ocr-enabled=true`를 사용한다. 기본은 false다. true이면 기존 STT→전체 OCR→분석 순서·프레임 보존·처리 상태 계약을 유지한다.

**현재 선택 단위는 서버 설정이다.** 영상별 요청 옵션·화면 검수 별도 API·독립 비동기 OCR job은 아직 구현하지 않았다. true 모드는 여전히 같은 분석 job 안에서 OCR을 기다린다. 전체 OCR을 따로 예약하는 제품 기능까지 완료했다고 설명하지 않는다. 재시작한 서버의 이후 분석에 적용되며 과거 리포트를 소급 수정하지 않는다.

## 리포트 계약

- 기본 분석에서는 OCR와 SCREEN_TEXT_REVIEW를 NOT_ENABLED로 저장한다.
- `coverage.screenTextAnalyzed=false`이며 warnings에 `OCR_NOT_ENABLED`, `SCREEN_TEXT_REVIEW_NOT_ENABLED`를 표시한다.
- 메시지는 화면에만 있는 표현·개인정보를 확인하지 않았음을 명시한다. 미선택을 OCR 실패·키 없음·글자 없음으로 바꾸지 않는다.
- 전체 장면 검수와 선택적 후보 장면 확인도 계속 구분한다. 카드0개를 전체 영상 안전으로 읽지 않는다.
- STT가 비면 기본 분석은 실패한다. 몰래 전체 OCR을 실행하거나 대본 없는 성공을 발행하지 않는다.

화면 글자 분석기가 enabled-analyzers 목록에 남아 있어도 기본 모드에서는 실행하지 않는다. 기존 OCR 결과가 ThreadLocal에 남아 있어도 미선택 경로에서 이를 조회해 실패로 승격하지 않는다. 결과 저장·취소·프레임 수명·발언 사전·프롬프트는 기존 계약을 유지한다.

## 검증과 다음 단계

### 실제 서비스 확인 — ID111

2026-10-23 새 추정 상한 $2.00과 음성 Groq·텍스트/필요 후보 프레임 OpenAI 전송 승인으로 같은 제미나이 아카데미 원본(978초)을1회 분석했다. 새 Spring 실행 인자에서 local·전체 OCR false를 확인했고 다른 진행 작업은 없었다. 실제 청구액은 미확인이다.

이번 한 원본 실행에서808.537초·약87.44% 단축됐다. 최종 화면 검수 범위 자체를 줄인 비교이므로 동등한 전체 검수의 엔진 속도 향상으로 표현하지 않는다. STT 응답·발언 개정46·탐색26요청의 참고 선택 ID/요청 키/payload 크기는110과 동일했다. MT 정상 참고도11개 탐색 요청에 전달됐다. 기존 노잼 구간은 NO_CANDIDATE로 유지됐으며 명시적 PASS 응답은 아니다.

실제 report의 `speechAnalyzed=true`, `screenTextAnalyzed=false`, `sceneAnalyzed=false`를 확인했다. `OCR_NOT_ENABLED`·`SCREEN_TEXT_REVIEW_NOT_ENABLED`가 화면에만 있는 표현/개인정보 미검수를 안내하고 OCR_UNAVAILABLE은 없다. 발언은439/439탐색·미확인0·검증 실패0이지만22배치 문맥 제한 때문에 PARTIAL이다. 새 기본 경로에서 관측한 health는ocrBusy=false였고 OCR 자식은 없었다. 최종 Python 본체RSS약133MiB이며 서버를 임의 종료하지 않았다.

사례 작성에 사용한 같은 원본의1회 회귀 확인이다. 전체 요청을 고정한 실험·독립 정확도 검증이나100분 영상 처리시간 보장은 아니다. 화면 글자/장르 입력에서 OCR이 빠지고 후보 수도 달라져 속도 차이 전부를 단일 요소의 고정 인과 효과로 환산하지 않는다. 화면만의 위험을 놓칠 수 있다는 제품 범위는 유지한다.

API5종·승인 계획·비교 JSON은 Git 제외 `experiments/speech-first-20261023-rSfLCP/`에 보존했다. 이번 실행은 코드·사전·사용자 라벨을 바꾸지 않았다. 다음은 다른 정상 영상과 알려진 검토 대상 영상에서 발언 탐지 유지 여부를 확인하는 것이다. 아래는 변경 당시 무료 검증 기록이다.

무료 테스트로 기본 OCR 미호출·발언 분석 진행, opt-in OCR 실행·실패 상태 보존, 화면 분석기 미호출, 화면 coverage=false·미실행 경고, STT 실패의 비우회, DB 저장 후 report 계약을 확인한다. 기존 프레임 저장 테스트는 full-screen opt-in을 명시해 보존한다. 첫 전체 실행에서는 그 테스트가 예전 기본 OCR 실행을 가정해 실패했고, 선택을 명시한 뒤 재검증한다.

최종 Spring 전체1,160개 통과·실패0·건너뜀0이다. 테스트 격리용 AOP 대상 복구 코드의 타입 추론 오류도 수정하고 전체 재실행했다. 유료 호출·기존 서버 재시작·실제 영상 재분석은0회다. Python 코드는 이번에 변경하지 않았다.

기본 경로의 OCR 호출이 없어지는 것은 코드·mock 시험으로 확인하지만, 실제 서비스 처리시간이나 탐지 품질을 아직 측정하지 않았다. OCR에 쓰던 약13분을 항상 그대로 절약한다는 보장도 하지 않는다. STT·LLM 후보량·장면 확인 등 나머지 비용은 별도로 남는다.

다음은 Spring 재시작 후 같은 원본1회에서 OCR 미실행·발언 후보·소요시간·미실행 안내를 확인하는 것이다. 실제 Groq/OpenAI 호출은 별도 새 예산·전송 승인 후 진행한다. 화면만의 문제 탐지가 필요하면 명시적 full-screen 설정으로 검수 범위를 넓힌다.
