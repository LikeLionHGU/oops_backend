## 14. 승격 게이트와 복원 리허설

`tools/release_gate.py`는 로컬 JSON 비교기다. 모델을 부르거나 runtime을 덮어쓰거나 실제 서버에 배포하지 않는다.

비교 입력은 다음을 서로 해시로 고정해야 한다.

- **Suite:** 사전 동결된 입력·사람 승인 정답, source/evaluation group, 카테고리, 입력 해시, 관련 참고 ID 검수. suite 자체와 기준선·후보 실행의 해시가 같아야 한다.
- **Criteria:** suite 동결 뒤 실행 전에 잠근 전체 기준. 전체와 카테고리별로 미탐, 오탐, 불확실, 미평가, 계약 실패, 근거 오류/미검수, 중복, 관련 참고 미회수·기존 관련 참고 밀림, 예산 위반, 최대 비용을 따로 정한다.
- **Runs:** 기준선·후보가 각 suite의 모든 케이스를 정확히 한 번씩 포함하고, 케이스별 원본·입력 해시가 동결 suite와 일치해야 한다. `REVIEW_REQUIRED`는 `COMPLETED` 및 `REVIEWED_VALID` 근거만 허용한다. 각 실행은 코드·모델·프롬프트·정책·runtime·설정·검색 구성요소에 속한 실제 파일 경로/해시를 매핑하며, 구성요소별 지문은 manifest에서 계산한다. 검색 실험은 실제 bundle을 검증한 상태에서 검색 구성요소만 바뀌고 경로-구성요소 매핑은 같아야 한다.
- **승격 승인:** 결과가 `READY_FOR_HUMAN_REVIEW`여도 자동 승격하지 않는다. 기준선·후보의 실제 bundle 디렉터리가 manifest와 파일 집합·SHA까지 정확히 일치하고, 격리 임시 디렉터리 rollback rehearsal가 PASS이며, 수동 승인이 후보 bundle 해시·criteria 해시와 일치할 때만 `deploymentEligible=true`가 된다. 승인 JSON에 `PASS`만 적는 것으로는 eligibility가 열리지 않는다. 이 도구는 실제 배포를 실행하지 않는다.

카테고리 실패는 전체 평균으로 상쇄하지 않는다. 같은 기준선보다 품질 지표가 나빠지면 별도로 실패시킨다. `UNCERTAIN`, `NOT_EVALUATED`, `CONTRACT_FAILURE`는 성공이나 PASS로 세지 않는다. 비용은 두 실행에서 동일한 산정기준(`PROVIDER_REPORTED` 또는 사전 고정 추정치)을 써야 한다. 사람 승인 상태와 sourceGroup 확인은 입력된 검수 메타데이터에 대한 일관성 검사이지, 사람 신원·원본 영상·라벨 진실성을 암호학적으로 인증하지는 않는다.

비교 준비가 된 이후 명령 모양:

```sh
python3 tools/release_gate.py compare \
  --suite <frozen-independent-suite.json> \
  --baseline <baseline-run.json> \
  --candidate <candidate-run.json> \
  --criteria <prelocked-criteria.json> \
  --baseline-bundle-dir <baseline-bundle> \
  --candidate-bundle-dir <candidate-bundle> \
  --rollback-rehearsal \
  --approval <optional-human-promotion-approval.json>
```

실제 bundle을 확인하지 않는 비교는 결과를 `READY_FOR_HUMAN_REVIEW`로 낼 수 있어도 eligibility는 항상 false다. 실제 bundle 디렉터리를 제공하면 manifest에 나열된 파일만 있어야 하고, 파일 내용 SHA와 정규화 bundle SHA가 실행 기록과 일치해야 한다. 심볼릭 링크·민감 경로·누락/추가 파일은 거부한다.

이 변경부터 실행기록은 `release-evaluation-run-2` 계약을 사용한다. 이전 v1 기록은 입력 지문과 파일별 구성요소 귀속을 증명하지 못하므로 새 검증 비교에 그대로 재사용하지 않는다.

`rollback-rehearsal`은 baseline/candidate bundle의 서로 다른 파일 manifest를 별도 임시 디렉터리에 차례로 적용하고, baseline 파일 집합을 복원한 뒤 SHA가 같은지 확인한다. 실제 프로젝트·서버·배포 디렉터리는 변경하지 않는다. manifest 형식은 다음과 같다.

```json
{
  "baselinePaths": ["runtime.json", "application.yml"],
  "candidatePaths": ["runtime.json", "application.yml", "new-config.json"]
}
```

```sh
python3 tools/release_gate.py rollback-rehearsal \
  --baseline-dir <baseline-bundle> \
  --candidate-dir <candidate-bundle> \
  --manifests <baseline-candidate-paths.json>
```

현재는 이 도구를 실제 배포 산출물에 실행하지 않았다. 테스트 fixture에서 경로 탈출·비밀 파일·링크·추가/변경 파일 거절, 파일 구성이 다른 candidate 적용 후 baseline 복원을 확인했다. 그러므로 “운영 롤백 완료”가 아니라 **오프라인 리허설 기능 구현 및 합성 검증**이다.

## 15. 검색 알고리즘 비교와 적용 경계

현재 production selector는 세 요소를 한 점수로 숨기지 않는다.

- **LEXICAL:** NFKC 정규화 뒤 한국어 문자 3-gram 겹침과 문서 빈도 기반 점수. 사전 전체 크기/빈도가 바뀌면 기존 사례 순위에도 영향을 줄 수 있다.
- **STRUCTURED:** `context-search-profiles.json`의 작성된 query/reference 조건으로 개념 확장. 현재 `structured-context-search-enabled` 기본값은 `true`이며 판정 호출을 추가하지 않는다.
- **RELATION / ROUTING:** 역할별 관계 유사도와 mechanism routing은 각각 실험 설정으로 분리돼 있다. `candidate-source-relations-enabled`와 `mechanism-routing-enabled` 기본값은 `false`다.
- **SEMANTIC:** 의미 순위 비교 실험이 존재하지만 현재 운영 검색 경로로 승격된 상태는 아니다.

이 작업에서 기본값·검색식·공용 프롬프트를 변경하지 않았다. 기존 `CasebookImpactAudit`, `ContextFitAdoptionGateTest`, structured/role ablation 테스트를 유지한다. 특히 기존 적용 게이트는 현 개발 자산에서 이득이 확인되지 않으면 채택하지 않는다. 이 테스트들은 검색의 구조·참고 선택 변화를 보며, 모델 최종 판단의 의미 정확도를 증명하지는 않는다.

새 비교는 `release_gate.py`의 `SEARCH_ABLATION`으로 동일한 suite/정답/모델/프롬프트/정책/runtime/설정을 고정하고 retrieval 지문만 바꾼다. manifest에는 구성요소별 실제 파일과 SHA가 있어야 하며, 두 실제 bundle 디렉터리가 없으면 검색 ablation은 거절한다. suite에는 각 query의 사람 검수 `expectedRelevantReferenceIds`가 필요하다. 비교 결과는 아래를 전체·카테고리별로 보존한다.

- 관련 참고 미회수와 baseline에서 candidate로 옮길 때 밀린 관련 참고
- 무관 참고 유입과 payload 상한 초과
- 최종 미탐/오탐, 불확실·미평가·계약 실패, 근거 오류·미검수, 중복
- 비용 및 비용 산정 방식

개발 평가에 쓴 동일 사건 자료는 독립 평가에 세지 않는다. 현재 레지스트리에 query별로 승인된 관련 참고 ID가 충분히 연결돼 있지 않고, verified independent source group도 없다. 따라서 아직 알고리즘 간 실제 품질 비교를 실행하지 않았고 어떤 검색 옵션도 새로 승격하지 않았다.

## 16. 사례 확장과 독립 영상 평가

품질 감사에서 runtime은 **64개 참고 예시 / 6개 기준**이다. 이 중 맥락 unit으로 이관된 것은 29개, legacy 유지 항목은 **35개**다. legacy 35개는 31개 `familyId` 작업 묶음으로 정리되며 4개 묶음이 각각 2항목, 나머지 27개가 단일 항목이다. `familyId`는 검수 작업을 모으는 이름일 뿐 검증된 영상/source group으로 간주하지 않는다.

각 legacy 항목은 현 시점 모두 `UNCLASSIFIED_REQUIRES_HUMAN_REVIEW`다. 분류 후보는 중복, 새 표현, 새 경계, 정책 충돌, 새 메커니즘, 출처 부족 보류다. 도구는 이를 자동 추측하지 않는다. 출처·승인·문맥 연결을 확인한 뒤 사람이 이 중 하나를 정해야 한다. 이 triage 보고서는 기본 inventory에 포함되며 runtime/사례/정답을 수정하지 않는다.

```sh
python3 tools/audit_context_casebook.py \
  --output datasets/controversy/experiments/legacy-triage-<새이름>
```

출력은 Git 제외 실험 폴더에 쓰인다. 기존 폴더를 덮지 않는다. 그룹 ID를 source independence나 데이터셋 라벨로 승격하지 않는다.

독립 영상 평가를 시작하려면 최소한 다음을 채워야 한다.

1. 개발/기존 검수 영상과 겹치지 않는 실제 source group 및 원본·전사 출처 해시를 확인한다.
2. 모델 결과를 보기 전에 영상별 판단과 관련 참고 ID를 사람 검수하고 suite/criteria를 동결한다.
3. 검토 대상뿐 아니라 가까운 정상 대조를 같은 메커니즘·출처 기준으로 포함한다.
4. 같은 영상에서 나온 클립·전사·파생 문장을 한 source/evaluation group으로 묶어 train/dev/holdout 누출을 막는다.
5. 그 자료로 개발을 시작하면 holdout에서 제외하고, 새 미사용 출처를 다시 확보한다.

현재 고정 suite는 독립 gold가 아니고 source group으로 확인된 독립 영상은 **0개**다. 그래서 코드가 실행된다는 이유로 16번 전체를 완료 처리하지 않는다. 영상 찾기·원음 검수·정답 라벨링·정책 승인·유료 모델 비교는 이번 변경에서 수행하지 않았다.

## 변경·검증 기록

- `tools/release_gate.py`: suite/criteria/run hash, 사전 동결 시각, 독립 source disjointness, 카테고리별 기준·회귀, 참고 회수/밀림·최종 품질·비용·승인 bundle을 fail-closed 비교. 자동 배포 없음.
- rollback rehearsal는 지정 경로만 새 임시 디렉터리에서 시험한다. 비밀 파일명 및 경로 탈출을 거절한다.
- `tools/audit_context_casebook.py`의 legacy inventory는 35개를 분류 미정으로 표시하고 기존 family id별 검수 작업 순서만 제공한다.
- 실제 로컬 inventory 결과는 Git 제외 `datasets/controversy/experiments/release-14-16-foundation-20261025/`에 보관했다. 이 파일은 원문/승인 라벨 변경이나 runtime 승격이 아니다.
- 모델/API 호출 0, runtime/프롬프트/기본 검색 설정/사례 승인 라벨 변경 0.
- 새 gate 및 inventory 관련 테스트는 합성 fixture에서 실행한다. 현재 suite의 실제 운영 승격·검색 품질·독립 영상 정확도를 확인한 것은 아니다.
