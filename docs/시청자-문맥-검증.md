## 이번 구현 범위

STT 후보 탐색에 `visualCandidates`를 추가했다. 텍스트만으로 위험을 증명하지 못해도 화면을 봐야 해석이 달라지는 비교·평가를 별도로 제안한다. 국가명·지역명·지시어 자체는 선별 이유가 아니다. 기존 텍스트 후보와 별도이며 배치 제안 합계 12개, 전체 검증 후보 기본 24개에 함께 포함된다. 이미지 후보는 추가로 영상당 최대 3개다.

```text
STT 시간순 읽기 → 텍스트 후보 → 기존 텍스트 근거 검증
              └→ 화면 확인 필요 후보
                    → Python /scene-frames에서 원본 JPEG 추출
                    → STT 문맥 + 실제 이미지 + 원본 프레임 시간
                    → 화면 관찰 / 발언 연결 / 대조 해석 / 판정
                    → 원문·프레임 ID·출력 계약 검증 → 카드 또는 미확인
```

Spring `CandidateReviewEngine` → `VisualContextReviewer` → `AnalysisServerClient.sceneFrames` → Python `scene_frames.sample` → `OpenAiClient.completeWithImagesAsJson` 순서다. 이미지 경로 문자열을 보여주는 대신 JPEG를 Base64로 실제 전달한다. 현재 설정 모델을 유지하며 공식 GPT-6 Luna 문서는 이미지 입력 지원, 오디오·비디오 입력 미지원, 파인튜닝 미지원을 명시한다. 계정·프록시에서 실제 동작하는지는 별도 실영상 검증이 필요하다. [공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-6-luna), [이미지 입력 문서](https://developers.openai.com/api/docs/guides/images-vision).

## 프레임·비용·보안 한도

- 업로드 원본만 지원한다. YouTube 링크는 매 후보마다 재다운로드하지 않도록 이번 경로에서 명시적으로 미확인 처리한다.
- anchor 중간 시간은 유지하고, 탐색 후보의 원문 인용에 연결된 다른 발언 시점에서 최대 2장을 우선 선택한다. anchor와 먼 인용부터 선택하되 이미 선택한 시간과 2초 미만으로 겹치는 시점은 제외한다. 남은 슬롯만 anchor -2초/+2초로 보충하고 영상 범위 안으로 제한한다. 최대 3장은 유지한다. 인용 없는 전체 문맥이나 OCR 간판을 임의로 시각 근거로 선택하지 않는다.
- Python 저장소 `videos/` 아래 실파일만 허용하며 기존 경로 검증을 재사용한다. 임의 URL·외부 파일·OCR framePath를 이미지 입력으로 쓰지 않는다.
- ffmpeg 최대 20초/프레임, 최대 768×768 안의 JPEG, 프레임당 512,000바이트다. 실제 `showinfo pts_time`을 반환하고 요청 시간과 1초 넘게 다르면 실패한다. OCR 설치 여부와 무관하다. 임시 작업 디렉터리는 정리하며 새 프레임 파일을 영구 저장하지 않는다.
- 모델에는 low detail로 최대 3장을 보낸다. 작은 자막·미세 표정·짧은 장면 전환에는 부족할 수 있다. 영상당 기본 이미지 검증 최대 3요청이며 기존 클라이언트의 전송 재시도는 별도다. 입력 이미지/토큰·시간·비용이 늘 수 있으며 정확한 비용 절감이나 상한 금액은 주장하지 않는다.
- 기본 `visual-context-enabled=true`, `VISUAL_CONTEXT_ENABLED=false`로 끌 수 있다. 꺼진 상태에서도 화면 필요 후보를 정상 PASS로 바꾸지 않는다. 후보 예산 초과·영상 길이 미확인·이미지 누락·시간/출력/인용 실패는 부분 검토로 남긴다.
- 장면에는 개인정보가 있을 수 있다. 이 기능은 해당 영상의 일부 화면도 기존 외부 AI 공급자에게 전송한다. 서비스의 사용자 안내·동의·보관 정책에 이를 포함해야 한다. 진단에는 이미지 바이트·저장 경로·키·공급자 원문 응답을 남기지 않는다.

## 관찰과 해석의 분리

### 개정 19: 지칭어·해석 대상 분리와 화면 의존성 확인

탐색의 동일 요청 안에서 모든 primaryIds에 대해 위험 후보 여부와 화면 의존성 여부를 별도로 확인하도록 지시한다. 국가명·지역명 단독 규칙이나 특정 벤치마크 문장 하드코딩은 없다. 별도의 독립 장면 탐색기나 결정적인 라우팅 알고리즘을 추가한 것은 아니므로 모델이 화면 필요 후보를 누락할 가능성은 남는다.

검증 응답의 `targetMention`은 TARGET 원문에 실제 존재하는 지칭어, `target`은 문맥상 해석 대상이다. 둘이 다르면 CONTEXTUAL 관계와 다른 발언 ID의 CONTEXT 인용, 구체적인 targetReason을 요구한다. EXPLICIT 관계에 서로 다른 이름을 반환하거나 원문에 없는 지칭어·연결 인용을 반환하면 실패한다. 기존 직접 지칭 응답의 null targetMention은 target을 원문 지칭어로 사용하는 호환 경로다. PASS/UNCERTAIN에는 targetMention도 null이어야 한다.

원문 일치·허용 문맥·유형·대조 해석 검증은 유지한다. 이 계약은 모델의 대상 해석이 의미적으로 맞다는 보증이 아니다. 연결이 불명확하면 UNCERTAIN을 반환하도록 요구한다. 공개 카드/DB 스키마는 유지하며 원문 근거와 해석 대상은 기존 evidence/target/targetReason으로 전달한다. targetMention 별도 DB 저장이나 독립 페르소나 모델은 추가하지 않았다.

프레임 선택은 인용 시간 기반 휴리스틱이다. 장면 전환 검출·영상 전체 분석·시각적 중복 검출은 아직 구현하지 않았다. 이미지 수/후보 한도/요청 구조는 유지하지만 새로 선별되는 후보가 늘면 총비용은 늘 수 있다.

`observations(frameId, description)`는 제공된 화면에서 보이는 내용, `connectionReason`은 발언과의 연결 해석이다. 실제 프레임 ID·길이·원문 인용·anchor·대상·대조 해석을 서버에서 검증한다. 이 검증은 모델의 화면 설명이나 비판 해석이 사실이라는 의미적 보증은 아니다.

한적한 거리와 국가 언급이 함께 있어도 자동 차별 판정하지 않는다. 위치 질문·중립 비교와 구별되는 평가 연결이 필요하다. 억양·추가 장면이 필수라면 UNCERTAIN이다. 모델이 묘사한 관찰은 프레임 ID와 함께 진단에 남기고 카드 이유에도 선택적 장면 검증임을 표시한다. 기존 카드 유형·DB는 유지한다. 공개 coverage의 `sceneAnalyzed`는 전체 장면 분석 구현을 뜻하므로 이 선택적 보충만으로 true로 바꾸지 않았다.

## 실패 진단

기존 `VERIFICATION_FAILED` 상태 아래 `failureCode`를 추가했다. 요청/HTTP/연결/한도/JSON 파싱/거부/중단, 후보 누락·중복·예상 외 후보, 출력 필드 조합·대상 근거·원문 인용·게시 계약 실패를 구분한다. 누락 응답과 구조 검증 실패를 정상 판단으로 바꾸지 않는다. ID 20의 원래 모델 응답은 보관되지 않았으므로 새로운 코드를 과거 실행에 적용해 정확한 원인을 복원할 수 없다.

## 아직 하지 않은 것

음성 억양·웃음·효과음, 독립적인 장면 후보 탐색, 영상 전체 시청, 포즈·행동 분석, 댓글 수집·사례 검색·모델 학습은 이번 구현 범위가 아니다. 텍스트 탐색이 이미지 후보를 놓치면 여전히 화면 검증은 실행되지 않는다. 이후 장면 전환 표본 기반 탐색이 이 빈틈을 보완할 수 있지만 별도의 비용/미탐 평가가 필요하다.

다음 실험에서는 중국 발언에 화면 필요 후보가 생기는지, 실제 프레임과 발언 연결이 적절한지, 정상 국가·지역 비교에 과탐지가 생기는지를 확인한다. 중국 발언 카드가 무조건 나오는 것을 정답 조건으로 고정하지 않는다. 텍스트 전용/이미지 보충을 같은 STT와 사람 라벨로 비교한다.

Spring과 Python 둘 다 새 코드를 실행하도록 재시작해야 한다. 이번 작업은 실제 서버 재시작·유료 분석·배포를 수행하지 않았다.
