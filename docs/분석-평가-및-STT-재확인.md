#### 10/11 후속: 실행기·출력 계약 구현, 실제 호출 전

`tools/run_boundary_comparison.py`를 추가했다. `setup`은 private 설정 양식 생성, `freeze`는 검증한 패킷/양쪽 프롬프트/모델 설정/공통 참고/단가/한도를 요청 본문·해시로 고정, `run`은 기본 검사만 수행하고 `--execute`에서만 호출한다. frozen 평가 초안은 수정하지 않고 별도 실행 파일을 만든다. 사용자 서버·운영 판단에는 연결하지 않는다.

사용자가 **추정 총비용 $0.50 이하**를 선택했다. `bcd-execution-config-draft.json`에 $0.50/최대 42회로 기록했다. 모델·설정 기본 제안은 기존 gpt-6-luna/none/0.1이지만 모델 접근 가능 여부는 실제 호출 전 확인 대상이다. 양쪽 프롬프트·참고 스냅샷·단가/출처/확인일은 아직 미입력이며 실제 실행 파일은 만들지 않았다. API 키는 실행에서만 환경 변수 또는 명시한 private env 파일로 읽고 출력/설정에 넣지 않는다.

출력 계약은 전체 텍스트 창의 decision/reason/missingInformation/쟁점별 issues(axis/reason/normalInterpretation/evidence)다. 합성 입력의 null 시간과 저장 STT 원문은 보존하며 익명 segment ID를 부여한다. 근거 인용은 해당 행의 실제 연속 문자열이어야 한다. PASS/UNCERTAIN은 쟁점 빈 배열이고 UNCERTAIN에는 누락 정보가 필요하다. **운영의 후보 검증 JSON과 다른 평가용 계약**이다. 운영 후보·장면·복구·대상 지칭 계약을 모두 재생하거나 전체 서비스 정확도를 측정한다고 주장하지 않는다. 기준 프롬프트도 이 평가 계약에 맞게 명시적으로 고정해야 한다.

요청 전 reservation/attempt 파일을 남기고 응답/사용량/시간을 저장한다. 자동 재시도·복구는 없다. 한도 초과는 호출 전 중단, 네트워크 오류·거절·잘린 응답·사용량 미확보·계약/인용 오류는 첫 실패 후 중단한다. 입력/요청/설정/예약액 변조를 검사하며 같은 unit은 양쪽에 동일 입력을 사용한다. 요청별 예약 금액은 누적하고 실패 때 돌려주지 않는다. 출력은 새 private 폴더와 0600 파일이며 기존 실행 덮어쓰기/자동 재개는 없다.

비용은 입력 UTF-8 바이트+여유량과 최대 출력 토큰으로 보수적으로 예약하고, 응답 토큰×설정 단가로 추정한다. **공급자 토크나이저·실제 청구액 보장 장치가 아니다.** 캐시 할인은 적용하지 않고 예약보다 실제 사용량이 크면 즉시 중단한다. 네트워크 오류 등 비용 미확인은 unknownCostAttempts/estimateCompleteForAttemptedCalls=false로 남긴다. actualBilledCostUsd=null이며 실제 계정 청구 한도는 별도다.

형식과 실제 인용이 맞으면 VALID_CONTRACT이지 논란 탐지 정답이 아니다. targetIssueFound/unsupportedInference/duplicateIssue/qualityGateMet는 자동 확정하지 않는다. 다른 쟁점 경고와 B/C/D 목표 발견은 사람 검수로 구분한다. 가짜 응답으로 전체 241개 Python 테스트를 통과했고 실모델 호출은 0회다.

```bash
# 이미 만든 설정은 덮어쓰지 말고 검토해서 채운다.
python tools/run_boundary_comparison.py freeze \
  --packet datasets/controversy/evaluation/v1/bcd-boundary-comparison-draft \
  --config datasets/controversy/evaluation/v1/bcd-execution-config-draft.json \
  --output datasets/controversy/evaluation/v1/bcd-execution-frozen.json

```

현재 설정으로 freeze하면 미입력 항목 때문에 거절되는 것이 정상이다. 실제 호출은 이후 프롬프트·참고·단가를 검토하고 새 결과 폴더와 `--execute`를 명시한 뒤 진행한다. [공식 Structured Outputs 문서](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat)를 OpenAI Docs 스킬로 확인해 JSON Schema, 거절·불완전 응답 처리를 적용했다. 형식 보장을 의미 판단 보장으로 해석하지 않는다.

### 변경 전에 고정할 채택 기준

다음은 향후 비교의 사전 기준이며 이번에 개선을 입증했다는 뜻이 아니다.

1. 사람 승인 정답과 충분한 원문을 확보한다. 기존 `review_dataset.py`의 독립 검수자 2명·불일치 조정·출처/개인정보/이용 범위 계약을 유지한다. 초안의 `proposedDecision`을 정답으로 복사하지 않는다. B/C도 알려진 사건이라는 이유로 무조건 경고 정답이 되지 않는다.
2. 한 번에 한 가설만 변경한다. 기준/수정은 동일 입력·모델·설정·참고 스냅샷·호출 한도를 사용하고 각 조합을 3회 비교한다. 평가 가족의 사례를 사전에서 제외한 조건과 같은 사건 사례를 포함한 개발 조건을 구분한다. 참고 선택까지 바꾼 시험을 프롬프트 단독 효과라고 부르지 않는다.
3. 논란 누락은 기준보다 감소해야 한다. 정상 대조 경고와 애매한 입력의 근거 없는 확정은 증가하면 안 된다. 원문 밖 대상·의도·행위 해석, 근거 인용 실패, 쟁점 중복도 증가하면 안 된다. 평균 카드 수 증가를 개선으로 삼지 않는다.
4. 반복 결과는 케이스별 3회 결정과 유효 근거를 기록한다. 새롭게 찾은 목표는 유효 경고 2/3 이상을 최소 조건으로 두되, 목표별 결과를 숨기지 않는다. 안정성이 악화되면 채택을 보류한다. 2/3도 높은 신뢰도나 범용 정확도의 증명은 아니다.
5. 시간·입출력 토큰·실제 비용을 같은 범위로 기록한다. 미확보 값은 null이다. 시간/비용 허용 증가 상한을 실행 전에 정하고, 정하지 않았으면 유료 시험을 시작하지 않는다. 전 항목 30개 × 2안 × 3회는 최대 180개 평가 작업이지만, 복구·탐색·이미지 요청이 붙으면 API 호출 수는 더 많으므로 별도 총호출/금액 상한이 필요하다.
6. 독립적인 새 사건 시험이 없으면 일반화 개선은 미확인이다. 먼저 개발 결과를 보고 기준을 수정했다면 해당 확인 세트는 새 검증용으로 다시 사용하지 않는다.

## 연결 후보 대조 개정 30

### 후속 안정화 — 개정 31

후보 인용 검색이 모든 사례 슬롯을 차지하는 구조를 바꿨다. 후보 인용으로 찾은 사례 하나와 가까운 문맥으로 찾은 사례 하나를 우선 교차하고 나머지도 교차 순서로 채운다. 가까운 문맥은 허용 검증 창 안에서 각 인용 앞뒤 15초의 원문이다. 부족한 검색 결과는 전체 허용 창에서 보충한다. 판정 기준·전체 검증 원문을 축소한 것은 아니다. 후보 검증은 같은 사건의 관련 흐름을 가족 다양성 때문에 뒤로 밀지 않는다. 전체 탐색은 기존 사건 다양성 우선이다. 최대 사례 수·문자 상한·제외 사건/채널은 유지하며 뜻을 이해하는 검색으로 표현하지 않는다.

현재 후보의 검증된 탐색 인용은 중복을 제거하고 시간/ID/인용 순으로 정렬해 검색한다. 대상 지칭 관계 오류 TARGET_MENTION_RELATION은 기존 대상 근거 복구 지시로 재검증하지만, 자동 EXPLICIT/CONTEXTUAL 변경이나 경고 복원은 하지 않는다. 영상당 합산 2회 한도를 유지하므로 46처럼 예산이 이미 소진되면 여전히 복구할 수 없다.

ContextReferenceAudit에 선택적 candidateQueries를 추가했다. 60초/48구간 이하 창, 원문의 유일한 시작 시각 1~8개만 받는다. 허용 창 밖·중복/존재하지 않는 시간·과대 창은 거절하며 출력은 사례 선택 메타데이터뿐이다. 원문·키·댓글은 출력하지 않고 모델을 호출하지 않는다. private routing-31-input.json의 고정 40.5초 단일 인용/20.5~80.5초 창에서는 B/C가 선택됐다. 23.5·36.5·39·40.5초 고정 연결/1.5~61.5초 창은 C/B다. 46 원래 탐색 모델의 proposedEvidence는 저장돼 있지 않아 같은 후보의 전후 재현이라고 주장하지 않는다. 고정 검색에서 B가 전달됨을 확인한 것이지 B 탐지가 개선됐다는 결과는 아니다.

검증: Java 520개·도구 Python 103개, 실패/생략 0개. 원문 변경·새 유료 모델 호출·전체 영상 재분석·운영 배포는 하지 않았다. 사용자가 띄운 로컬 서버는 종료하지 않았으므로 다음 분석 전에 Spring을 재시작해야 한다.

두 줄 이상을 근거로 제안한 TARGET_TREATMENT 후보는 PASS에도 비판 가설과 원문의 근거 부족 설명, 제안된 다른 줄의 실제 CONTEXT 인용이 필요하다. 정상 선택/시설 정보와 타인의 생활을 낮추는 실제 비교·평가를 대조하는 검증 기준을 추가했다. 직접 욕설·주민 전체 일반화는 필수 조건이 아니며, 주변 맥락이나 후보 이유만으로 악의·열등함을 만들어서는 안 된다.

누락은 LINKED_PASS_CONTRAST_REQUIRED 또는 LINKED_PASS_CONTEXT_REQUIRED다. 텍스트·이미지 검증은 같은 중립 복구 지시를 사용하며 기존 영상당 합산 최대 2회 한도는 유지한다. 복구도 실패하면 검증 실패/미확인/PARTIAL로 남긴다. 계약 검사는 대조 설명의 존재와 실제 인용을 검증할 뿐 설명의 의미적 타당성을 보증하지 않는다. 단일 줄 PASS, 표현 축, STT 원문, 모델·샘플링·사전은 유지한다.

## 실행 기록 도구

저장소 루트에서 실행한다. `capture`는 127.0.0.1:8080의 완료 리포트·상태·임시 진단·전사를 읽기만 한다. 업로드·AI·검색을 호출하지 않는다. private JSON에는 원문과 진단이 포함되므로 Git 제외 영역에 저장한다. 진단은 1시간/20영상 메모리 제한이며 서버 재시작 전에 보관해야 한다. 리포트 자체는 DB에 유지된다.

```bash
python tools/evaluate_analysis_run.py capture 44 \
  --output datasets/controversy/experiments/run-44.json

python tools/evaluate_analysis_run.py evaluate \
  datasets/controversy/benchmarks/pisik-v1.json \
  datasets/controversy/experiments/run-44.json \
  --output datasets/controversy/experiments/evaluation-44.json

python tools/evaluate_analysis_run.py template \
  datasets/controversy/benchmarks/pisik-v1.json \
  datasets/controversy/experiments/run-44.json \
  --output datasets/controversy/experiments/assessment-44.json
```

양식의 MATCH, 원문/대상/정상 대조 확인, 전체 카드 검수 필드는 자동 채우지 않는다. 양식 상태 그대로 `--assessment`로 제출하면 완료된 품질 검수가 아니므로 거부된다. 검수 후 평가에 `--assessment <검수 파일>`을 추가한다. 여러 평가 파일은 `compare <파일1> <파일2> ...`로 비교한다. 모델/프롬프트 개정이 다르거나 전사 해시가 없으면 엄밀한 동일 조건 반복 시험이 아니다.

## STT 확인 구간 선정 — 로컬 진단 전용

`GET /api/v1/videos/{id}/analysis/stt-review-plan`을 추가했다. 기존 review-diagnostics-enabled 조건에 묶여 기본 운영 설정에서는 노출하지 않는다. 로그인/영상 소유권이 없는 공개 서버에서 이 설정을 켜면 안 된다. Spring 재시작 후 사용할 수 있다.

선정 개정은 `2026-10-10-stt-review-plan-1`이다. 발언 진단의 UNCERTAIN에서 전사/오인식/음성/발음/알아듣기 관련 누락 정보가 명시된 구간만 고려한다. 대상 신원·외부 사건·문맥 부족만으로 음성을 다시 처리하지 않는다. PASS된 단순 오타나 현재 진단에 표시되지 않은 오류를 임의로 찾거나 교정하지 않는다.

- 원문 ID/시작·끝과 DB 전사를 대조하고 rawText를 그대로 반환한다. 원문 시간 불일치면 SOURCE_SNAPSHOT_MISMATCH이며 임의 매핑하지 않는다.
- 실제 유효 후보의 anchor/제공 문맥에 포함된 구간만 원음 확인 계획에 넣는다. 문맥 포함은 판단을 막는 오류라는 확정이 아니므로 사람 확인이 필요하다.
- 후보 연결이 없으면 DEFERRED_NO_CANDIDATE_LINK로 남긴다. 현재는 시간순 최대 3구간/합산 20초, 각 원문 앞뒤 1초 계획만 만든다. 겹치는 클립도 각각 계산하는 보수적 합산이다.
- 계획 한도는 실제 API 과금 상한이 아니다. executionEnabled=false/additionalCalls=0이며 음성 추출·인식·원문 수정·DB 쓰기는 하지 않는다.
- 진단이 없거나 만료되면 DIAGNOSTICS_UNAVAILABLE이지 오류 없음/PASS가 아니다. 진단에서 놓친 전사 오류와 한영 표현 차이는 자동으로 발견하지 못한다.

다음 재전사 단계에서는 후보 우선순위, 겹치는 원음 범위 합산, 모델·실제 비용/시간 상한, 수정 전사 별도 테이블과 원음 근거·시간 정렬을 설계한다. GPT의 문맥 추측을 원문 교정으로 저장하지 않는다.

## 이번 관찰과 다음 순서

ID 44는 43과 동일 STT 원문/시간인데 C/D만 발행했다. B는 후보 탐색 누락·전사 차이·병합 제거가 아니라 검증 PASS로 사라졌다. 이번 실행에는 병합할 B finding 자체가 없어서 병합 2의 실영상 효과는 검증하지 못했다. 판정 보류 0건이므로 이 오류 선정기는 B 누락을 음성 오류로 자동 분류하지 않는다.
