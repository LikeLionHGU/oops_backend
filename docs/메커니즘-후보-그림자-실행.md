# 메커니즘 후보 생성 · 무료 그림자 실행

2026-10-20 · minwook · 운영 미연결. 기존 검색·AI 탐색·검증·병합·리포트 결과는 변경하지 않는다.

## 목적과 이전 실험에서 가져온 경계

기존 StructuredContextSearch는 관련 참고를 고르는 검색 전용이며 두 프로필만 지원한다. 이번 MechanismCandidateShadow는 별도 순수 함수로, 검토할 원문 신호를 확보하는 첫 단계다. AI를 대체하는 판정기가 아니다.

이전 자동분류 시험에서는 같은 발견 입력·참고에서도 후보 결과가 달랐다. 구조화 검색은 관련 사례 회수를 개선했지만 정상 경계 비교에서 최종 판단 우위를 증명하지 못했다. 따라서 이번에는 사전·프롬프트를 바꾸지 않고 후보 생성만 관찰한다. 과거 순위·슬롯 비교는 후보 생성 효과의 근거로 사용하지 않는다.

## 구현 계약

- 개정: `2026-10-20-surface-candidate-shadow-1`.
- 세 규칙: 신체 부위+훼손 동작 표면 표현, 가치 부정+선택 조건 표현, 집단+범위+평가 표현.
- 출력: mechanismId, RULE_SHADOW 출처, 규칙 개정, anchorId, 적중 구간 ID·문자 위치·원문 부분 문자열, 연결 구간 ID.
- 문자 위치는 Java UTF-16 offset이며 시간 정렬이나 단어 단위 타임스탬프가 아니다. 원문은 정규화·교정하지 않는다.
- SPEECH만 사용하며 화면 글자·사전 설명·AI 가설은 입력 신호에 포함하지 않는다.
- 최대 8개 연속 음성 구간·전체 20초·인접 구간 공백 3초 이하. 이 값은 초기 감사 예산이며 대화 경계·같은 화자를 보증하지 않는다. 신호 등장 순서의 의미 관계도 판정하지 않는다.
- 같은 메커니즘·anchor의 중복은 가장 짧은 구간 수의 연결 하나로 정리한다. 다른 대안 근거 전체를 보존하는 기능은 아직 없다.
- 입력 최대 10,000음성 구간·구간당 24,000 UTF-16 문자, 출력 최대 1,000후보. 초과 후보 수와 20초 초과 구간 수를 따로 보고한다. 긴 단일 구간은 현재 검사하지 않으며 PASS로 해석하지 않는다.
- 인용·정상 설명도 후보로 남을 수 있다. 후보는 경고가 아니며 결과에 PASS/REVIEW·위험 점수·비판 가설을 생성하지 않는다.

규칙은 초기 코드 정의다. 사건명·브랜드·피식대학 ID는 조건에 넣지 않았다. 지역 비하·은근한 반어·모든 방언·동의어를 포괄하지 않으며, 메뉴라는 대상 자체의 의미 확인이나 신체 비유 여부도 확정하지 않는다. 문자열 신호를 실제 의미 관계로 승격하면 안 된다.

## 오프라인 실행

Spring 디렉터리에서 저장된 transcript API 응답(`success:true`, `data:[{startMs,endMs,text}]`)을 읽는다. 출력은 stdout이며 원본 파일·DB를 수정하지 않는다. 원문 일부가 포함되므로 출력도 비공개 연구 자료로 취급한다.

```sh
./gradlew --offline mechanismShadowAudit \
  -PmechanismShadowInput=../datasets/controversy/experiments/v1-current-pipeline-restart-20261018/transcript.json
```

입력 파일 SHA256을 출력한다. stt-index ID는 해당 스냅샷 배열 순번이며 DB 식별자나 다른 전사의 같은 ID와 동일성을 보장하지 않는다. 네트워크·Spring·모델·DB 호출은 없다.

저장71번 전사 재생에서는 메뉴34→35 연결과 신체 표현37의 2후보를 생성했다. 메뉴는 `의미가 없`과 `주는대로`, 신체는 `살을 뜯`의 실제 위치를 보존했다. 이는 78번의 새 요청 재현이나 최종 카드 탐지 성공이 아니다. 단일 기존 전사와 합성 경계 테스트만으로 범용 후보 회수율을 주장하지 않는다.

무료 전체 Java 테스트 1,046개 통과·실패/오류0. 신규8개는 반복 결과 동일성, 원문 offset, 일반 리뷰, 긴 공백, 정상 인용도 후보로 유지, 음식 복합어/화면 글자 제외, 독립 메커니즘, 짧은 연결 선택·중복, 긴 단일 구간 제외를 확인했다. 제공자 호출0이며 운영 서버 재시작·사전 변경·DB 변경은 없다.

## 다음 단계

1. 실제 정상 영상의 저장 전사에도 같은 무료 감사를 적용해 불필요한 후보와 잘못 연결한 신호를 검수한다.
2. 이 도구 출력과 기존 AI 후보를 원문 스냅샷이 같은 경우에만 비교한다. 현재 자동 비교·운영 진단 연결은 미구현이다.
3. 검수 후 공통 후보 계약에 출처를 분리하고 RULE/AI 합집합을 기존 검증기로 전달한다. 규칙 가설을 임의로 만들지 않는다.
4. 운영 연결 시 시간 구간별 예산·중복·원문 창·미평가 상태를 설계한다. 지금의 1,000개 감사 상한을 운영 검증 예산으로 사용하지 않는다.
5. 그 이후에만 별도 승인된 실제 모델 비교로 최종 오탐·미탐·비용을 측정한다. 사전 검색이 없다는 이유로 규칙 후보를 지우거나, 검색 성공만으로 후보를 강제하지 않는다.
