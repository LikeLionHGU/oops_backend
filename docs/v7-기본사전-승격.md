## 현재 상태

로컬 기본 경로 `datasets/controversy/guidelines/runtime.json`을 v7로 승격했다.
32사건에서 나온 참고39개·공통 판단6유형·작성된 관계 프로필4개이며, 기존 시험 v7과 바이트까지 동일하다.
이는 실행 기본값의 채택이지 `humanValidated`·개별 사건 검수·학습 이용 허가를 참으로 올린 것이 아니다.
독립 영상에 대한 탐지 개선을 입증했다는 뜻도 아니다.

서버 재시작/배포/AWS 파일 전송은 하지 않았다. 실행 중인 Spring은 시작 시 읽은 사전을 사용한다.
다음 시작 시 기본 경로를 읽으면 v7이며, `REVIEW_GUIDELINES_LOCATION` 등 명시적 설정이 있으면 그것이 우선한다.
데이터는 Git 제외이므로 **코드만 pull해서는 AWS 사전이 바뀌지 않는다.** 서버의 비공개 입력/사전도 별도로 반영해야 한다.
v7이 이전의 발견 배치 참고 고정 대신 후보별 원문으로 참고를 다시 선택하는 경로를 활성화한다는 점도 변경 범위에 포함한다.

## 추가 기능 ON 결과의 정확한 의미

후속 [동일 v7·v1/v2 비교8회](v7-v1-v2-자동분류-비교.md)에서는 지역 흐름이 OFF0/2·ON2/2, D는 양쪽2/2,

기본OFF는 유지한다. 아래 표의 최초 판정 비교/합성 회수 비교와 이번 관측을 구분한다.

즉 **자동 분류는 참고 회수에 이득을 보였으나 최종 논란 탐지가 더 좋아졌다는 결론은 아직 아니다.**

사용자는 v7 승격을 요청하고 ON 효과를 질문했다. 이를 모든 추가 기능의 기본ON 요청으로 확대하지 않았다.

## 재빌드가 v4로 되돌아가지 않게 한 방식

정식 입력 선택 정책은 비공개 `definitions/runtime-selection.json`이다.

```json
{
  "schemaVersion": "incident-runtime-selection-1",
  "targetSchema": "review-guidelines-7"
}
```

빌드 순서는 사건 원장/공통 정의 → v4 기반을 메모리에서 생성 → 맥락 단위·원문 출처·검색 키·관계 프로필 결합 → v7 검증/저장이다.
과거 `experiments/*/runtime.json`이나 이미 생성된 기본 사전을 빌드 입력으로 복사하지 않는다.
시험 프리뷰 도구도 v4 기반을 원장에서 다시 만들므로 기본 사전이 v7이 된 뒤에도 사용할 수 있다.

```bash
cd /Users/im_inwook/dev/oops_backend
/opt/anaconda3/bin/python tools/build_incident_dataset.py --write
/opt/anaconda3/bin/python tools/build_incident_dataset.py --verify
```

정책/단위/프로필/검색 키/원문 출처를 manifest의 입력 해시에 포함한다.
원문 SHA 불일치, 필수 입력 누락, 불명확한 정책은 저장 전 실패하며 기존 사전을 그대로 둔다.
새 사건은 별도 맥락 단위가 없어도 기존 참고 형태로 보존된다. 임의 프로필·검색 키·정답 라벨을 생성하지 않는다.
정책 파일이 없는 옛 데이터셋은 v4 빌드를 지원하지만, 이미 v7인 사전을 기본 빌드가 조용히 v4로 내리는 것은 차단한다.
