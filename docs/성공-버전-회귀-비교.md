### 실제 적용한 변경은 복구 지침뿐

실행 개정 `2026-10-11-target-role-repair-32`는 **기본 검증 프롬프트를 개정 31 그대로 유지**하고 TARGET_REPAIR_PROMPT만 명확히 했다.

1. 대상 평가 경고에는 실제 TARGET 역할 인용이 필요하다. CONTEXT 인용이나 targetMention 필드만으로 대신하지 않는다.
2. 먼저 TARGET.quote에서 targetMention을 그대로 복사하고 해석 대상 target을 작성한다. 같은 줄을 PRIMARY와 TARGET으로 각각 인용할 수 있다.
3. EXPLICIT은 두 값이 같을 때만 사용하며, 다르면 CONTEXTUAL·다른 segmentId의 CONTEXT·연결 설명을 요구한다.
4. 기존대로 새 판단은 PASS/UNCERTAIN/REVIEW_REQUIRED 모두 가능하다. 경고 복구를 강제하지 않는다.

텍스트·선택적 이미지의 기존 대상 오류 복구에서 공통으로 사용한다. 후보당 1회/영상당 합산 최대 2회, 원문/ID 검증, 복구 가능 코드, 사례 검색, 병합, API/DB, STT/OCR, 모델·샘플링은 바꾸지 않았다. **새 복구 지침 자체의 실모델 효과는 아직 유료 시험하지 않았다.** 위 20회 비교는 보류한 통합 수정안의 실험이며, 복구 개정 32의 탐지 개선을 입증한 결과가 아니다.

추가 회귀 테스트는 지칭어가 CONTEXT로만 반환되면 여전히 거절되는지, 모델이 유효 TARGET 역할을 다시 반환할 때만 finding이 나오는지, 새 안내가 특정 사건을 강제하지 않는지 확인한다. Java 전체 522개·도구 Python 119개 통과(실패/생략 없음), 저장 응답 Java 감사 6개 성공이다. 사용자 서버를 재시작하거나 AWS에 배포하지 않았다.


대상 작성 안내는 EXPLICIT/CONTEXTUAL 구분을 유지하면서 순서와 자기 점검을 짧게 고정하는 방향이다.

```text

target과 targetMention이 동일하면 EXPLICIT을 사용할 수 있다.
서로 다르면 CONTEXTUAL의 별도 CONTEXT 인용과 연결 설명이 필요하다.
```
