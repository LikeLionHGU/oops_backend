## 결론

이번 고정 40.5초 B 후보는 이전/현재 모두 PASS 3/3이었다. 개정 28로 되돌리는 것만으로 B 탐지가 복구된다는 근거는 없다. C는 이전 REVIEW_REQUIRED 3/3, 현재 REVIEW_REQUIRED 2/3·PASS 1/3이었다. 현재의 판단 프롬프트 차이가 C 판정에 영향을 줄 가능성을 보여 주지만, 3회 표본으로 특정 문구의 인과효과나 안정성을 확정하지 않는다. 운영 코드·모델·사전·검증 기준은 변경하지 않았다.

## 이번 비교 방법

tools/compare_review_prompts.py는 기본 dry-run이며 --execute에서만 유료 호출한다. 개정 28의 검증 프롬프트는 git 870dd72에서, 현재 프롬프트는 실행 개정 31 소스에서 추출한다. 공통 POLICY·범용 참고 계약·사례 입력을 동일하게 붙이고, 각 사례의 사용자 입력 해시를 두 버전에서 같게 유지한다. promptRevision 메타데이터도 두 버전 모두 개정 28로 고정해 버전 이름을 추가 변수로 만들지 않았다.

- 모델: 기존 gpt-6-luna, reasoning_effort=none, temperature=0.1, json_object.
- 비교 도구의 max_completion_tokens=7000. 실제 업로드 경로 전체 설정의 재현이라고 주장하지 않는다.
- ID 47 저장 원문을 사용한다. B는 40.5초 anchor와 35/36.5/39초 인용, 1.5~61.5초 창이다.
- C는 70.5초 anchor와 69.5/72초 인용, 30.5~90.5초 창이다.
- 가설은 새로 고정한 중립적 검토 질문이다. 당시 탐색 모델의 원래 proposedEvidence/hypothesis 복원이 아니다.
- 참고는 작업 사전 v4의 공통 패턴과 B/C 사례를 두 버전 모두 동일하게 제공한다. 현재 선택 알고리즘을 평가한 실험은 아니다.
- B/C는 버전별 3회, 합성 정상 대체 선택/정상 메뉴 리뷰는 버전별 1회다. 반복마다 호출 순서를 교대했다.
- 최대 16호출, 자동 재시도 없음. STT/OCR/검색/장면/탐색/복구/리포트 발행은 하지 않았다.
- 알려진 사건을 포함한 개발 보정이며 정답 승인·범용 정확도·정상 리뷰 과탐지율 평가가 아니다. 정상 리뷰 대조에는 명시적인 비공격 설명이 있어 어려운 정상 경계를 충분히 시험하지 못했다.

16호출 모두 API 응답 성공, 입력 96,874토큰·출력 6,521토큰이다. 실제 청구 금액을 확인하지 않아 비용 금액은 확정하지 않는다. 각 호출의 제공 모델 이름·사용량·요청 해시와 입력/시스템 해시는 Git 제외 private JSON에 보관했다.

ReviewGuidelineReplay로 16개 응답을 현재 production evidence validator에 통과시켰다. 고정 후보를 탐색 응답 모양으로 변환한 오프라인 감사이며 진짜 탐색을 재실행한 것은 아니다. 이전 버전의 Java 검증기를 실행한 결과도 아니다. 이번에는 모든 이전 PASS가 현재 추가 계약까지 충족해 현재 검증기에서 거절되지 않았다.

이번 실험은 OpenAI Docs 스킬과 공식 [평가 안내](https://developers.openai.com/api/docs/guides/evaluation-best-practices)를 참고해 동일 입력·반복·정상 대조를 고정했다. 반복 결과와 계약 검증을 분리했으며 전체 파이프라인의 정확도로 확대 해석하지 않는다.

## 다시 실행하기

기본 명령은 계획 저장만 하며 호출하지 않는다. output은 Git 제외 private 디렉터리의 새 파일명을 사용한다.

```bash
python tools/compare_review_prompts.py \
  datasets/controversy/experiments/run-47.json \
  datasets/controversy/guidelines/runtime.json \
  datasets/controversy/experiments/prompt-comparison-plan.json
```

유료 비교는 --execute를 명시한다. 기본 --repeats 3이고 1~3만 허용하며 총 8~16호출이다. 루트 .env의 OPENAI_API_KEY를 문자 그대로 읽고 파일을 실행하거나 키를 출력하지 않는다. 입력/응답은 같은 사건에 종속된 private 실험 자료로 남기며 범용 사전·학습 데이터 승인 상태를 변경하지 않는다.
