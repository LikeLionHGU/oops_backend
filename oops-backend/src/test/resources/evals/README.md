# 문맥 비교 개발 사례

`contextual-comparison.json`은 **합성 개발 사례 14개**다. 음식·교육·주거·직업의 위험/정상 대조 쌍과 개인 경험·상품 비교·추억·비판적 인용·전사 오류·대상 누락을 담는다. 실제 고객 영상, 확정 정답, 독립 평가셋이 아니다. 프롬프트 설계자가 만든 잠정 제품 기준이므로 검수자 합의가 필요하다.

`decision`은 입력 전체를 읽은 묶음의 기대 결정이다. `REVIEW_REQUIRED`는 삭제·혐오·위법 판정이 아니라 원문으로 설명할 수 있는 재검토 후보를 뜻한다. `category/target/targetType`은 기대 유형/대상, `reason/alternative`는 주석 근거다. `UNCERTAIN`의 `missing`은 필요한 추가 정보다. 실제 평가에서는 모델에 `lines`만 보내고 라벨/해설을 제공하지 않는다.

`ContextualComparisonReviewTest`는 자료에서 만든 **모의 응답**으로 실제 분석기/검증 경로의 묶음 후보·구간 PASS 분리, 원문 대상 인용·보류 처리를 확인한다. 기대 라벨대로 응답을 만들었으므로 테스트 통과를 모델 정확도·재현율·오탐률로 사용하지 않는다. 실제 모델 호출 실행기는 아직 없다. 테스트는 추가 외부 API 호출 없이 실행된다.

다음 실제 평가 절차:

1. 원본을 보는 검수자 2명이 결정·대상·유형·주요 인용을 주석하고 불일치를 조정한다. 실제 영상의 사용 권한/개인정보도 확인한다.
2. 프롬프트에 노출되지 않은 영상/채널/사건 단위 독립 평가셋을 확보한다. 동일 영상 문장을 나누는 것으로 누출을 막을 수 없다. 이 합성 자료도 개발에 사용했으므로 holdout으로 재명명하지 않는다.
3. 동일 STT/OCR 입력으로 변경 전/후를 비교하고 여러 실행의 변동성을 기록한다. 모델 설정, 코드/프롬프트 버전, 입력 해시, 호출/토큰/지연을 남긴다. 유료 호출은 별도 승인/예산 아래 실행한다.
4. 위험 사례 누락, 정상 사례 과탐지, 보류 비율, 대상·유형·인용 정확성, 계약 탈락을 별도로 집계한다. 보류/탈락은 PASS가 아니며 성공한 응답만 분모로 삼지 않는다.
5. 음식 이외 소재·장르, 다른 화자/언어, 인용·풍자·억양 의존 사례를 확장한다. STT에 없는 의도/장면은 확인 필요로 남긴다. 이 자료만으로 모든 영상 지원을 검증했다고 말하지 않는다.

[OpenAI 공식 평가 지침](https://developers.openai.com/api/docs/guides/evaluation-best-practices)을 참고해 명시적 기준·대조 사례·개발/평가 분리를 유지한다. OpenAI Evals 도입이나 외부 자료 업로드는 하지 않았다.
