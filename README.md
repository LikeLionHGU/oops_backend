# OoPs?! — 공개 전 영상 검수 도우미

영상의 발언과 화면 문구에서 사람이 다시 확인할 지점을 찾아, 원문·앞뒤 맥락·시간과 함께 보여주는 서비스다. 특정 사건을 맞히는 것보다 여러 소재의 영상에서 정상적인 리뷰와 검토할 표현을 구별하는 것이 목표다.

> 2026-10-16 · `minwook` 코드 기준. STT 기본은 Groq `whisper-large-v3`, 텍스트 판단은 `gpt-6-luna`다. AWS에 실제 배포된 버전·설정은 별도로 확인해야 한다.

## 서버 구성

| 구성 | 담당 |
|---|---|
| Spring Boot 4 / Java 17 · 8080 | 업로드, 작업 상태, 분석 순서, OpenAI 판단 요청, 근거 검증, DB·리포트 |
| Python FastAPI · 8000 | 영상 준비, Groq STT, OCR, 선택 구간 프레임 추출 |
| Groq Whisper Large v3 | 음성을 구간 시작·끝 시간이 있는 대본으로 전사 |
| OpenAI GPT-6 Luna | 발언·화면 문구의 후보 탐색과 검증 |
| PaddleOCR | 로컬 프레임의 글자와 영역 추출 |

`oops-backend/`와 `oops-analysis/`는 별도 프로세스다. 같은 머신에서 실행할 때 Spring의 `./uploads`와 Python의 `../oops-backend/uploads`가 같은 실제 저장소를 가리켜야 한다. 로컬 DB는 H2 파일 모드이고 재시작 후에도 기록이 남는다.

## 현재 분석 흐름

10/20 표시 개선: 검증된 상호 인용 신체 비유 카드에서 구체적인 비유 원문이 유일하게 식별되면 이를 대표 문구·시각으로 사용한다. 애매하면 기존 대표를 유지하며 탐지·점수·전체 근거는 바꾸지 않는다. 무료 테스트 1,038개 통과. [범위와 한계](docs/AI-분석-로직.md#2026-10-20-병합-카드의-대표-원문-개선).

2026-10-19: 같은 두 줄을 대표/문맥만 바꿔 중복 발행한 신체 비유는 [보수적 근거 병합](docs/AI-분석-로직.md#2026-10-19-신체-비유의-상호-인용-중복-병합)으로1카드/1흐름 처리한다. 탐지·사전은 그대로다. 무료 Java1,033개 통과와 저장71/72 카드 근거 재생을 확인했으며 재시작 이후 새 분석에만 적용된다. 기존 DB 결과는 변경하지 않았다.

현재 개발은 [고정 평가셋 기반 회귀](docs/평가셋-정리-및-R01-집중검수.md#2026-10-18-현재-작업-방식--미세-실험-중단통합-회귀로-전환)로 전환했다. 승인12조건을 단일 등록부로 관리하고 운영 소스 기준선과 과거 시험 성적을 분리한다. 수정 후보는 한 번에 하나만 비교하며 추가 미세 시험은 보류했다. 아직 실제 영상 가족이1개라 범용 검증 완료는 아니다. 아래 개별 시험은 과거 결과다.

최신 합성 대조 기준선은 [4조건 ×3회](docs/표현-탐지-및-선택-필터-설계.md#완료-합성4조건-기준선12회-결과)에서 승인 판단 일치12/12·계약12/12다. 이유의 화자 추정·원문 위치 등은 별도 점검 메모로 남겼다. test 전용 계약의 작은 대조 시험이며 R01·운영 성능 개선을 뜻하지 않는다. 사용량 설정 단가 추정 $0.00166732/새 승인 상한 $0.10, 실제 청구 미확인. 운영 설정은 그대로다.

평가는 독해·판단 기준 일치·근거 타당성·형식을 분리한다. R01 고정 독해 조건은 뜻풀이 선언3/3을 보존했다. 표현 자체의 경고는 기존 PASS 기준과 달라도 독해 오류로 단정하지 않고 근거 재검수로 남긴다. [분리 평가 기준](docs/R01-원문관계-독립진단-계획.md#평가-축-분리--독해-성공과-판단-기준-불일치는-다르다). 운영 변경·추가 유료 호출은 없다.

최신 [원문 독해 우선 판단 계약35회 시험](docs/R01-원문관계-독립진단-계획.md#새-판단-계약35회-결과)을 완료했다. R01 PASS는 원문만/고정 독해 제공 모두2/3으로 안정화되지 않았다. 오염 독해4/4는 원문 근거로 이의를 제기해 재확인으로 보냈다. 새 계약은 test 전용이며 운영에는 적용하지 않았다. 사용량 설정 단가 추정 $0.00587869, 승인 상한 $0.50 이내이며 실제 청구는 미확인이다.

최신 [행위 전제 감사37회 결과](docs/R01-원문관계-독립진단-계획.md#독립-전제-감사37회-결과--핵심-오독-미해결운영-연결-보류)는 형식37/37 통과지만 실제 R01의 뜻풀이 오독을 해결하지 못했다. 단순 방향 반전·없는 지속 강요는 검출했으나 정상 설명의 재확인도 있어 운영 연결은 보류한다. 자동 PASS나 카드 변경은 하지 않았다.

2026-10-18 개정44는 검증에서 후보 쟁점을 보존하도록 지침을 보강했다. 뜻풀이를 실제 질문으로, 자기 제안을 상대 요구로 바꾸거나 주변의 별도 쟁점으로 현재 후보를 경고하지 않게 한다. 원문 범위·서버 검증기는 유지하며 실제 모델 효과는 미검증이다. [수정 범위](docs/R01-원문관계-독립진단-계획.md#후보-쟁점-보존-지침-반영--실제-모델-효과-미검증).

영상 등록 → 길이 확인 → STT·OCR → 표현 등장 목록 저장 → 맥락 사전 참고와 후보 탐색 → 후보의 원문·대상·문맥 검증 → 관련 근거 기반 병합 → 리포트와 사람의 검수 결정.

- STT는 기존 OpenAI Whisper와 같은 음성 추출·10분 분할·구간 타임스탬프 계약을 사용한다. 단어별 시간은 현재 요청하지 않는다.
- OCR에는 간판·메뉴판도 잡힐 수 있다. 편집 자막·배경 글자·불확실 영역을 구분하며 자막이 반드시 있다고 가정하지 않는다.
- 욕설·논쟁 표현의 등장은 별도 트랙이다. 적중만으로 맥락 경고를 확정하지 않는다.
- 가격·날짜 등 사실 대조와 최근 뉴스 검색은 기본 분석에서 제외했다. 기존 검색을 시험하는 서버 프로필은 `external-review`다.
- 일부 후보는 선택 프레임 검증을 사용할 수 있다. 전체 영상의 말투·표정·억양을 이해하는 기능이나 포즈 분석을 완료한 상태는 아니다.
- 경고 0개와 정상 통과는 다르다. 수행 범위·실패·미판정도 함께 확인한다.

## 로컬 실행

먼저 Java 17, Python 환경, `ffmpeg`·`ffprobe`를 준비한다. 아래 명령은 저장소 루트에서 시작한다. 이미 설정 파일이 있으면 예제 파일로 덮어쓰지 않는다.

### Python 분석 서버 — 터미널 1

최초 설치:

```bash
cd oops-analysis
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

처음에만 `.env.example`을 `.env`로 복사한 뒤 입력한다. 키는 저장소나 채팅에 올리지 않는다.

```env
GROQ_API_KEY=발급받은_Groq_키
STT_MODEL=whisper-large-v3
MEDIA_STORAGE_ROOT=../oops-backend/uploads
```

```bash
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

모델·키 설정은 Python 프로세스 재시작 후 반영된다. OpenAI STT로 되돌릴 때는 `STT_MODEL=whisper-1`과 Python용 `OPENAI_API_KEY`를 설정한다. 자동 제공자 fallback은 없다. OCR을 제외한 설치·Windows 안내는 [Python README](oops-analysis/README.md)를 따른다.

### Spring 백엔드 — 터미널 2

`oops-backend` 디렉터리에서 OpenAI 키를 환경변수 또는 `application-secret.yml`에 설정한다. Spring은 Python의 `.env`를 자동으로 읽지 않는다.

macOS zsh 예시:

```zsh
cd oops-backend
read -s "OPENAI_API_KEY?OpenAI API 키 입력: "
export OPENAI_API_KEY
echo
export JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home
bash ./gradlew bootRun --args='--spring.profiles.active=local --server.address=127.0.0.1'
```

Java 경로는 설치 환경에 맞춰 조정한다. 상세 설정은 [Spring README](oops-backend/README.md)를 참고한다. `bootRun`은 서버가 실행되는 동안 끝나지 않는 것이 정상이다.

### 업로드·조회 — 터미널 3

```bash
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8080/health

curl -X POST http://127.0.0.1:8080/api/v1/videos \
  -F "file=@/절대경로/영상.mp4" \
  -F "genre=GENERAL"
```

응답의 `videoId`를 아래 `VIDEO_ID` 자리에 넣는다.

```bash
curl http://127.0.0.1:8080/api/v1/videos/VIDEO_ID/status
curl http://127.0.0.1:8080/api/v1/videos/VIDEO_ID/report
curl http://127.0.0.1:8080/api/v1/videos/VIDEO_ID/transcript
```

새 모델은 기존 완료 리포트를 자동으로 바꾸지 않는다. 완료 영상으로 다시 비교하려면 새로 업로드한다. `analysis/retry`는 실패·취소 상태에서만 사용할 수 있다. 업로드는 전사와 분석 API 호출·비용을 발생시킨다.

## 사전과 데이터

| 파일 | 역할 |
|---|---|
| `datasets/controversy/guidelines/runtime.json` | 현재 기본 v7 맥락 사전. 로컬 39개 참고·6개 공통 기준 |

| `oops-backend/src/main/resources/expression-dictionary.json` | 욕설·논쟁 표현의 별도 등장 목록 |

맥락 사전은 사건별 원장과 공통 정의에서 빌드한다. `runtime.json`을 직접 편집하지 않는다. 현재 예시 선택은 문자 검색 + v7 로컬 개념 조합 보완이며 기본 최대 3개다. [구조화 검색](docs/맥락사전-구조화검색-보완.md)은 별도 API 호출 없이 사적 신체 정보 질문·집단 전체 평가 참고를 회수한다. 의미 검색이나 논란 판정은 아니며 `STRUCTURED_CONTEXT_SEARCH_ENABLED=false`로 이전 검색을 재현한다. LLM 검색 키 분류·원문 관계 추가 기능은 별도로 기본 OFF다.

`datasets/**`는 Git 제외다. **코드를 pull하거나 빌드해도 비공개 사전이 자동 배포되지 않는다.** 실행 서버에 별도로 제공하고 Spring을 재시작해야 한다. [데이터셋 파일 관리](docs/데이터셋-파일-관리.md)와 [v7 승격 기록](docs/v7-기본사전-승격.md)을 따른다.

## 최신 점검과 다음 작업

[Groq 전환 후 점검](docs/Groq-전사-후속-점검.md)에서 원본 2개를 재전사하고 발췌 5쌍·정상 초안 6개를 비교했다. 핵심 전사 오류는 일부 개선됐지만, 관련 사례 회수 0개·후보 쟁점 이동·대상 연결 계약 탈락이 남았다. 정상 초안은 4개 정상 처리, 2개 필수 출력값 누락 실패이며 정식 사전에는 반영하지 않았다.

후속 무료 검색 비교에서는 속옷 질문의 관련 참고가 0→3개로 회수됐고 집단 전체 표현의 참고가 집단 일반화 사례로 바뀌었다. 이후 [정상 경계·최종 판단 32회 비교](docs/구조화검색-OFF-ON-정상경계-비교.md)를 완료했다. 새 정상 초안의 경고는 양쪽 0이지만 필수 출력값 실패가 OFF 1/12·ON 4/12였다. 최종 판단 우위는 미확인이다. 다음은 출력 계약 안정화 → 원문 행위·대상 보존 → 집단 일반화 경계 검수다. 죽음 표현 참고 부족도 남았으며 회수 개선을 안정화 완료로 해석하지 않는다.

설정된 STT 비용 추정은 분당 $0.00185이며 `[ai-cost]` 로그에 텍스트 비용과 함께 계산된다. 실제 청구액과 다를 수 있다. 모델을 바꾸면 가격 설정도 맞춰야 한다.

탐색 출력은 [JSON/strict 비교](docs/탐색-출력계약-JSON-스키마-비교.md) 후 strict JSON Schema 기본 ON이다. 후속 ID 범위 비교 32회도 완료했다. 정상 초안은 양쪽 12/12 완전 무경고, 범위 오류도 양쪽 0건이라 제한 추가의 감소 효과는 입증하지 못했다. 검토·대표 ID는 현재 배치, 근거 ID는 보조 문맥까지 허용한다. 행위·대상 의미 보존과 문맥 제한은 남는다. `STRUCTURED_DISCOVERY_OUTPUT_ENABLED=false`로 이전 JSON 모드를 선택할 수 있다.

[최종 판단 근거 분리](docs/최종-판단-근거-분리.md)는 기본 OFF 선택 기능이다. 후속 계약/판단 가드4안112회 비교에서 승인 기준 일치·계약 통과는 기존10/16·가드만8/16·계약만9/16·둘 다10/16이었다. 무료870개 통과, 안정적인 의미 개선은 미입증으로 `FINAL_REVIEW_BASIS_ENABLED`는 false를 유지한다. 다음은 대상 지칭 계약과 PASS 대조 누락의 무료 재현이다.

2026-10-18 최신 개정43/44 비교30회에서도 R01 PASS는 양쪽0/3이었다. 합성4조건은 양쪽12/12 기준 일치지만 계약 통과는 기존15/15·수정13/15라 개정44의 성능 우위가 없다. 사용량 설정 단가 추정 `$0.00965794`, 실제 청구 미확인이다. 원본 응답과 실패를 보존했고 이번 시험의 추가 코드 변경·배포는 없다. [세부 결과와 후속 계획](docs/R01-원문관계-독립진단-계획.md).
